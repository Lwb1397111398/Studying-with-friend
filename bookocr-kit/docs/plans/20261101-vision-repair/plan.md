# 视觉对照精校方案（2026-11-01 定稿，待执行）

> 老板目标的正式表述：**成品不继承源头缺陷——PDF 文字层哪里坏了，视觉就修到哪里；只继承不修复，和普通 OCR 无异。**
> 本方案就是把这条目标落到 3 本文字层拔取书上的执行计划。

## 一、背景与实测现状

- 2 本 AI 逐页书（逻辑新引、损害赔偿）已达标：每页看过原图，残留 ≈ 0。
- 3 本文字层拔取书（不当得利、债法原理、民法总则）实测残留（2026-11-01 体检，垃圾字符口径 = `proofread.py` 的 `_JUNK_CHARS`）：
  - 不当得利 83 个字符 / 34 页，其中 **p515 一页集中 45 个**（尾页德文文献区）；图示碎片行 ~10 页（p86、129、168、220、224、298、336、365、436、437）。
  - 债法原理 48 个、民法总则 28 个（页清单待检测脚本补全）。
  - 逻辑新引 2、损害赔偿 0（不动）。
- 不当得利已实测锚点页（34 页，检测脚本结果必须包含它们）：
  `23,34,81,86,97,114,119,129,157,159,165,168,171,176,200,202,220,224,233,271,298,299,321,326,334,336,351,358,365,377,390,436,437,515`
- **为什么现有闭环没拦住**：qa→reocr→pack 闭环是存在的，但检测阈值松——垃圾段规则要求 ≥2 段含垃圾符号才标 needs_vision，行内单个残留字（如「捕鱼竺亦属如此」的「竺」=脚注①误读）不在任何规则内 → 5 本书 needs_vision=0 是**假阴性**，修复闭环一次没触发。

## 二、范围

### 做

1. **proofread 增加 `--vision` 模式**（核心交付）：
   - 输入 = 该页渲染图（`jobs/<书>/images/` 已有，缺失时用 prep 机制按 dpi 200 补渲染）+ 该页当前批文本；
   - 交 **caps 含 vision 的 API**，提示词要求：对照原图校对转写文本，修复与原图不符处（形近错字、漏字、脚注序号残留字、删除图示碎片行）；
   - **推断政策（老板 2026-11-01 两轮定稿）**：正文看不清处按上下文推断出正确字，目的是读者读得通、不机械死板。**引用骨架**（条号/判决字号/数字/人名/书名）只按原图辨认，反复读图（多 dpi、区域裁剪放大、独立二次调用）仍认不清→行内〔辨认不清〕+ 台账（最后手段），绝不编造。**整页糊不走占位**：穷尽读图手段后结合上下文重建正文，重建页 rule=inferred 落台账供老板抽检，且必须**双通道交叉核对**——一次带现文本对照修、一次只看图独立转写，两路 diff 的差异逐处裁定后才写回。每处推断落 changes.json 可追溯；
   - 输出沿用现有受控 JSON 协议（find/replace，find 页内唯一，edits≤8、merges≤3、new≤old+4），整行删除 = find 整行、new 置空；
   - 护栏照旧：禁触 `〔页/〔图/〔脚注/〔KIT` 结构行（STRUCTURED_LINE_RE）；审计落 `changes.json`（rule=`vision`）+ `proofread_report.md`；批文件先备份（现有 backup 机制）。
2. **残留页检测脚本**（一次性，可放临时目录不入库）：逐页统计 `_JUNK_CHARS` 计数，≥1 即入修复清单；对 3 本 pull 书跑全，结果与不当得利 34 锚点页取并集。
3. **接通本机视觉 API**（二选一，推荐 ①）：
   - ① 小修 `bookocr.py` 视觉三键 fallback：现硬编码 `C:\Agent\AImanager\ai-apis.json`（旧机器路径，本机不存在），改为 `E:\AI Agent\Agent Manager\ai-apis.json`（本机档案库，选 caps 含 vision 的启用档案）；
   - ② 或在 kit 目录 `apis.json` 手工配三键（base_url/api_key/default_model；该文件已 gitignore）。注意 kit `apis.json` 现只有 sensenova **文本**模型，不能拿来做视觉。
4. **执行顺序**：备份 → 3 本逐本 `proofread <书> --pages <清单> --vision` → 检测复验 = 0 → 重打包 3 本（三件套重生成 + spotcheck 重出）。
5. **规则层收紧（防复发）**：needs_vision 触发条件从「≥2 段含垃圾符号」扩为「页内出现任一 `_JUNK_CHARS` 字符」；selftest 补对应夹具断言（含「行内单残留字也触发」用例）。

### 不做

- 3 本 pull 书整本 AI 逐页重跑（已否决，见下）。
- 盲目全文替换垃圾字符（有人名误伤风险，实测例：「李陈勹美」p271——必须视觉对照逐处裁定）。
- 不动 2 本 AI 逐页书；不动章表（章界标题不受残留影响）；4 本待识别新书的识别不在本方案内（其目录识别正则已修好，见 git `477a2fe`）。
