# 计划案：AI 智能校对层（proofread）

2026-10-27

## 背景与目标

老板反馈：bookocr-kit 产出的书稿仍有大量 OCR 残留错误，例如《不当得利》中：

- `勹无因管理仁覃言＄芦：用）的法律上原因` —— 图示区内部文字被 OCR 当成正文混入（形近字 + 框线乱符）；
- `知已知彼`（应「知己知彼」）、`淮确`（应「准确」）这类形近错字；
- 段尾脚注序号残留 `。心` / `。专` / `。竺`（脚注 ①②③ 的序号字形被 OCR 吞错）；
- 外文连写 ≥14 字母无空格（`Differencesand`、`einheitstheorie` 等）、中文夹进拉丁串（`cond兀tio` 类）；
- `(l)`（应 `(1)`）、`（IO万元）`（应 `（10万元）`）等列表序号/数字混淆；
- 分段问题：段落被硬拆/粘连、碎片行、清单项与正文混排。

老板原话：

> 我认为，在识别过程中对于这种不合理的地方，AI 可以自己判断，甚至可以适当改写，使之变得合理。比如遇到「某观点是女子的」——这个「女子」就可能是识别错误，应当是「好的」；「某某观点是淮确的」通读一遍，发现可能是识别错误，这个「淮」应当是「准」，就应该修改一下。

目标 = 把「读得通」的判断交给 AI 校对层：
- AI 通读上下文，自动纠正不合理错字/残句（保守纠错，不臆造、不改写语义）；
- 对识别不清处推测合理讲得通的替代（仅限明显形近错字/垃圾符号）；
- 大块不可信区域不瞎猜，整页标 `needs_vision` 交回现有 `reocr --exact` 视觉重识别闭环。

## 现状基线（2026-10-27 对 5 本书 output/*.txt 实测）

| 指标 | 不当得利 | 债法原理 | 民法总则 | 损害赔偿 | 逻辑新引 |
| --- | --- | --- | --- | --- | --- |
| 垃圾符号字（勹＄竺叩＼｜） | 99 | 52 | 31 | 0 | 2 |
| 段尾脚注残留（。心/。专…） | 26 | 4 | 11 | 0 | 0 |
| `(l)` | 44 | 7 | 9 | 0 | 0 |
| 连写≥14 字母拉丁串 | 395 | 258 | 250 | 517 | 21 |
| 拉丁串夹 CJK | 29 | 47 | 45 | 11 | 5 |
| 知已 / 淮 | 1 / 0 | 0 / 0 | 1 / 1 | 0 / 0 | 0 / 0 |
| ≤3 字碎片行 | 98 | 56 | 82 | 20 | 37 |

关键事实：
- 逻辑新引/损害赔偿是 aivision 视觉路线，仍有 `cond兀tio`、`。专` 残留 → 识别路线本身也产错，校对层必须**路线无关**（对 pull / aivision / reocr 产物统一处理）；
- 不当得利 p30 的 `勹无因管理仁覃言＄芦…` 是 pull 的 band 检测漏判（图内文字泄漏），最可靠的修复是**整页视觉重识别**，不是文本硬猜 → 校对层负责打标，重识别复用现有 `reocr --needs-vision`；
- 民法总则 p8 `勹三－ 买卖（债权…）` 同理（图内标注漏成正文）。

## 方案总览

新增独立模块 `proofread.py`（命令 `python proofread.py`，另在 `bookocr.py` 挂 `proofread` 子命令转发，保持「一个程序入口」的使用习惯）。两层管线：

### 1. 规则层（零成本、确定性、先跑）

对每页正文段落依序应用：

| 规则 | 触发 | 动作 |
| --- | --- | --- |
| `note_tails` | 段尾/句读后出现 [心专竺卢叁叩令乃弓井] 且后接段尾/新句 | 删掉该 OCR 序号残留字 |
| `l_paren` | `（l）`/`(l)` 且段内存在其他列举记号（`(2)` 等） | → `（1）`/`(1)` |
| `latin_upper` | `（IO` 这类 I+数字混入 | → `（10` |
| `zhiji` | 成语白名单「知已知彼」 | → 「知己知彼」 |
| `huai_que` | `淮确｜淮的｜淮据｜淮此｜淮绳` | → 准…（逐词白名单，不全局替换 淮→准，保护淮河/淮南） |
| `junk_line` | 段落 ≤40 字、无句读、含 ≥1 个垃圾字符（勹＄竺叩＼｜＠ 等）且前后都是正常正文 | 删除该段并记日志（图内泄漏碎片） |
| `trad_page` | 段内含 ≥3 个 `_TRAD_ONLY` 繁体专用字且本段 <60 字 | 删段；≥2 段命中 → 整页标记 `needs_vision` |
| `junk_page_flag` | 同页命中 `junk_line` ≥2 段或 `trad_page` ≥1 段 | 整页标 `needs_vision`（reocr 入口） |

规则层产出 `{fixes, dropped_paras, flagged_pages}`，全部写审计日志。

### 2. AI 层（`--ai` 开启；按块调用文本 API；默认开）

把正文按页组块（每块 2~3 页 / ≤2500 字），给文本模型送结构化任务：

```
你是书稿 OCR 校对员。输入是一本书某一页的 OCR 转写结果，其中可能有：
OCR 形近错字（如「淮确」应为「准确」、「女子的」应为「好的」）、
应删未删的脚注序号残留（如「债之关系。专」里的「专」）、
外文单词被拆散、括号/引号配对错误、段落被错误拆分或粘连。
你的唯一任务：让文字读得通，不曲解任何内容，不做文字润色。

输出 JSON（不输出任何其他内容）：
{ "edits": [ { "find": "…", "replace": "…" } ],         // find 必须在片段中逐字符出现
  "merges": [ { "into_prev_line": "上一段文本的末 12 字" } ] // 指定应并回上一段的段
}
```

约束（强制写进 prompt + 应用端校验）：
- `old` 必须逐字符出现于当前页串接文本，且**唯一**出现；不满足 → 丢弃该修复（宁可漏改，不可错改）；
- `fixes` 数量 ≤8；`merges` 数量 ≤3；
- `old` 或 `new` 中**禁止**出现 `〔页`、`〔图`、`〔FIGURES`、`〔脚注` 与换行；
- `len(new) ≤ len(old)+4`，且 new 不含 `http`、`【` 等；
- 禁止整段删除正文——AI 若认为整段是图内泄漏不可修，输出 `{"flag": "needs_vision", "page": N}`（每块 `flags` ≤2），程序据此把该页写进批 `needs_vision`（下游 reocr --needs-vision 会处理并阻断 pack，直到用视觉核过）；
- JSON 解析失败 / 超时 / 429 → 跳过该块，规则层成果保留；重试 2 次。

合并动作（`merges` 语义：`merges` 数组里出现第 i 段 ⇒ 第 i 段与第 i+1 段合并，逐条向右吞并）实现为：把这两段按「西文字母→补空格，否则直接拼接」的规则合一，段界消失。合并后段落数减一，写回批文件。

### 3. 主流程 / 命令

```
python bookocr.py proofread <书名> [--pages 31,100-120] [--batch b011] [--all]
                    [--ai] [--no-ai | --rules-only] [--workers 4] [--dry-run] [--no-backup]
```

- 默认（不带 `--rules-only`/`--ai`）：跑规则层 + AI 层，AI 失败兜底规则层；
- AI 层走文本 API（OpenAI 兼容 `/chat/completions`），模型复用 apis.json / `_load_vision_api` 三键；并发 `--workers`（默认 4，429 退避 2 次）；temperature=0.1 偏保守，但可判段界；
- `changes.json`（每次运行：页号、old→new、原因、命中/丢弃计数）+ `proofread_report.md`（前后对照表 + 建议 reocr 页清单）落 `jobs/<书>/proofread/`；
- 重写 `batches/bXXX.txt` 时：备份 `batches/` → `proofread/backup-<ts>/batches/`（与 reocr 备份习惯一致）；**只动页内正文段落，〔页N〕标记、〔图：…〕/〔图版页〕行、批文件结构一律原样保留** —— 保证 `cmd_check`（页标记对账/字数阈值）、`cmd_reocr`、`cmd_pack` 全链路兼容；
- 会同步把有改动的批的 `stats.chars` 用 `PAGE_MARK` 重新计数（写回前重算，供 status 显示与 pack 拦截）；不改动 `needs_vision`/`thin_pages` 之外的台账字段（避免覆盖 done/assigned）。

### 4. 全链路闭环（本次 5 本书的落地顺序）

1. `pull/qa` 既有产物 → `proofread --rules-only` 清确定性垃圾（快速、全部页）；
2. `reocr --needs-vision --exact`：把规则层标记的整页 + pull 遗留 needs_vision 全部视觉重识别（视觉路线书没有本地文字层时退化为 aivision 单页重识别）；
3. `proofread --ai`（全书、分块并发）做通读式纠错/合并段；
4. `qa` 终检 + `spotcheck` → `chapters --no-review`（疑点仍记台账）→ `pack` 三件套。

（2 → 3 顺序的关键：reocr 会整批覆盖批文件，必须先于 AI 微调跑，否则会冲掉微调。）

## 验证方案（写完代码即跑）

1. **单测（selftest.py 扩展，无 API 依赖）**：夹具批文件覆盖 note_tails / l_paren / junk_line / merges / U+FFFD 硬判 / 〔页N〕完整性保持；跑完断言批文件字节级结构与 `check` 全绿；
2. **AI 层离线验证**：临时 stub `_load_text_api` 返回固定 JSON，验证解析/校验/回写全链路（防幻觉注入）；
3. **真实数据试点**：不当得利 p30 页样例（老板原文点名）前后 diff；p31 图示占位行不变；`(l)`、`。专` 清零；
4. **全量回归**：`selftest.py` 全绿、5 本书 `qa` 指标对比表（修复数、垃圾符号数、段尾残留数、短行数、引号坏段数前后对照）。

## 验收标准（全部满足才算完成）

1. 上述 4 项验证通过，metrics 明示 5 本书的修复计数与残余量；
2. 抽检报告 `report/proofread_report.md` 给出建议 `reocr --needs-vision` 页清单（若有）；
3. `pack` 三件套正常产出（txt / 插图版 PDF / KIT 图包 zip），zip 的 kit.json 章节表完整；
4. `selftest.py` ALL PASS；
5. git 工作区干净（模块总览/当前进度/计划案同 commit），GitHub 推送结果如实汇报（失败不重试，列原因）。

## 成本与耗时申报

- 规则层：0 次模型调用；
- AI 层：每次调用 ~2000 token in/out，全书 ~6000 字/块×?块 —— 以不当得利 35.4 万字、630 页的民法总则为例：全书 ≈ 60~70 次调用（分块 2500 字块），5 本书合计 300~350 次调用，预计 25~35 分钟串行；并发 4 后 ≈ 10 分钟；
- 相比整本视觉重识别（5 本 ≈ 6000 页 ≈ 6000 次识图调用），本方案识别调用 0 次，文本校对调用 1/10 量级，是成本下界。

## 已否决的备选方案

- **「AI 整段改写」开放提示**：无法用 find/replace 校验，幻觉风险不可控，不做；
- **「AI 分段全部重建」**：一次返回全书新分段 = 大改写，超出「校对」范畴，不做；
- **「不用 AI、纯规则表」**：老板的示例（女子的→好的、淮→准、勹→删）全部是上下文敏感判断，纯规则表无法覆盖（规则表能兜底的已尽量兜）；
- **「每书跑 3 遍 AI 投票」**：成本 ×3，精度收益 <5%，不做。
