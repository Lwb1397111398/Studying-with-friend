# 视觉识别模块总览

## 模块职责

把页图交给视觉模型（子代理逐页看，或直连视觉 API 并发看）转成正文/脚注/图台账；`spec.md` 是给模型的转写规范。

## 运作流程

1. `cmd_prep` 按 `dpi`（默认 200）把 PDF 渲染成 `images/pNNNN.png`，`manifest.rendered` 记已渲染页。
2. 两条路线：
   - **子代理**：`cmd_next` 发任务卡（页图清单 + spec 路径），子代理写 `batches/bXXX.txt|_notes.txt|_figures.json`，`cmd_check` 验收。
   - **aivision**：`cmd_aivision` 读 `apis.json` 或 Agent Manager 档案库中 caps 含 vision 的档案，按页并发调用 `/chat/completions`，图片 base64 内联；默认 4 路（config `aivision_workers`），429/超时走 `_aivision_page_retry` 退避重试。
3. 模型输出经 `_parse_aivision_page` 拆成正文/脚注/图：识别 `〔脚注〕`、`〔FIGURES〕` 分区；**保留空行**交给 `_join_vision_lines` 分段（空行=段界，标题/编号项/图占位独立成段），`_join_vision_notes` 按编号折叠脚注续行。
4. `_write_batch_from_pages` 把逐页结果写成批文件，`cmd_check` 做页对账与字数/可读字符占比质检。
5. 页级结果落 `reocr/pNNNN.json`（cmd_reocr 使用），可断点续跑。

## 入口文件

- `bookocr.py`：`cmd_prep`、`cmd_aivision`、`_aivision_page`、`_aivision_page_retry`、`_parse_aivision_page`、`_join_vision_lines`、`_join_vision_notes`、`_write_batch_from_pages`、`cmd_next`、`cmd_patch`、`_load_vision_api`
- `spec.md`：转写规范（视觉模型唯一必读）
- `apis.json`（gitignore）：视觉 API 的 base_url/api_key/default_model

## 对外接口 / 被谁调用

- CLI：`prep`、`aivision`、`next`、`patch`
- `cmd_reocr` 复用 `_aivision_page_retry` + `_parse_aivision_page` 做按页重识别。

## 依赖的上游模块

工程与状态（页范围、manifest、rendered）；下游是质检与修复、切章打包。

## 关键数据结构

- 页结果：`{page, body:[段落], notes:[脚注], figs:[{page,rect,kind,title,desc}], model, ts}`
- `figures` JSON：`[{"page":61,"rect":[0.08,0.55,0.92,0.85],"kind":"table","title":"…","desc":"…"}]`

## 已知坑与约束

- 并发 >4 容易触发 429；aivision 默认 4，reocr 默认 3，突发失败会自动退避 5 次。
- 模型常把一个自然段按屏宽折行；**空行才是段界**，`_parse_aivision_page` 不能吞掉空行。
- 双栏索引/年表要在 spec 里明确「先左栏读完再右栏」，否则模型会左右交错。
- 图表内部文字必须转成 `〔图：…〕` 占位 + figures，不能当正文；spec 第 7/11 条约束。
- 页图未渲染的批会被 aivision 跳过，先 `prep --pages`。
