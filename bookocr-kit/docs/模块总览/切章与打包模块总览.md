# 切章与打包模块总览

## 模块职责

把转好的批文件切成手机 App 能直接用的章表，给 pull 图补语义，最后产出 txt、插图版 PDF、KIT 图包三件套。

## 运作流程

1. `cmd_chapters <书名>`：
   - `collect_book` 汇总所有 done 批的正文（按 `〔页N〕` 分段）；
   - 识别章标题（`第X章`）、节标题（`第X节`）、二级标题（`一、`/`（二）`），按字号与位置给 `lv`；
   - 前置块（封面/版权/序言/目录）标 `FRONT`，正文标 `BODY`，附录/索引按标题归类；
   - 与目录页条目逐条对账（相似度），产生 `toc_miss`（目录有、正文没切出）与 `thin`（章内不足 50 字）疑点，写 `chapters_review_task.txt`；
   - `--apply <裁决文件>` 吸收 ADD/DROP/IGNORE；`--no-review` 只记台账不拦 pack；结果存 `manifest.chapters`。
2. `cmd_figdesc <书名>`：
   - 待办 = `manifest.figures` 中 `desc == PULL_FIG_DESC` 的图；
   - 按 `rect`（比例坐标）从 PDF 直接 `get_pixmap(clip=…)` 裁小图 → `figures/<id>_p<页号>.png`；
   - 极扁横条（高 <48px 或高宽比 <0.06）判为装饰线/表格线，跳过识图；
   - 其余并发调视觉 API，返回 `{title,desc,kind}` 写回台账；失败重试一次，413 时降 dpi 重裁。
3. `cmd_pack <书名>`：
   - 拦截：未切章、thin_pages 未 patch、needs_vision 未复核、占位图未补语义（可 `--force`）；
   - 生成 `output/<书名>.txt`：头部写章界元数据块（App 识别后按章表直入），正文把 `〔图：…〕` 占位行替换成补好的图题+描述；
   - 生成 `<书名>_插图版.pdf`（reportlab 可用时，把原图嵌回对应页）；
   - 生成 `<书名>_Kit图包.zip`：`kit.json`（章表+图清单）+ `book.txt` + `figures/*.png`；
   - 写 `report/spotcheck.md`（5 页抽样对照）。

## 入口文件

- `bookocr.py`：`cmd_chapters`、`cmd_figdesc`、`cmd_pack`、`collect_book`、`_aivision_figure`
- 产物：`jobs/<书名>/output/`、`chapters_review_task.txt`、`figures/`

## 对外接口 / 被谁调用

- CLI：`chapters`、`figure-desc`、`pack`
- 依赖质检模块清空 `needs_vision`/`thin_pages` 后才能打包。

## 关键数据结构

- `manifest.chapters`：`[{t:标题,p:页,lv:1|2,r:FRONT|BODY,a:目录对账名}]`
- `manifest.figures`：`[{id,page,rect,kind,title,desc,from_pull,w,h,file}]`
- `kit.json`：`{title, chapters:[…], figures:[…]}`

## 已知坑与约束

- `figure-desc` 之后**不能再跑 pull**：pull 重建 figures 会把语义退回占位。
- `reocr` 会重置 chapters/packed，重识别后必须重跑 chapters 再 pack。
- 章疑点里的 `thin` 多是「章标题独占一页」的正常排版，IGNORE 即可；`toc_miss` 多是目录列到「节」而程序只把「章」当章，别盲目 ADD。
- 插图版 PDF 依赖 reportlab；没装则 txt/zip 照出。
