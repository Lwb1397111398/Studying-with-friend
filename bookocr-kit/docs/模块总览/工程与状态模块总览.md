# 工程与状态模块总览

## 模块职责

一本书一个工程：建工程、渲染页图、记录批次与进度，保证任何命令中断后都能从 `manifest.json` 接着跑。

## 运作流程

1. `cmd_init <书名> --src <PDF>`：读 config（route/pages_per_batch/dpi/output）→ 建 `jobs/<书名>/` → 按 10 页切批（`b001…`）→ 写 manifest（页码、图片路径、批次、状态）→ 打印下一步。
2. `cmd_prep <书名> [--pages a-b]`：按 dpi 渲染页图到 `images/`，更新 `manifest.rendered`；已有页不重复渲染。
3. `cmd_status`：打印批状态计数、done/failed、needs_vision/thin_pages、章数、是否打包，给出下一步提示。
4. 每条命令都通过 `load_manifest/save_manifest` 原子读写 `manifest.json`；长任务逐页落盘（`reocr/pNNNN.json`），中断重跑自动跳过已完成页。
5. `resolve_job`/`normalize_bid` 负责书名与批号解析，允许 `b1`、`001` 等简写。

## 入口文件

- `bookocr.py`：`cmd_init`、`cmd_prep`、`cmd_status`、`load_manifest`、`save_manifest`、`resolve_job`、`normalize_bid`
- `config.json`：route/pages_per_batch/dpi/aivision_workers/chapter_review/output

## 对外接口 / 被谁调用

所有子命令都依赖本模块；`manifest` 是唯一进度权威来源。

## 关键数据结构

`manifest.json`：
```json
{
  "name": "民法总则-王泽鉴2022", "src_pdf": "…", "npages": 630,
  "dpi": 200, "color": false, "route": "pull",
  "pages": [{"image": "images/0001.png"}],
  "rendered": [1,2,…],
  "batches": {"b001": {"pages":[1..10], "body":"batches/b001.txt",
              "notes":"…", "figures":"…", "status":"done",
              "needs_vision":[…], "thin_pages":[…]}},
  "furniture": ["第九章…"], "chapters":[…], "figures":[…], "packed": true
}
```

## 已知坑与约束

- **书眉 `furniture` 在全书写入，reocr --exact 重抽非目标页时要用它**，否则书眉会重新混进正文。
- 多个 bookocr 进程同时跑会争「台账锁」并超时；批量处理请串行。
- `jobs/` 已 gitignore，不随 kit 拷贝走；换电脑重新识别。
- 不要手工改 `manifest.json` 的 batch 状态，跑 `check`/`retry` 更安全。
