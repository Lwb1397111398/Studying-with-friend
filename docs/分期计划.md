# 分期计划

> 依据 `docs/调研/开源同类App调研与借鉴.md` 第四节拍板拆期。每期做完在对应期目下补「启动提示词」供老板复制开新会话。

## 第 1 期：P0 落地（FSRS 复习排期 + 判卷降档梯子）

- **目标**：复习调度换 FSRS-6；AI 判卷输出稳定化。
- **范围**：java-fsrs 接入、Room v11（FSRS 4 列 + review_log + 旧档回填）、四档按钮+预写间隔+记住概率排序；AiClient.chatJson 降档梯子（JSON mode→纯 prompt→校验重试）+ QuizJudge 接入。顺手修复 BackupManager 旧 DTO 漏 itemType。
- **明确不做**：错题重练进 FSRS、出题接 JSON 梯子（防升 promptVersion 触发全量重生成）、出处逐字比对（判卷转述合法，防幻觉归属引用溯源期）。
- **验收标准**：全量单测绿、双 APK 构建绿、四查绿、推送 GitHub。
- **状态**：✅ 2026-11-15 完成（591f188，911 例 0 失败）。

## 第 2 期：P1-③ 引用溯源（讲解/总结标出处可跳原文）

- **目标**：讲解卡与章末总结的正文里，AI 讲到具体内容时标「依据哪一段」并可直接跳过去看原文——法学生最吃「出处」这套，防 AI 凭空编造出处。
- **范围**：①讲解 prompt（explain_note.txt）与总结 prompt（summary_pack.txt 的 <总结>/<串联>）加标记要求，格式 `〔p编号〕`、只准标喂过的段；②生成端软校验——白名单外的标记落库前剔除（不整页重试，零额外 AI 调用）；③渲染端——标记显示成小胶囊（复用 ParaTag 视觉），讲解卡在阅读页内滚动跳段、总结页跳阅读页指定段（Routes.read 的 paraId 参数已存在，直接复用）；④缓存零烧钱——不动 NOTE_VERSION/summary promptVersion，旧讲解照旧显示（无胶囊），新生成才带标记。
- **明确不做**：随手问/判卷/出题的引用（调研拍板先做讲解/总结）；换个讲法（renote）临时流式不加标记；旧缓存强制重生成；跳段高亮底色。
- **验收标准**：新生成的讲解/总结出现可点胶囊且点击跳到对应段；白名单外标记被剔除（单测锁定）；全量单测绿+双 APK 绿+四查绿+推送。
- **状态**：✅ 2026-11-15 完成（全量 921 例 0 失败 +1 skipped，双 APK 绿）。

## 第 3 期：P1-④ prompt 法律向改写 + 人工基准集

- **目标**：把讲解/总结 prompt 按法律教材场景改写（anx-reader 结构 + 我们的术语表/学情体系），改写效果可回归验证而不是纯靠感觉。
- **范围**：先攒 20~30 段典型教材段落做人工基准集（老板参与定「好讲解」标准），再改 prompt，对照基准集评分；改写涉及 promptVersion 升级（触发重生成，烧钱预算须先报老板）。
- **明确不做**：不动判卷 prompt（P0-② 已定校验口径）。
- **验收标准**：基准集落盘 + 改写前后对照评分记录 + 老板点头。
- **状态**：✅ 2026-11-15 完成。基准集 25 段落盘、两版 prompt 改写（评分对照抓出格式跑飞缺陷并修复）、11 段抽样对照评分均值 23.27→24.55（+1.27/25，见 `docs/基准集/评分对照记录.md`）；promptVersion 策略=不升级零烧钱（旧缓存照常显示）。**2026-11-16 老板拍板**：「好讲解」五维标准（忠实/可懂/一句话说透/例子/覆盖，各 0~5 共 25 分）确认生效，后续 prompt 验收均按此对照；promptVersion 维持不升级（想要旧章换新讲解时在讲解卡点「重新生成」，按章可控）。
