## 2026-11-28 更新包「软件包似乎无效」根治（本轮）

- **老板反馈**：手机上这次更新提示「软件包似乎无效」，想在 App 里直接更新成功。
- **取证结论**：云端 Release 资产健康（本机实拉 49,136,746 字节、zip 完整、versionCode=184、签名指纹 `857e5d03…` 不变）——坏在手机端下载到的那份。代码实锤根因：**全链路只验字节数不验内容**——镜像塞错误页/Range 错位字节都能通过长度校验落盘转正；且「长度恰好对但内容坏」的缓存会被反复复用（复用只比长度），重试永远装不上。
- **修复四件**：①`downloadApk` 下载完成/复用缓存/断点转正三处过 `verifyApk`（SHA-256 优先、无哈希退长度比对），不过 `purgeBroken` 清正式包+.part+全部段断点抛人话，再点「立即更新」全新重下自愈；②CI 把 sha256 写进发布说明**第二行**注释 `<!-- studyfriend-update-sha256=… -->`（不能进第一行：旧版 App 解析正则要求 versionName 后紧跟 `-->`，同行加字段会让存量手机全部「远端版本信息无法识别」锁死旧版），`ReleaseInfo`/`parseUpdateMeta` 带出；③CI 发布任务 concurrency 串行（排队非取消）防并发 clobber 写坏资产 + 发布后回读资产比对 sha256 自验（不一致 CI 红不发坏包）；④流式哈希收口 `UpdateChecker.sha256File`（OcrModelDownloader 委托消重）。
- **验证**：快速层 UpdateCheckerTest 29 例（21 存量 + 8 新增：解析第二行 sha/strip 双注释/单流 sha 不符清缓存/坏缓存自愈重下/好缓存复用不联网/断点坏内容清掉/长度与元数据不符不落地/分块 sha 不符全清）+ OcrModelDownloaderTest 9 例（委托后回归）全 0 失败；云端资产本机实拉校验通过（上面取证结论）。全量回归按频控留给下次最终验收。
