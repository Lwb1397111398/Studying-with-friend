> 评分产出过程全部落盘可复现：`法律讲解基准集.json`（25 段基准集）→ `score_offline.py gen`（两版讲解生成）→ `judge2`（评委打分）→ 本记录。
> **2026-11-16 老板拍板**：五维标准确认生效（后续 prompt 验收均按此对照）；promptVersion 维持不升级。

## 方法

- **抽样**：25 段基准集中抽 11 段（覆盖全部 8 类型：概念定义 B01/B03、构成要件 B05/B07、法条阐释 B10、案例分析 B12/B14、学说争议 B16、制度目的 B19/B21、体系定位 B22；区分辨析 B24 因维云网关连续 524 超时未取得改写后版本，放弃不补）。
- **生成**：同一段落喂两版 prompt 各生成一次讲解（模型统一为 glm-5.3，维云渠道，timeout 300s）。
- **评委**：高智商 API（glm-5.3，pro 台账）按五维各 0~5 分打分——忠实度/可懂度/一句话说透/例子质量/覆盖度（口径见 `score_offline.py` JUDGE2_SYSTEM）。一次 consult 评 4 条（2 段×2 版），共 7 次（首轮 6 组 + B03/B05 重评 1 组）。
- **B03/B05 重评说明**：首轮评委给出改写后 B03=18/B05=19 的低分，核查发现根因是**改写后 prompt 偶发格式跑飞**（glm 输出无六标签的纯 markdown，App 端 NotePlanner 会解析失败）——不是讲解质量问题。已修 prompt（格式硬约束两条：首字符必须是 `<标题>` 的 `<` + 落笔前自检），重生成后六标签回归、批注呼应回归，再重评这两段。

## 结论

1. **改写后均值 +1.27（23.27 → 24.55，满分 25）**：11 段中 6 升 2 降 3 平。两处 −1 在评委单次评分方差内；升幅集中在制度目的（+4/+3）与法条阐释/案例分析/体系定位（各 +2）——决策树对「这类段落第一句讲什么」的指引是主要增益来源（评委 comment 实证：改写后「首句即点破核心」vs 改写前「开头先绕批注再给核心」）。
2. **顺带抓出并修复一个真缺陷**：改写后 prompt 首版在 glm-5.3 上偶发不输出六标签（11 段中 2 段），App 端会解析失败。修复=格式硬约束（首字符 `<` + 输出自检条），重生成验证格式回归。该缺陷不改会在真机上表现为部分段落讲解失败。
3. **生成方差提示**：glm-5.3 单条输出风格方差大（同 prompt 两段一个对话体一个教科书体），抽样统计已平滑；老板真机用的主力档案是 deepseek-v4-flash，实际风格以真机为准。
