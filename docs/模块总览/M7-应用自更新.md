## 模块职责（一句话）

App 自己检查 GitHub 上有没有新版本，发现后弹窗、下载 APK、唤起系统安装器覆盖安装——更新包由 GitHub Actions 在每次推送 main 时自动构建发布。

## 运作流程（按真实数据流走）

1. **云端出包**：推送 main → `.github/workflows/build-release.yml` 在 GitHub 的 ubuntu 服务器上跑 `./gradlew assembleRelease`，产物改名 `StudyingWithFriend-latest.apk`，连同发布说明发布到仓库的 `latest` Release（无则创建、有则 `--clobber` 替换）。发布说明第一行是机器可读元数据注释 `<!-- studyfriend-update versionCode=14 versionName=0.1.14 -->`（GitHub 页面渲染不可见），更新内容列最近 5 条提交标题。
2. **版本号来源**：`app/build.gradle.kts` 里 `versionCode = git rev-list --count HEAD`（提交数），`versionName = "0.1.提交数"`。本机构建和云端构建对同一提交算出同一个号；推送一次自动 +1。
3. **App 端检查**：`UpdateViewModel` 在 App 启动时（`AppNav` 的 `LaunchedEffect`）静默调 `autoCheckIfNeeded()`——开关开着且距上次检查超 24 小时才联网；设置页也有手动「检查更新」按钮（`checkNow`）。两者最终都走 `UpdateChecker.fetchLatest`：GET `https://api.github.com/repos/Lwb1397111398/Studying-with-friend/releases/latest`（带 `User-Agent: studyfriend-app`，GitHub 强制要求；**完全匿名**——2026-10-07 起令牌入口已删，`token` 传 null），用 kotlinx-serialization 解析 JSON：从发布说明第一行读 versionCode/versionName，从 assets 里找第一个 .apk 的下载地址和大小。
4. **版本比较**：远端 versionCode > 本机 `BuildConfig.VERSION_CODE` 才算有更新（`Available` 弹窗）；否则「已是最新」。
5. **下载**：`UpdateChecker.downloadApk` 经 HttpURLConnection 流式下载到应用缓存 `cacheDir/updates/update-<versionCode>.apk`，64KB 缓冲边下边回调百分比进度；先写 `.part` 临时文件、校验 Content-Length 一致后才改名——中断不留半截包；同版本号完整文件已存在直接复用不重下。
6. **安装**：`UpdateInstaller.install` 用 FileProvider（authority `com.studyfriend.app.update`，只开放缓存 `updates/` 子目录）拿到 content:// URI，发 `ACTION_INSTALL_PACKAGE` 唤起系统安装器。缺「安装未知应用」授权时自动跳系统开关页（`ACTION_MANAGE_UNKNOWN_APP_SOURCES`），用户打开后回 App 再点一次「安装更新」即可。

## 签名（关键约束）

- 云端构建的包必须和手机上已装的包**签名一致**，否则系统拒绝覆盖安装。
- 本机调试钥匙的副本已提交在 `android/keystore/app.keystore`（PKCS12，口令 android / alias androiddebugkey——标准调试钥匙参数）；gradle 里 debug、release 两个 buildType 都锁这把钥匙。
- 效果：不管在哪构建、什么变体，签名指纹都是 `857e5d03…`，互相可覆盖安装。
- **钥匙随仓库公开（2026-10-01 起仓库已公开）**：任何人可见这把调试钥匙。已评估：签名一致只保证「同一个作者的应用可覆盖安装」，不能授予任何安装或数据权限——别人拿它签的包装不上来覆盖本 App（包名+签名要同时匹配系统才允许覆盖，且 Android 对陌生来源安装本来就弹全屏确认）。风险可控，接受。
- **令牌现状：入口已删除（2026-10-07，老板拍板「已经没有用了」）**。仓库公开后 GitHub API 匿名即可读 Releases，设置页令牌输入栏、「保存令牌」「如何获取令牌？」按钮、令牌指引弹窗全部移除；`UpdateViewModel` 检查/下载一律匿名（`token = null`）。数据层 `SettingsRepository` 的令牌存取方法与 `github_token_enc` 键保留（老数据无害兼容），`UpdateChecker` 的 `token` 参数保留给未来私有仓库场景（单测仍覆盖 Bearer 头）。

## 已知坑与约束

- **更新检查固定走 `releases/tags/latest`，不许改回 `releases/latest`**（2026-10-07 实际翻车）：`releases/latest` 返回的是发布时间最新的 Release，10-05 发的「OCR 模型三件套」Release 发布时间更晚，把它抢走 → App 解析不到版本元数据报「远端版本信息无法识别」。止血：OCR 模型包标记为 prerelease（GitHub latest 会跳过 prerelease；OcrModelDownloader 按 tag 下载资产不受影响）；根治：`UpdateChecker.UPDATE_TAG` 按 tag 查询，任何后续 Release（OCR 模型 v2 等）都不再影响更新检查。**以后往仓库加新 Release，只要不是 App 更新包，一律勾 prerelease**。

- **仓库改名/迁移**：`UpdateChecker.REPO` 和 workflow 里的仓库名要同步改。
- **每次发布覆盖同一个 Release**（tag=`latest`，资产固定名 `StudyingWithFriend-latest.apk`）：App 只认发布说明里的元数据，不认 tag。
- **versionCode 靠 git 提交数**：任何构建环境都必须能跑 `git rev-list`（CI checkout fetch-depth: 0）；取不到时回退 1（实际不该发生）。
- **GitHub API 匿名限流 60 次/小时**：自动检查 24h 节流，正常使用远够（令牌入口已删，如将来转私有需恢复令牌机制，`UpdateChecker.token` 参数已预留）。
- **模拟器/测试**：隐藏键 `update_api_base` 可把更新源指向本地假服务器（E2E 用法见 `tools/fake_github.py`，截图在 `.e2e/*.png`）。
- 系统安装器装 **相同 versionCode** 允许、更低拒绝；测试时假发布的 versionCode 要 >= 已装版本。
- **CI 排坑实录（2026-10-01 首跑三连败修复）**：① Windows 提交的 `gradlew` 丢可执行位 → 云端 `./gradlew` 报 126，需 `git update-index --chmod=+x`（已修，现 100755）；② `android/gradle.properties` 里机器专属 `org.gradle.java.home` 在 Linux 上无效 → 已删，JDK 由各环境 JAVA_HOME 决定；③ 阿里云 Maven 镜像被 GitHub 美国服务器访问会 502 → `settings.gradle.kts` 里 CI 环境（`CI`/`GITHUB_ACTIONS` 环境变量）跳过镜像直连 google/mavenCentral，且条件必须**内联**在块里（pluginManagement 块先于脚本体执行，读不到文件级变量）。
