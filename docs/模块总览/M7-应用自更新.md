# M7 应用自更新 · 模块总览

> 状态：✅ 完成（OPT-F 后新增能力：手机上直接升级，不再需要电脑构建 + 传 APK）
> 验证：单测 9 用例全绿；模拟器 E2E 全链路通过（检查→弹窗→下载→权限引导→系统安装器→安装成功，书架数据保留）

## 模块职责（一句话）

App 自己检查 GitHub 上有没有新版本，发现后弹窗、下载 APK、唤起系统安装器覆盖安装——更新包由 GitHub Actions 在每次推送 main 时自动构建发布。

## 运作流程（按真实数据流走）

1. **云端出包**：推送 main → `.github/workflows/build-release.yml` 在 GitHub 的 ubuntu 服务器上跑 `./gradlew assembleRelease`，产物改名 `StudyingWithFriend-latest.apk`，连同发布说明发布到仓库的 `latest` Release（无则创建、有则 `--clobber` 替换；**发布任务全局串行**（concurrency 组排队），防两次推送并发 clobber 把资产写坏）。发布说明前两行是机器可读元数据注释（GitHub 页面渲染不可见）：第一行 `<!-- studyfriend-update versionCode=14 versionName=0.1.14 -->`（版本判断），第二行 `<!-- studyfriend-update-sha256=… -->`（安装包指纹，2026-11-28 起）；**sha256 必须放第二行**——旧版 App 的解析正则要求 versionName 后紧跟 `-->`，同行加字段会让存量手机全部「远端版本信息无法识别」。发布后 CI 把资产**回读下来比对 sha256 自验**，不一致直接红（宁可 CI 失败不发坏包）。更新内容列最近 5 条提交标题。
2. **版本号来源**：`app/build.gradle.kts` 里 `versionCode = git rev-list --count HEAD`（提交数），`versionName = "0.1.提交数"`。本机构建和云端构建对同一提交算出同一个号；推送一次自动 +1。
3. **App 端检查**：`UpdateViewModel` 在 App 启动时（`AppNav` 的 `LaunchedEffect`）静默调 `autoCheckIfNeeded()`——开关开着且距上次检查超 24 小时才联网；设置页也有手动「检查更新」按钮（`checkNow`）。两者最终都走 `UpdateChecker.fetchLatest`：GET `https://api.github.com/repos/Lwb1397111398/Studying-with-friend/releases/latest`（带 `User-Agent: studyfriend-app`，GitHub 强制要求；**完全匿名**——2026-10-07 起令牌入口已删，`token` 传 null），用 kotlinx-serialization 解析 JSON：从发布说明第一行读 versionCode/versionName，从 assets 里找第一个 .apk 的下载地址和大小。
4. **版本比较**：远端 versionCode > 本机 `BuildConfig.VERSION_CODE` 才算有更新（`Available` 弹窗）；否则「已是最新」。
5. **下载（源池并行分块 + 断点续传 + 内容校验）**：`UpdateChecker.downloadApk` 下载到应用缓存 `cacheDir/updates/update-<versionCode>.apk`，64KB 缓冲边下边回调百分比进度。**内容校验收口（2026-11-28 起，三处）**：下载完成、复用缓存、整包断点转正都过 `verifyApk`——SHA-256（来自发布说明元数据）优先，旧发布没有哈希退回「长度与 Release 元数据一致」比对；只验字节数拦不住「长度恰好对但内容坏」的包（镜像塞错误页/Range 错位字节都可能），装到手机就是系统安装器报「软件包似乎无效」且坏缓存被反复复用——校验不过 `purgeBroken` 清掉正式包+`.part`+全部段断点抛人话，用户再点一次「立即更新」即全新重下自愈。**大包（≥8MB 且源池 ≥2 个）走并行分块**：整包切 2~8 段（目标 ~8MB/段——镜像掐长连接观测点在 ~12MB，段压到 8MB 基本一次拉完不被掐），线程数 = min(段数, 源数×2)，线程完成后按队列领下一段；**源池顺序镜像优先、直连殿后**（国内手机网络直连资产 CDN 大概率被墙，直连打头阵只会白等连接超时；直连能通时兜底补位）；段内源池轮转 **3 轮**（被掐/换源后从段断点续拉只补缺口——轮数不足会让「直连死一次+镜像掐一次」耗尽重试、首次下载必失败，2026-11-22 装机实录）；**源级信号量每源 ≤2 并发许可**（2026-11-22 实测单源 4 连接有 2 条被饿死；一次只持一个许可无死锁）。每段独立断点文件 `.part.c<N>`、Range 从段内断点续拉，服务器不支持 Range 回整包 200 时只有第 0 段可读到段边界、其余段抛错换源；全部段齐 → 按序拼接进整包 `.part` → 校验总长 → 内容校验 → 改名收尾；任一段全部轮次失败抛人话汇总（已齐段保留作断点，重试只补缺口）；进度为各段已收字节聚合、只报单调递增百分比（断点预扫描在主线程线程启动前定案，防各线程初始化竞态）。**小包/无镜像走单流整包**（E2E 假服务器同此路径）：镜像优先依次试、`.part` 半截包保留作断点（`Range: bytes=已收-` 续拉、换镜像也续、服务器不支持 Range 回 200 从头下自愈），同版本完整文件已存在且校验通过直接复用。GitHub 资产 CDN（release-assets.githubusercontent.com）在国内时好时坏（2026-10-25 整段阻断 0 字节到手；2026-11-22 本宽带直连又以 ~230KB/s 拉通）。46.7MB 安装包实测：ghfast.top 单连 ~260KB/s（≈3 分钟）、双连合计 ~1.1MB/s（并行 ~3 倍速）。仅 `https://github.com/` 开头的地址拼镜像（E2E/单测本地地址不拼），测试可用 `chunkCount` 参数强制分块、`sha256` 参数注入校验值。OCR 模型下载（OcrModelDownloader 复用 downloadApk，205MB 模型包）同样受益，其 SHA-256 流式实现已收口到 `UpdateChecker.sha256File`。
6. **安装**：`UpdateInstaller.install` 用 FileProvider（authority `com.studyfriend.app.update`，只开放缓存 `updates/` 子目录）拿到 content:// URI，发 `ACTION_INSTALL_PACKAGE` 唤起系统安装器。缺「安装未知应用」授权时自动跳系统开关页（`ACTION_MANAGE_UNKNOWN_APP_SOURCES`），用户打开后回 App 再点一次「安装更新」即可。

## 签名（关键约束）

- 云端构建的包必须和手机上已装的包**签名一致**，否则系统拒绝覆盖安装。
- 本机调试钥匙的副本已提交在 `android/keystore/app.keystore`（PKCS12，口令 android / alias androiddebugkey——标准调试钥匙参数）；gradle 里 debug、release 两个 buildType 都锁这把钥匙。
- 效果：不管在哪构建、什么变体，签名指纹都是 `857e5d03…`，互相可覆盖安装。
- **钥匙随仓库公开（2026-10-01 起仓库已公开）**：任何人可见这把调试钥匙。已评估：签名一致只保证「同一个作者的应用可覆盖安装」，不能授予任何安装或数据权限——别人拿它签的包装不上来覆盖本 App（包名+签名要同时匹配系统才允许覆盖，且 Android 对陌生来源安装本来就弹全屏确认）。风险可控，接受。
- **令牌现状：入口已删除（2026-10-07，老板拍板「已经没有用了」）**。仓库公开后 GitHub API 匿名即可读 Releases，设置页令牌输入栏、「保存令牌」「如何获取令牌？」按钮、令牌指引弹窗全部移除；`UpdateViewModel` 检查/下载一律匿名（`token = null`）。数据层 `SettingsRepository` 的令牌存取方法与 `github_token_enc` 键保留（老数据无害兼容），`UpdateChecker` 的 `token` 参数保留给未来私有仓库场景（单测仍覆盖 Bearer 头）。

## 已知坑与约束

- **「软件包似乎无效」= 手机上那份安装包内容坏了，不是云端包坏（2026-11-28 装机实录）**：老板手机更新 0.1.184 反复报系统安装器「软件包似乎无效」。实测云端 Release 资产本身健康（zip 完整、versionCode 一致、签名指纹 `857e5d03…` 不变）——坏在下载环节只验字节数不验内容：镜像塞回错误页/Range 错位字节都能通过长度校验落盘转正，且**长度恰好对的坏缓存会被反复复用**（重试也没用）。修复三件：①App 下载/复用/断点三处内容校验（SHA-256 优先、退长度），不过清全部缓存自愈重下；②CI 把 sha256 写进发布说明第二行注释；③CI 发布串行化（concurrency 排队，防并发 clobber 写坏资产）+ 发布后回读资产比对自验。**存量手机最后一跳**：升到首个带校验的版本用的是旧下载代码（老毛病仍在），但新版 versionCode 换了缓存文件名必然全新下载，云端资产健康即可装上；装上后所有后续更新自带哈希校验自愈。
- **「应用未安装」二轮与 sideload 破局（2026-11-28 下午）**：老板装 0.1.185 仍报「应用未安装，软件包似乎无效」，猜「debug/正式版签名不一致」——实测排除（debug/release 同钥匙 L50/L57；本机钥匙=CI 密钥还原分支=云端 184 包=手机 178 签名，三端指纹全 `857e5d03…`；178→185 包名/SDK/ABI/manifest 零变化）。根因同上：旧引擎（178 自带，0.1.180 才修的坏段+轮数不足）二次拉回坏文件。**鸡生蛋死结只能 sideload 破**：本机 assembleRelease 出同签名同版本号 0.1.185 交老板平板手动装（桌面 `读书搭子-0.1.185.apk`），绕开坏下载环节；ghfast.top 当轮 540s 超时（curl 28）佐证镜像不稳。装上后 App 内更新即新引擎。
- **资产 CDN 国内时好时坏：直连与镜像同池并行（2026-11-22 更新）**：`api.github.com`（检查）与 `release-assets.githubusercontent.com`（下载 302 后的资产 CDN）是两套域名。资产 CDN 2026-10-25 曾整段阻断（TCP 建连 0 成功、80MB 包 0 字节到手），2026-11-22 本宽带又能直连拉通 ~230KB/s——时好时坏，所以 App 把直连和镜像组成源池并行分块拉（见运作流程第 5 步），不再赌「直连先失败才换镜像」。镜像判活命令（死一个删一个，改列表 → push → CI 自动出新版）：
  `curl -sL -r 0-1023 -m 15 -o /dev/null -w "%{http_code} %{size_download}B" "https://<镜像>/https://github.com/Lwb1397111398/Studying-with-friend/releases/download/latest/StudyingWithFriend-latest.apk"`，回 `206 1024B`（或 200）即活。
  **2026-11-22 镜像大验尸（12 候选实测）**：只有 ghfast.top 活着（206、支持 Range 断点）；gh-proxy.com 403、ghproxy.net / github.moeyy.xyz / gh.llkk.cc / ghproxy.link / ghproxy.vip / ghproxy.site / ghproxy.cc / hub.gitmirror.com / ghproxy.homeboyc.cn / cf.ghproxy.cc 全部超时——已从 `DOWNLOAD_MIRRORS` 删除。
  **ghfast.top 并发约束**：双连接各 ~580KB/s 不互相挤占，单源 4 连接起开始饿死（4 连接实测 2 条 45s 超时）——分块轮转保证**单源并发 ≤2** 是硬约束。**镜像扛不满单发长连接**（2026-10-25 实测 83MB 单发被掐在 ~12MB）：分块 + 段级断点续传配合用，缺一不可。
  **检查更新没有镜像可走（2026-11-22 实测）**：gh-proxy 族镜像均不代理 api.github.com（403 Invalid input）也不代理 releases.atom——api.github.com 本宽带 WiFi 实测 1.4s 通，手机流量网络若被墙检查会 15s 超时报错，暂无解；候选方案存档未排期（CI 把版本号写进资产文件名，App 走 expanded_assets 镜像页解析版本号）。
  **首次引导死锁**：带兜底的版本自己也得先下载才装得上——存量旧手机没有兜底逻辑，仍下不动。逃逸路径：手机浏览器直接开「活镜像 + APK 地址」下载安装（镜像域名国内可达，浏览器下载中断也能续），或电脑走镜像下载后传手机；装上第一个带兜底的版本后，App 内更新即全自动。

- **更新检查固定走 `releases/tags/latest`，不许改回 `releases/latest`**（2026-10-07 实际翻车）：`releases/latest` 返回的是发布时间最新的 Release，10-05 发的「OCR 模型三件套」Release 发布时间更晚，把它抢走 → App 解析不到版本元数据报「远端版本信息无法识别」。止血：OCR 模型包标记为 prerelease（GitHub latest 会跳过 prerelease；OcrModelDownloader 按 tag 下载资产不受影响）；根治：`UpdateChecker.UPDATE_TAG` 按 tag 查询，任何后续 Release（OCR 模型 v2 等）都不再影响更新检查。**以后往仓库加新 Release，只要不是 App 更新包，一律勾 prerelease**。

- **仓库改名/迁移**：`UpdateChecker.REPO` 和 workflow 里的仓库名要同步改。
- **每次发布覆盖同一个 Release**（tag=`latest`，资产固定名 `StudyingWithFriend-latest.apk`）：App 只认发布说明里的元数据，不认 tag。
- **versionCode 靠 git 提交数**：任何构建环境都必须能跑 `git rev-list`（CI checkout fetch-depth: 0）；取不到时回退 1（实际不该发生）。
- **GitHub API 匿名限流 60 次/小时**：自动检查 24h 节流，正常使用远够（令牌入口已删，如将来转私有需恢复令牌机制，`UpdateChecker.token` 参数已预留）。
- **模拟器/测试**：隐藏键 `update_api_base` 可把更新源指向本地假服务器（E2E 用法见 `tools/fake_github.py`，截图在 `.e2e/*.png`）。
- 系统安装器装 **相同 versionCode** 允许、更低拒绝；测试时假发布的 versionCode 要 >= 已装版本。
- **CI 排坑实录（2026-10-01 首跑三连败修复）**：① Windows 提交的 `gradlew` 丢可执行位 → 云端 `./gradlew` 报 126，需 `git update-index --chmod=+x`（已修，现 100755）；② `android/gradle.properties` 里机器专属 `org.gradle.java.home` 在 Linux 上无效 → 已删，JDK 由各环境 JAVA_HOME 决定；③ 阿里云 Maven 镜像被 GitHub 美国服务器访问会 502 → `settings.gradle.kts` 里 CI 环境（`CI`/`GITHUB_ACTIONS` 环境变量）跳过镜像直连 google/mavenCentral，且条件必须**内联**在块里（pluginManagement 块先于脚本体执行，读不到文件级变量）。
