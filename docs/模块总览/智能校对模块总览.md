# 智能校对模块总览

## 模块职责

一句话：对已转写完成的批文件做两层校对——**规则层**（确定性、零成本）清掉可枚举的 OCR 残留，**AI 层**（文本模型通读上下文）修形近错字与粘连碎句；整页不可信时不硬猜，打 `needs_vision` 标记交回 `reocr` 视觉重识别闭环。

对应老板需求：「AI 通读一遍，把不合理的地方改得合理」——保守纠错、不臆造、不改写语义。

## 运作流程

1. **选批**：命令 `python proofread.py <书名> [--pages 30,35] [--batch b011] [--all] [--no-ai|--rules-only] [--dry-run] [--workers 3] [--no-backup]`（`bookocr.py` 有同名子命令转发）。只挑 `assigned/done` 状态的批；备份 `batches/` 全量复制到 `jobs/<书>/proofread/backup-<时间戳>/batches/`（`--no-backup` 跳过）。
2. **规则层**（对每个目标页的段落序列依序执行，零模型调用）：
   - `note_tails`：句读后（。；：！？"）】》 后）出现脚注序号残留字（心/专/竺卢/叩/乃/弓/井/卫 卢… 白名单集合），且其后是段尾或新句 → 删该字；
   - `l_paren`：段内出现 `（l）`/`(l)` 且同段还有 `(2)`、`（二）` 等其他列举记号（允许空格如 `（2 ）`）→ 改 `（1）`；
   - `latin_upper`：`(IO…`/`（IO…` 这类 I 开头括号串（全/半角括号都认）→ `（10…`（O→0）；
   - `zhiji`：成语白名单「知已知彼」→「知己知彼」；
   - `huai`：词组白名单（淮确/淮的/淮据/淮此/淮绳/淮时/淮于）→ 准…（不全局替换，保护淮河/淮南）；
   - `junk_line`：段落 ≤40 字、无句读、含 ≥2 个垃圾字符变体（勹＄竺叩＼｜｀〜｛｝卩〓 等）→ 删段；若删掉后该页非结构段全空 → **安全兜底**：该页保留原文并只打 `needs_vision`（绝不把整页删成空页）；
   - `trad_page`：段内 ≥3 个繁体专用字且段 <60 字 → 删段；命中 ≥2 段 → 整页 `needs_vision`；
   - `junk_page_flag`：同页 `junk_line` ≥2 段或 `trad_page` ≥1 → 整页 `needs_vision`；
   - 规则层每条改动记录 `{rule, old→new}` 审计。
3. **AI 层**（默认开；`--rules-only`/`--no-ai` 跳过；`PROOFREAD_AI_STUB=<json路径>` 时走离线 stub，selftest 用）：每页组一个块（正文段落编号 【1】【2】…，结构行 `〔页N〕/〔图…〕` 原样传但不许碰）：
   - 通道：apis.json 档案（kit 本地 → Agent Manager `E:\AI Agent\Agent Manager\ai-apis.json` main 档案兜底），OpenAI 兼容 `/chat/completions`，temperature 0.1，重试 2 次；429 → 该档案冷却 30 分钟，401/403/404 → 停用该档案，网络错误 → 5 分钟重试；
   - 模型输出 JSON `{edits:[{find,replace}], merges:[段号], flag}`，受控解析（`_ai_parse`）：
     - `find` 必须在新页文本中**逐字符唯一**出现，否则丢弃该条（宁漏勿错）；
     - 禁止触碰：〔页/〔图/〔FIGURES/〔脚注/〔KIT/http/换行/【/〕；`len(new) ≤ len(old)+4`；edits ≤8、merges ≤3，超限重试；
   - 受控应用（`_ai_apply`）：edits 逐条段内替换（不触结构行，命中 0 或多只记 `ai_skip` 审计不改文）；merges 从后向前吞并（第 v 段并回 v-1 段，西文连写补空格），段数减一；
   - `flag=needs_vision` 或规则层整页命中 → 写入 manifest `batches[bid].needs_vision`（下游 `reocr --needs-vision --exact` 消化；`pack` 会硬拦存在未消 needs_vision 的书）。
4. **写回**：只动页内正文段落；`〔页N〕`/结构行/段间空行格式严格保留（`"〔页N〕"` 独立行、段落一行）。改动的批在 manifest 中用 `_PAGE_MARK` 重算 `stats.chars`，不覆盖 done/assigned/thin_pages 之外字段。
5. **产物**：`jobs/<书>/proofread/changes.json`（按批记录全部改动与 ai_skip）、`proofread_report.md`（前后对照 + 建议 reocr 页清单）。

## 入口文件

- `proofread.py`：全部核心逻辑（选批/规则层/AI 层/写回/报告），可独立运行；
- `bookocr.py`：`_cmd_proofread_bridge` + `proofread` 子命令转发（一行桥接，无重复死代码）；
- 产物目录：`jobs/<书名>/proofread/{changes.json, proofread_report.md, backup-<ts>/}`。

## 对外接口 / 被谁调用

- CLI：`proofread <书名> [--pages|--batch|--all] [--no-ai|--rules-only] [--dry-run] [--workers] [--no-backup]`；
- 写 manifest 的 `needs_vision` → 被 `reocr --needs-vision` 消费、被 `pack` 拦截；
- selftest.py 校对段（规则层 6 规则断言 + AI stub 子进程全链路）。

## 依赖的上游模块

文字层拔取或视觉识别（批文件是输入）；下游是质检与修复（reocr）、切章与打包（pack）。

## 关键数据结构

- `changes.json`：`{ "b001": [ {"rule":"note_tail","old":"…","new":"…"} , {"rule":"ai","old":"…","new":"…"} ], … }`
- manifest 增量字段：`batches[bid].needs_vision`（页号数组）、`batches[bid].stats.chars`（按 `PAGE_MARK` 分段重算）；
- 档案结构：kit `apis.json` / Agent Manager `ai-apis.json`（共享形态：base_url + api_key_env/inline key + models）。

## 已知坑与约束

- 批文件若 `assigned/done` 之外状态会被跳过——先 `next`/`check` 派批；
- 429 冷却期间换档案自动接力；全部档案不可用会人话报错不硬重试，避免反复钉枪限流；
- AI 层永远只是「建议中的小改」：unique 检查 + 长度上限 + 禁词三重闸门，幻觉改不进文；
- merge 只在段号与段数一致时生效，从后往前应用防止段号漂移；
- 已被规则层改过的段落，AI 层若再引用旧文本会因 unique 不匹配自动丢弃——分层运行（先规则后 AI）是安全的。
- 全链路顺序铁律：`proofread` 一定在 `reocr` **之后**（reocr 整批覆盖会冲掉微调），在 `chapters/pack` 之前。
