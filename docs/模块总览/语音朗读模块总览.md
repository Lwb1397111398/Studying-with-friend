# 语音朗读模块总览

> 最后更新：2026-11-22 —— TTS 双模式升级三模式：新增 **Edge 在线朗读**（`EdgeTtsClient` WebSocket 协议 + `EdgeTtsEngine` MediaPlayer 内存播放）并设为默认引擎；根因=老板真机点朗读闪退、两条旧引擎路径真机从未验证。系统引擎补 TextToSpeech 构造器/入队 runCatching 加固。

## 模块职责

一句话：把书「读出声」——阅读页正文听书、章末总结包记忆思路朗读，提供「Edge 在线（默认）」「手机自带」「本地离线模型」三引擎，设置页可切换、离线模型可在设置页下载。

## 运作流程（按数据真实流向）

1. **用户点朗读**：阅读页工具行「朗读」chip（`ReadScreen.toggleTts`）拼接本章 BODY 段文本（`\n` 连接）调 `TtsPlayer.toggle(text)`；总结包记忆 Tab 同款调 `tts.toggle(asset.memoryMd)`。
2. **选引擎**：`TtsPlayer.mode` 来自设置 `KEY_TTS_ENGINE`（`SettingsRepository.ttsEngineMode()`，edge/system/local，坏值回退 **edge**），进页时 `LaunchedEffect` 读入；Edge 音色另存 `KEY_TTS_EDGE_VOICE`（晓晓/云希）。
3. **prepare 分级诊断**（返回 null=可用 / 非 null=用户可读原因）：
   - Edge 在线（`EdgeTtsEngine`）：ConnectivityManager 检查有网即可用；真正的握手/合成失败在 speak 阶段人话报错。
   - 系统（`AndroidTtsEngine`）：①`queryIntentServices(TTS_SERVICE)` 预检（需 Manifest `<queries>` 声明，Android 11+ 包可见性）→ ②TextToSpeech 初始化挂 6 秒超时，**构造器异常 runCatching 兜住（2026-11-22 加固，少数 ROM 直接抛异常闪退）** → ③`setLanguage(简体中文)` 放宽检查。
   - 离线（`SherpaTtsEngine`）：`TtsModelManager.isTtsReady`（373 文件尺寸下限全达标）→ OfflineTts 单例加载（数秒，App 级常驻避免反复重载）。
4. **回落策略**：LOCAL 不可用 → 自动改用系统引擎，`notice` 输出「离线朗读暂不可用（原因），这次先用系统语音」；**EDGE 不可用直接 Error 不回落**（回落只会退回已不可用的路径，明说原因让用户自己切）。
5. **发声**：`splitSentences` 分句（句末标点/分号/换行，4000 字符硬切）后逐句：
   - **Edge 引擎**：逐句 `EdgeTtsClient.synthesize`（WebSocket 连 `speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1`，握手带 TrustedClientToken+Sec-MS-GEC 防伪令牌，先发 speech.config 声明 mp3 24kHz 48kbps，再发 ssml 请求；收二进制帧取 Path:audio 负载拼 mp3，Path:turn.end 收尾）→ `MediaPlayer` + `ByteArrayMediaDataSource` 内存直播不落盘；**当前句播放期间后台预取下一句**，句间停顿压到毫秒级；每句播完推进句进度；`stop()` 取消合成协程 + 主线程 release 播放器立即掐声。语速 0.5~2.0 映射 SSML prosody rate 百分数；401/403 视为设备时钟偏差，探测服务器 Date 校正后重试一次。
   - 系统引擎：全部句子 `QUEUE_ADD` 入队（入队 runCatching 加固），`utteranceId` 编码句序号，`onDone` 推进句进度；
   - 离线引擎：逐句 `generateWithCallback`（音色 sid=3 中文女声 zf_001、speed=语速倍率）边合成边写 AudioTrack（约 5 秒缓冲领先量），每句写完推进进度，全部播完等 `playbackHeadPosition` 追上再收尾。
6. **高亮跟随**：句进度 → `sentenceToParaIndex`（每段分句数前缀和映射）→ 段底色淡染 + 自动滚动。
7. **模型下载**（`TtsModelManager`）：清单 373 个文件共约 205MB（model.int8.onnx 114MB + voices.bin 53MB + lexicon/dict/espeak-ng-data），源站 `hf-mirror.com` 直连（迁 Xet 后 307/302 链路自动跟随，文件路径逐段 URL 编码；`.part` + Range 断点续传，416 弃 .part 重下；失败集整批再试最多 3 遍）。**选 Edge 后此整块变成可选下载，不再挡朗读**。

## 入口文件清单

- `data/tts/TtsPlayer.kt` —— TtsEngine 接口 + TtsState 状态机 + 三模式分发/回落/notice + splitSentences/sentenceToParaIndex
- `data/tts/EdgeTtsClient.kt` —— Edge 在线合成客户端（WebSocket 协议/Sec-MS-GEC 令牌/SSML 组帧/音频帧解析/时钟校正重试；endpoint 与 clockSkewProbe 可注入供单测）
- `data/tts/EdgeTtsEngine.kt` —— Edge 引擎（逐句预取/MediaPlayer 内存播放/stop 掐声/语速音色）
- `data/tts/AndroidTtsEngine.kt` —— 手机自带系统 TTS 封装（分级诊断/超时/语速/构造器与入队加固）
- `data/tts/SherpaTtsEngine.kt` —— sherpa-onnx 离线引擎（kokoro 配置/AudioTrack 播放/单例）
- `data/tts/TtsModelManager.kt` —— 离线模型清单/下载/断点续传/就绪判定/删除
- `data/tts/TtsChunkCallback.java` —— sherpa JNI 回调（必须 Java 实现，见坑 2）
- UI 接入：`ui/screens/ReadScreen.kt`（正文听书）、`ui/screens/ChapterAssetsScreen.kt`（MemoryPane 记忆朗读）、`ui/screens/SettingsScreen.kt` + `SettingsViewModel.kt`（引擎三选/Edge 音色/模型下载管理）、`data/SettingsRepository.kt`（KEY_TTS_ENGINE/KEY_TTS_RATE/KEY_TTS_EDGE_VOICE）
- 资产：`android/app/libs/sherpa-onnx-1.13.8.aar`（官方完整版，自带配套 onnxruntime，同名冲突经 packaging pickFirst 解决，见坑 3）

## 对外接口 / 被谁调用

- `TtsPlayer(systemEngine, scope, localEngine?, edgeEngine?)` + `state/notice/mode/toggle/pause/resume/stop/shutdown`：M4a 正文听书、M5 记忆朗读两处调用。
- `EdgeTtsClient.synthesize(text, voice, ratePercent)` → mp3 字节（ByteArray?，null=失败）；`EdgeVoices.XIAOXIAO/YUNXI` 音色常量。
- `TtsModelManager.state/startDownload/deleteTtsModel/isTtsReady`：设置页调用。
- `splitSentences`/`sentenceToParaIndex` internal 函数：ReadScreen 分段计数用。

## 依赖的上游模块

- M1 数据层：SettingsRepository（Room SettingDao 存引擎模式/语速/Edge 音色）。
- `com.squareup.okhttp3:okhttp:4.12.0`（2026-11-22 Edge 引擎引入）：WebSocket 客户端——`java.net.http` 要 API 34+、minSdk 26 只能走 OkHttp；MockWebServer 同版本仅 testImplementation。okhttp 自带 consumer R8 规则，release 无需额外 keep。
- 微软 `onnxruntime-android:1.22.0`（OCR 引入）：与 sherpa aar 同名 so 冲突经 pickFirst 解决（APK 保留 sherpa 版）；OCR Java API 运行时跑 sherpa 的 ort，兼容性依据见坑 3。
- 网络：hf-mirror 下载走 HttpURLConnection；Edge 走 okhttp；INTERNET 权限已有。

## 关键数据结构

- `TtsEngineMode { SYSTEM, LOCAL, EDGE }`；`TtsState { Idle, Preparing, Speaking(sentenceIdx, total), Paused(sentenceIdx, total), Error(message) }`；`TtsModelManager.DownloadState { Idle, Running(done, total), Done, Failed(message) }`。
- `TtsFile(relPath, bytes)`：模型清单条目，bytes 兼作完整性下限。
- 模型落盘：`context.filesDir/tts/kokoro-v1.1-zh/`（与听的思维同目录名）；Edge 音频不落盘（内存 MediaDataSource）。

## 已知坑与约束

1. **「点朗读闪退」修复策略（2026-11-22）**：老板平板点朗读即闪退，两条旧引擎路径在真机从未出声验证过（模拟器 AOSP 无 TTS 引擎，出声路径只有 JVM 单测锁定）。修复=三管齐下：①Edge 在线引擎设为默认（未改过设置的用户升级后自动绕开两条旧路径）；②系统引擎 TextToSpeech 构造器 + speak 入队 runCatching 兜成人话错误（构造器抛异常是少数 ROM 的已知形态）；③sherpa native 层 SIGSEGV 无法 catch，保持显式选「离线模型」才加载的策略（默认不触发）。**闪退根因未拿到真机崩溃栈，属推断修复**——老板升级后若仍闪退（Edge 模式下不该再发生），先看设置页当前引擎是什么。
2. **Sec-MS-GEC 防伪令牌**（2024-08 起微软强制）：unix 时间转 Windows 纪元 ticks，向下取整 5 分钟窗（3_000_000_000 ticks），SHA256("ticks+token") 大写十六进制。设备时钟偏差 >5 分钟会 401/403——客户端探测服务器 Date 头算偏差重试一次（`clockSkewProbe` 可注入，单测不发真网）。测试向量由 Python 独立实现交叉验证（EdgeTtsClientTest）。
3. **TrustedClientToken 不是密钥**：`6A5AA1D4EAFF4E9FB37E23D68491D6F4` 是写死在 Edge 浏览器里的公开常量，所有 edge-tts 类客户端通用，无需申请、不入库也不违背凭据纪律。协议为非官方接口：微软改协议/限流时朗读会挂——报错文案已引导切回「手机自带」。
4. **Manifest `<queries>` TTS_SERVICE 必须存在**：targetSdk 30+ 没它 TextToSpeech 绑不上引擎、初始化必失败。2026-10-25 补上。
5. **sherpa JNI 回调必须用 Java 写**：JNI 用硬编码签名 `invoke([F)Ljava/lang/Integer;` 反查回调方法，Kotlin 2.x lambda（indy）没有该桥接方法，合成首个分片直接 abort。`TtsChunkCallback.java` 即为此存在。
6. **onnxruntime 同名 so 冲突与 pickFirst**：sherpa 官方 aar 自带 4 ABI 的 `libonnxruntime.so`，与 OCR 的微软 onnxruntime-android 1.22.0 同名——`packaging.jniLibs.pickFirsts` 保留先声明的 sherpa 版。**曾试过剔除 sherpa 自带 so 共享微软 1.22.0，实测失败**（`@@VERS_1.22.0` 符号版本标签 bionic linker 解析不到）。副作用：OCR 微软 Java API 运行时跑在 sherpa 的 ort 上（C API 单入口向后兼容，理论兼容，OCR 实测过没问题）。
7. **R8 keep 必须**：release 开 minify，`com.k2fsa.sherpa.onnx.**` 已全量 keep；`ai.onnxruntime.**` 的 keep 原有；okhttp 自带 consumer 规则不用管。
8. **native 引擎单例常驻**：114MB 模型加载数秒，OfflineTts 挂 companion 常驻（选过离线模式后才加载）；低内存设备注意。
9. **prepare 签名是 `suspend fun prepare(): String?`**（null=可用）：错误原因必须用户可读，UI 原样展示；不要回退成 Boolean。
10. **produceState 线程纪律**（沿袭 M5）：引擎回调来自非主线程，Compose 侧 collect 必须 `withContext(Dispatchers.Main)` 写快照。
11. **晚到错误忽略**（沿袭 M5）：用户 stop 后引擎晚到 onError 依状态忽略，不把 Idle 覆盖成 Error。
12. **模拟器（AOSP 镜像）无任何 TTS 引擎**：系统模式报「本机没有可用的系统朗读引擎」（预检命中，非 bug）；离线/Edge 模式可完整验证发声（Edge 走真网）。
13. **hf-mirror 仓库状态会漂移，改清单前先对账**（2026-11-15 教训）：迁 Xet 后清单旧值与实际不符会让「尺寸下限校验」永远判不完整+续传 416，用户侧现象是「下载半路下不动」。再大面积挂下载先跑对账脚本（Range 0-0 读 Content-Range/Content-Length，429 退避）。
14. **下载只活在进程内**：TtsModelManager 挂 App 级 scope，锁屏/后台被杀即中断（无前台服务）；.part 全保留，回设置页点「继续下载」断点续传。
15. **Edge 引擎语速上限 +100%**：SSML prosody rate 百分数钳到 -50%~+100%（系统引擎 0.5~2.0 全域支持，Edge 超出范围服务端拒绝合成）。
