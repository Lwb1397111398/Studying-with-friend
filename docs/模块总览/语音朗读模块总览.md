# 语音朗读模块总览

> 最后更新：2026-10-25 —— TTS 双模式改造：手机自带系统引擎修复（queries 声明 + 分级诊断 + 超时兜底）+ 本地离线模型引擎（sherpa-onnx kokoro）+ 模型下载管理 + 自动回落。经验学自「听的思维」项目（`C:\AIWorkSpace\tingsiwei-src`，同机系统语音可用的对照组）。

## 模块职责

一句话：把书「读出声」——阅读页正文听书、章末总结包记忆思路朗读，提供「手机自带」与「本地离线模型」双引擎，设置页可切换、离线模型可在设置页下载。

## 运作流程（按数据真实流向）

1. **用户点朗读**：阅读页工具行「朗读」chip（`ReadScreen.toggleTts`）拼接本章 BODY 段文本（`\n` 连接）调 `TtsPlayer.toggle(text)`；总结包记忆 Tab 同款调 `tts.toggle(asset.memoryMd)`。
2. **选引擎**：`TtsPlayer.mode` 来自设置 `KEY_TTS_ENGINE`（`SettingsRepository.ttsEngineMode()`，system/local，坏值回退 system），进页时 `LaunchedEffect` 读入。
3. **prepare 分级诊断**（返回 null=可用 / 非 null=用户可读原因）：
   - 系统（`AndroidTtsEngine`）：①`queryIntentServices(TTS_SERVICE)` 预检（需 Manifest `<queries>` 声明，Android 11+ 包可见性——真机「没有可用中文语音」根因之一）→ ②TextToSpeech 初始化挂 6 秒超时（裸机回调可能永不返回）→ ③`setLanguage(简体中文)` 放宽检查（国产引擎返回 LANG_MISSING_DATA 但实际能读，不判死）。
   - 离线（`SherpaTtsEngine`）：`TtsModelManager.isTtsReady`（373 文件尺寸下限全达标）→ OfflineTts 单例加载（数秒，App 级常驻避免反复重载）。
4. **自动回落**：LOCAL 不可用 → `TtsPlayer` 自动改用系统引擎发声，`notice` StateFlow 输出「离线朗读暂不可用（原因），这次先用系统语音」，UI 朗读中低调显示；两边都不可用 → Error 行报系统引擎的准确原因。
5. **发声**：`splitSentences` 分句（句末标点/分号/换行，4000 字符硬切）后逐句：
   - 系统引擎：全部句子 `QUEUE_ADD` 入队，`utteranceId` 编码句序号，`onDone` 推进句进度；
   - 离线引擎：逐句 `generateWithCallback`（音色 sid=3 中文女声 zf_001、speed=语速倍率）边合成边写 AudioTrack（约 5 秒缓冲领先量），每句写完推进进度，全部播完等 `playbackHeadPosition` 追上再收尾。
6. **高亮跟随**：句进度 → `sentenceToParaIndex`（每段分句数前缀和映射）→ 段底色淡染 + 自动滚动。
7. **模型下载**（`TtsModelManager`）：清单 373 个文件共约 205MB（model.int8.onnx 114MB + voices.bin 53MB + lexicon/dict/espeak-ng-data），源站 `hf-mirror.com`（HuggingFace 国内镜像）直连；单文件 `.part` + Range 断点续传，服务端不认 Range 回 200 自愈重下；3 次重试；下载挂 object 自持 App 级 scope，离开设置页不中断；完成后原子改名到位。入口在设置页「朗读引擎」区块（进度条/继续下载/删除模型带确认弹窗）。

## 入口文件清单

- `data/tts/TtsPlayer.kt` —— TtsEngine 接口 + TtsState 状态机 + 双模式分发/回落/notice + splitSentences/sentenceToParaIndex
- `data/tts/AndroidTtsEngine.kt` —— 手机自带系统 TTS 封装（分级诊断/超时/语速）
- `data/tts/SherpaTtsEngine.kt` —— sherpa-onnx 离线引擎（kokoro 配置/AudioTrack 播放/单例）
- `data/tts/TtsModelManager.kt` —— 离线模型清单/下载/断点续传/就绪判定/删除
- `data/tts/TtsChunkCallback.java` —— sherpa JNI 回调（必须 Java 实现，见坑 2）
- UI 接入：`ui/screens/ReadScreen.kt`（正文听书）、`ui/screens/ChapterAssetsScreen.kt`（MemoryPane 记忆朗读）、`ui/screens/SettingsScreen.kt` + `SettingsViewModel.kt`（引擎选择/模型下载管理）、`data/SettingsRepository.kt`（KEY_TTS_ENGINE/KEY_TTS_RATE）
- 资产：`android/app/libs/sherpa-onnx-1.13.8.aar`（官方完整版，自带配套 onnxruntime，同名冲突经 packaging pickFirst 解决，见坑 3）

## 对外接口 / 被谁调用

- `TtsPlayer(systemEngine, scope, localEngine?)` + `state/notice/mode/toggle/stop/shutdown`：M4a 正文听书、M5 记忆朗读两处调用。
- `TtsModelManager.state/startDownload/deleteTtsModel/isTtsReady`：设置页调用。
- `splitSentences`/`sentenceToParaIndex` internal 函数：ReadScreen 分段计数用。

## 依赖的上游模块

- M1 数据层：SettingsRepository（Room SettingDao 存引擎模式与语速）。
- 微软 `onnxruntime-android:1.22.0`（OCR 引入）：与 sherpa aar 同名 so 冲突经 pickFirst 解决（APK 保留 sherpa 版）；OCR Java API 运行时跑 sherpa 的 ort，兼容性依据见坑 3。
- 网络：HttpURLConnection（无 okhttp），hf-mirror 需 INTERNET 权限（已有）。

## 关键数据结构

- `TtsEngineMode { SYSTEM, LOCAL }`；`TtsState { Idle, Preparing, Speaking(sentenceIdx, total), Error(message) }`；`TtsModelManager.DownloadState { Idle, Running(done, total), Done, Failed(message) }`。
- `TtsFile(relPath, bytes)`：模型清单条目，bytes 兼作完整性下限。
- 模型落盘：`context.filesDir/tts/kokoro-v1.1-zh/`（与听的思维同目录名）。

## 已知坑与约束

1. **Manifest `<queries>` TTS_SERVICE 必须存在**：targetSdk 30+ 没它 TextToSpeech 绑不上引擎、初始化必失败。2026-10-25 补上——真机「本机没有可用的中文语音，无法朗读」报错的根因之一（同机「听的思维」有此声明故正常）。
2. **sherpa JNI 回调必须用 Java 写**：JNI 用硬编码签名 `invoke([F)Ljava/lang/Integer;` 反查回调方法，Kotlin 2.x lambda（indy）没有该桥接方法，合成首个分片直接 abort（听的项目实证）。`TtsChunkCallback.java` 即为此存在。
3. **onnxruntime 同名 so 冲突与 pickFirst**：sherpa 官方 aar 自带 4 ABI 的 `libonnxruntime.so`，与 OCR 的微软 onnxruntime-android 1.22.0 同名——`packaging.jniLibs.pickFirsts` 保留先声明的 sherpa 版（`app/libs/sherpa-onnx-1.13.8.aar` 官方完整版）。**曾试过剔除 sherpa 自带 so 共享微软 1.22.0，实测失败**：微软 ort 的 `OrtGetApiBase` 带 `@@VERS_1.22.0` 符号版本标签，sherpa JNI 的裸符号引用在 bionic linker 解析不到（dlopen failed）。副作用：OCR 的微软 Java API（ai.onnxruntime 1.22）运行时跑在 sherpa 的 ort 上——两 so 导出符号集完全一致（C API 单入口设计 + GetApi 向后兼容），理论兼容；首次 OCR 实测前属 UNMEASURED，若 OCR 失败，回退方向 = 恢复微软版优先（pickFirst 顺序换位，但 sherpa TTS 将不可用）或降级微软依赖。
4. **R8 keep 必须**：release 开 minify，`com.k2fsa.sherpa.onnx.**` 已全量 keep（JNI 按类名动态注册 + TtsChunkCallback Function1 签名反查，混淆即挂）；`ai.onnxruntime.**` 的 keep 原有。32 位机型（armeabi-v7a/x86）：sherpa aar 4 ABI 全带 ort → 离线朗读可用；微软 aar 只发 arm64/x86_64 → OCR 在 32 位机型本就不可用（引入微软依赖即有，非本轮引入）。
5. **native 引擎单例常驻**：114MB 模型加载数秒，OfflineTts 挂 companion 常驻（选过离线模式后才加载）；`shutdown()` 只停播不释放 native。低内存设备注意。
6. **prepare 签名是 `suspend fun prepare(): String?`**（null=可用）：错误原因必须用户可读，UI 原样展示；不要回退成 Boolean。
7. **produceState 线程纪律**（沿袭 M5）：引擎回调来自非主线程，Compose 侧 collect 必须 `withContext(Dispatchers.Main)` 写快照。
8. **晚到错误忽略**（沿袭 M5）：用户 stop 后引擎晚到 onError 依状态忽略，不把 Idle 覆盖成 Error。
9. **模拟器（AOSP 镜像）无任何 TTS 引擎**：系统模式报「本机没有可用的系统朗读引擎」（预检命中，非 bug）；离线模式可完整验证发声。
10. **hf-mirror 小文件阶段慢**：373 文件逐个 HTTP 往返，大头（3 个文件占 170MB）几秒完成，espeak 小文件阶段约 15-20 分钟——真实体验，非 bug；断点续传保底。
