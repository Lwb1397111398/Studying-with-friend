# M5 计划案：章末总结包（总结/导图/记忆/串联/自测 + TTS/导出）

> 依据：总计划 §4.2/§4.3 任务 3、§5 里程碑 M5 行、§7 风险表；M4a 总览承诺（chapter_assets 已建未写、讲解内容是总结输入）、M4b 总览承诺（decodeCheckQuestions 自测卡消费、AiGate 全应用互斥纪律、Robolectric 视口教训）。
> 资产复用：E:\engine\tingsiwei 已验证的 TreeText（TAB 树）、MindMapPanel（WebView 桥接防循环）、assets/mindmap（index.html + MindElixirFull.iife.js，117KB 原样拷贝）。

## §1 目标与非目标

**目标**：读完一章（粗读完成）后，一次 AI 调用产出五件套并落库 `chapter_assets`：`<总结>`（markdown ≤600 字）、`<导图>`（TAB 缩进树、节点 ≤15 字）、`<记忆思路>`（200-500 字故事式）、`<串联>`（并列/递进知识点的故事线，优先时间线/成长线/因果线）、`<自测>`（3-5 题 JSON：RECALL/TRUE_FALSE/CASE，考推演不考背诵）。UI 提供五页签浏览、流式生成视图、导图渲染与 PNG 导出、记忆思路 TTS 朗读、总结包导出 Markdown、自测作答落库（错题本数据源）。生成成功时写入复习排期种子（1 天首期，M6 推进）。

**非目标（锁定范围）**：全书总览与复习中心 UI（M6）；错题本 UI（M6）；讲解详略档位与视觉规格（M7）；导图节点编辑与回写（editable=false，只读+导出，编辑能力入 backlog）；OCR；iOS。

## §2 数据与算法

### 2.1 输入组装（buildSummaryInput）

总计划 §119：**总结包只喂讲解要点而非全文**。前置条件：`db.paragraphDao().byChapter(chapterId)` 中存在 `aiAction != "NONE"` 的段落（即已粗读）；否则抛 `PlannerException("本章还没有粗读标注，请先完成粗读")`（UI 引导回阅读页）。

user 消息为手拼 JSON（沿用共享 `jsonEsc`）：
```
{"title":章名, "gist":章gist或"", "terms":要点term顿号串,
 "paragraphs":[{"id":idx, "act":"explain|group|skip",
   "text":讲解段 take(500) / SKIP 段 take(60), "why":AI 理由或 "",
   "note":该段所属讲解卡的 title+friendly take(200)（有才给）}]}
```
段落顺序按 idx；讲解段若属同一 GROUP 组，只在锚段条目带 note。

**总量预算硬顶（评审 P1-1）**：user 消息总字数（含 JSON 结构）超过 **24K** 时逐档降级，确定性循环直到达标：
- 档 0（默认）：讲解段 text 500 / SKIP 段 text 60 / note 200
- 档 1：讲解段 300 / SKIP 段不带 text（仅 act 标记）/ note 100
- 档 2：讲解段 150 / note 50
- 档 3：讲解段 80 / note 只留 title
- 档 4（终档，评审 P2-3）：仅前 120 段按档 3 规格保留 text/note，其余段只留 `{"id","act"}`——档 3 单段约 196 字，120 段即达 24K，此为硬地板；边界声明：**>120 段的章超出支持范围（提示先拆章）**

这样 100 段全 EXPLAIN 的极端章也被压进上下文（约 100×230≈23K），不会 API 400；专测锁定（§5 超长章预算）。

### 2.2 调用与解析（TaggedBundleParser）

`AiClient.chat(req, onDelta)` 纯文本流式（M3 已建，ChatRequest temperature=0.4、**maxTokens=6000**——五件套输出约 2600-3000 字+结构开销，M4b 教训：上限偏紧会导致末标签被截断→解析失败→整包重试双倍额度）。输出五标签文本。注入点 `ChatTextFn`（interface + suspend operator invoke，同 ChatJsonFn 模式，测试可换假实现）。

`TaggedBundleParser.parse(raw): SummaryBundle?`：
- 正则逐标签提取：`Regex("<总结>\\s*(.*?)\\s*</总结>", DOTALL)` 等五组，非贪婪、允许任意顺序；
- `<自测>` 内容先剥 markdown 围栏（```json ... ```）再 `QuizCodec.decode`；
- 校验：总结与记忆思路与串联非空、导图树 `TreeText.parse` 结果非空、自测题数 ≥1（>5 截 5）——任一不满足返回 null（整体失败，不部分落库，避免残包）。

### 2.3 QuizCodec

`@Serializable data class QuizQuestion(type:String="RECALL", q:String, a:String, explain:String="")`，type 归一到大写并白名单（其余按 RECALL）。`quizJson` 列 = ListSerializer 编解码，坏数据回退空列表（同 KeyTermsCodec 模式）。

### 2.4 SummaryPlanner 流水线

`class SummaryPlanner(db, context, settings, chatTextFn)`，`suspend fun run(chapterId, force=false, onDelta): SummaryAssetResult`（withContext(Dispatchers.IO)）：
1. 前置：章存在、`settings.decryptKeyOrNull()`（无→MissingKeyException）、2.1 标注检查；
2. 组装输入 + 加载 prompt（PromptLoader.load("summary_pack")，PROMPT_SUMMARY="summary_pack"）；
3. `chat()` 流式（onDelta 直通 Runner）→ raw；
4. `TaggedBundleParser.parse` → null 时**重试 1 次**（重试 user 消息追加"上次输出不符合五标签格式，请严格按格式重新输出"）；两次均 null → **Log.w 记录 raw 输出前 2000 字（快照留档，评审 P2-7）**后抛 `PlannerException("总结包解析失败，请重试")`——**不落库，绝不覆盖旧资产**；
5. `db.chapterAssetDao().upsert(ChapterAssetEntity(...))`（summaryMd/mindmapTree=原始 TAB 树文本/mindmapJson=null（渲染时由 TreeText 现转，存原始可人读文本）/memoryMd/chainMd/quizJson/model/promptVersion=SUMMARY_VERSION="summary-pack-v1"/createdAt）；**重生成成功落库时 `quizAttemptDao.deleteForChapter(chapterId)` 清空本章作答历史（评审 P1-3：attempt 只存 qIndex，重生成后同 qIndex 是不同题，旧作答挂新题是错数据；题目身份随资产版本失效，历史随之作废）**；
6. 排期种子：`reviewItemDao.insertAll(listOf(ReviewItemEntity(bookId, chapterId, 章名, intervalIdx=0, dueAt=now+1天)))`——`OnConflictStrategy.IGNORE` + unique(bookId,chapterId,title) 保证重生成不重复排期。

### 2.5 SummaryRunner（四态 + AiGate）

沿 M4b NoteRunner 模式：StudyApp 单例注入共享 `aiGate`；`StateFlow<SummaryRunState>` **四态**（评审 P2-4：总结包是单调用原子任务，无"部分完成保留"语义，不设 Interrupted）：
`Idle / Streaming(chapterId, partial:String) / Succeeded(chapterId, message) / Failed(chapterId, message, keyIssue:Boolean)`。
- start：join 模式自替换（捕获 old→cancel→新协程 join→`gate.tryBegin("总结")`→try/catch(CancellationException 保序不抹状态)/finally gate.end()）；
- onDelta 累积 StringBuilder → `_state.value = Streaming(...)`（StateFlow conflation 天然节流）；
- stop()：cancel + 回 Idle（流式中断不落库）；流式中途 IO 断连（区别于主动停止）→ Failed，同不落库；
- 完成文案："总结包已生成（自测 N 题）"（Succeeded）；
- **已知取舍（评审 P2-9 登记）**：整包原子落库下，生成后半途手动 stop 等于本次额度作废；"partial 暂存可恢复"入 backlog，v1 不做。

### 2.6 TtsPlayer 状态机（data/tts/TtsPlayer.kt）

`interface TtsEngine { suspend fun prepare(): Boolean; fun speak(text: String, onSentence: (Int) -> Unit, onDone: () -> Unit, onError: (String) -> Unit); fun stop(); fun shutdown() }`（评审 P1-2：逐句进度与错误都要有出口）；
`AndroidTtsEngine(context)` 包装 TextToSpeech（prepare 检查 `setLanguage(SIMPLIFIED_CHINESE)` ≥ LANG_AVAILABLE，缺失→false）；speak 前按句号/问号/换行分句（每段 ≤4000 字符硬限），**逐句 `QUEUE_ADD` 入队、utteranceId 编码句序号**：`UtteranceProgressListener.onDone(id)` 解出序号回调 `onSentence(idx)`（TtsPlayer 借此推进 Speaking(idx,total)）、最后一句 onDone 触发 `onDone()`、`onError(id)` 触发 `onError(msg)`；**用户 stop 引发的 onError（ERROR_STOPPED 类）由 TtsPlayer 依状态忽略**（已在回 Idle 路径）。
`class TtsPlayer(engine, scope)`：`StateFlow<TtsState>` = `Idle / Preparing / Speaking(sentenceIdx, total) / Error(msg)`；`toggle(text)` 切换播放/停止。Screen `DisposableEffect` 释放 engine。FakeEngine 驱动状态机单测（含"合成错误→Error"用例）。

### 2.7 注入与入口

StudyApp：`val summaryRunner by lazy { SummaryPlanner 依赖同双 Runner（settingsRepo/chatTextFn=AiClientChatTextFn/scope=appScope/gate=aiGate）}`；`AiClientChatTextFn` 置于 SummaryPlanner.kt（同 AiClientChatJsonFn 模式）。AppNav 新增 `SUMMARY/{chapterId}` → ChapterAssetsScreen；ReadScreen TopAppBar 加"总结"文字按钮（常驻，页内做前置提示）。

## §3 UI（ChapterAssetsScreen）

### 3.1 骨架
TopAppBar（章名+返回）→ 资产态按数据推导：无资产且非生成中 → 空态 CTA"让搭子总结本章"（粗读未完成→副文案"本章还没有粗读标注，先回阅读页完成粗读"且按钮禁用）；生成中 → 流式视图；有资产 → TabRow 五页签。ActionBar 式操作行：重新生成（force 弹确认，复用 M4a/M4b 模式）、导出 MD（有资产才显示）。

### 3.2 流式生成视图
collect `summaryRunner.state`：本章 Streaming → 显示 partial 文本（bodyMedium，auto-scroll 到底）+ "停止"按钮；另一任务占用（gate.label 非空且非本章）→ 提示文案。

### 3.3 总结/记忆/串联 tab
共享 `MdText`（ui/components/MdText.kt：行级解析 `#{1,3}` 标题 / `- `·`* ` 列表 / `**b**` 内联加粗（AnnotatedString）/ 空行分段；无标记行原样——纯函数可单测）。记忆 tab 顶部 TTS 播放钮（toggle，Speaking 时显示"朗读中 x/y 句"+停止）。

### 3.4 导图 tab
MindMapPanel（editable=false）加载 `TreeText.toMapData(TreeText.parse(mindmapTree), 章名)` 现转的 mapJson——**`remember(mindmapTree) { ... }` 缓存转换结果**（避免每次重组重解析，评审 P2-6）；toMapData 返回 `Pair<mapJson, virtualRoot>`，v1 恒以 mapJson 渲染（单根/多根的虚拟根包装已在 toMapData 内部完成，second 仅留作调试日志）。底部"导出 PNG"：`MapController.exportPng()` → onPngReady(base64) → 解码 → **SAF `CreateDocument("image/png")`** 写入（文件名"章名-导图.png"）。WebView 设置与模拟器软件渲染兜底按 tingsiwei 原样移植。

### 3.5 自测 tab
 QuizCodec 解码 quizJson 逐题卡：题型徽标（回想/判断/案例）+ 题干 → 展开输入作答（TextField）→ "对答案"（显示参考答案+解析）→ 自评三按钮 答对/模糊/答错 → 追加落库 `quiz_attempts(chapterId, qIndex, answer, verdict=CORRECT/PARTIAL/WRONG, feedback=explain)`（**同一版资产内追加历史、不改旧行；重生成资产时本章 attempts 已被清空（§2.4 步骤 5），从新题重新积累**）。底部"讲解自问"区：`byChapterOnce` 收集 notes 的 `decodeCheckQuestions`，展开翻面显示答案（不落库，消费 M4b 存储）。

### 3.6 导出 MD
`buildExportMd(book, chapter, asset, questions)` 纯函数拼接：标题行 + 生成日期 + 总结 md + 导图树（代码块包裹的 TAB 树，人可读可改）+ 记忆思路 + 串联 + 自测题（含答案解析）。SAF `CreateDocument("text/markdown")`。SAF 回调经 `rememberLauncherForActivityResult`。

## §4 Prompt（assets/prompts/summary_pack.txt）

system：统一朋友人设（§4.3 原文）+ 本次任务说明（读完全章后给朋友做章末五件套）。user 字段说明 + 五标签格式硬约束：
`<总结>`markdown ≤600 字，抓住骨架不逐段复述；`<导图>`TAB 缩进树 2 层为主、每节点 ≤15 字、根=章名；`<记忆思路>`200-500 字连贯叙述、讲故事式承接（不许分点罗列）；`<串联>`把并列/递进知识点编成一条线的故事（优先时间线/成长线/因果线，示例：无/限制/完全民事行为能力→从胎儿到成年的成长线）；`<自测>`3-5 题 JSON 数组 `[{"type":"RECALL|TRUE_FALSE|CASE","q","a","explain"}]`，考推演与辨析不考背诵，explain 1-2 句。只输出五标签内容，不加前后缀。
