## 1. 问题与目标

P3a 用「正则+字号证据」分章，实测遗留两类缺陷（真书 mfzz 630 页 E2E 实录）：

| 缺陷 | 实例 | 根因 |
| --- | --- | --- |
| 真章漏收 | 第九章全书缺席（基线即无，P3a 亦未解） | 第九章标题行排版/OCR 破损不匹配任何档位 |
| 标题黏连破损 | 「第二章：人 ｛」「第十章期日与期间一—权利义务变动的时点」 | OCR 把副标题、破折号、乱码并进标题行 |

书的**目录页**天然携带权威答案：全部章/节标题的**原文、页码、层级**。视觉模型读几张目录页图即可拿到，成本远低于逐页转写（老板：「一次性读的还少了，发给 LLM 的就少了」）。

**P3b-1 目标（本计划范围）**：把目录页变成结构化数据 `List<TocEntry>`，带缓存与全路径回退。**不改任何现有分章行为**——分章消费留给 P3b-2（页码校准与目录驱动切章，另行计划案评分）。

### 1.1 关键前置实测（2026-10-02，`.e2e/probe_toc_pages.py`，App 同口径 RE_TOC_LINE≥3）

## 3. 方案

### 3.1 数据结构与交接接口

**文件落位**：`TocEntry` 放既有 `PdfTypes.kt`（项目小数据类聚合文件，同包新增）；`TocJson` 独立新文件 `data/importer/TocJson.kt`（`object`，纯函数，**不做任何 I/O**）；`TocVisionParser` 独立新文件 `data/importer/TocVisionParser.kt`（**缓存读写封装在其内部**——构造器加 `cacheDir: File` 参数，parse 全权负责缓存的读/写/原子性，调用方无感）。

```kotlin
/** 目录条目（视觉识别产物）；page=条目标注页码（null=未见页码），level 1=章/篇/部 2=节。
 *  level 维持两级：章节树 UI（P3b-3）的层级由标题前缀（第X章/第X节）推导，
 *  TocEntry.level 只承担粗分职责，三级及以下条目按 PROMPT 统一记 2。 */
data class TocEntry(val title: String, val page: Int?, val level: Int)
```

**P3b-1→P3b-2 数据交接**：`ImportViewModel` 新增可空属性 `var tocResult: List<TocEntry>? = null; private set`（探针成功时赋值，写入口单一）。**消费契约**（属性注释注明）：①P3b-1 阶段**禁止除日志/诊断外任何消费**（无 UI 旁路、无埋点上报旁路）；②语义不变式——非 null 时保证条目数 ≥3、level=1 条目 ≥1、有页码条目非降序占比 ≥90%（即 TocJson 整体守卫不变式，P3b-2 可直接依赖，无需重复校验这三条）；③**模式偏离注明**：ImportViewModel 其余状态走 StateFlow，tocResult 探针期为裸 var（仅日志/诊断消费），P3b-2 引入正式消费时升级 StateFlow 或 sealed class。生命周期=ImportViewModel 实例存活期（一次导入会话内）；不落库不落盘——跨会话回退路径是缓存文件 `toc_v2_{uriHash}.json`（P3b-2 消费时可按 uriHash 直读缓存，绕过 VM 生命周期限制）。P3b-1 阶段该属性无消费方，属**有意的中间态**：探针先验证数据质量，P3b-2 同分支接力消费，不留死代码（revert 单 commit 即连属性一起消失）。**sealed class 升级检查项**：P3b-2 引入消费逻辑且出现多态结果需求时，评估升级为 `TocProbeResult` sealed class（探针阶段单一类型不值得）。

### 3.2 TocVisionParser（新文件 data/importer/TocVisionParser.kt）

- **命名说明**：`Parser`（结构化提取，产出语义条目）区别于 `VisionTranscriber`（忠实转写，产出原文文本），职责不同故不同后缀。
- 构造参数逐个列出（不用计数词）：`baseUrl` / `apiKey` / `model`（与 VisionTranscriber 同形）+ **`cacheDir: File`**（缓存根目录）+ **`enabled: Boolean = true`**（探针开关，false 时 parse 直接返 null——E2E 不达时可停探针不删代码）+ **`chatFn: suspend (ChatRequest) -> String = { req -> AiClient.chat(req) }`**（lambda 包装吸收 onDelta 默认参数——`::AiClient.chat` 为双参函数引用、类型不匹配；测试注入假实现断言零调用，项目无 mockk/mockito，注入是无 mock 设施下的标准做法）+ **`renderFn: (Int) -> String`**（页号→Base64，调用方绑定既有 PdfPageRenderer 实例 `{ idx -> renderer.renderPageBase64(idx) }`，与 VisionTranscriber 同一渲染方法、同 140dpi、ImportViewModel:285 实测在用）+ **`clock: () -> Long = System::currentTimeMillis`**（时间源注入，单测 20/21 用假时钟精确控制守卫边界，与 chatFn/renderFn 同一注入风格）。
- `suspend fun parse(pageNumbers: List<Int>, uriHash: String): List<TocEntry>?`
  - **入参为页号列表+uriHash**（调用方传 `tocLike` 物理页号与文件 uriHash）：渲染经 renderFn 注入、**逐页「渲染→调用→释放」的编排在 parse 内部**——不预加载全部页，内存峰值 ≤1 页图（~1MB Base64 字符串）；uriHash 供缓存文件名与失败标记使用（`VisionCache.uriHash(uri)`，实施时从 `VisionCache.file()` 内联实现抽出公开，禁止复制实现）。
  - 缓存读写封装在 parse 内部（cacheDir 由构造器传入），调用方无感。
  - **单页识别**逐页调用（每页一次 chat），结果按页拼接。**逐页前置检查**：处理每页（渲染与调用）前检查 `elapsed + readTimeout ≤ tocTotalTimeoutMs`，不满足 → 放弃剩余页并**整体返 null**（丢弃已成功页——半份目录不采纳）。**失败语义分型**：网络错误/超时 → 重试 1 次，且重试前同样检查 `elapsed + readTimeout ≤ tocTotalTimeoutMs`，不满足则跳过重试直接整体返 null；JSON 解析失败 → **不重试**（同输入温度 0.1 大概率同错），直接整体返 null；**页面渲染失败 → 整体返 null**（与模型调用失败同等对待，不跳过失败页——跳过会产出少一页的半份目录）。任一环节最终失败=整目录放弃，不部分采纳（半份目录比没有更危险）。
  - **线程模型**：parse 内部 `withContext(Dispatchers.IO)` 包裹网络调用，调用点在 ImportViewModel 导入协程（与 applyVision 同一执行环境），不阻塞主线程。
  - **总耗时守卫**：`tocTotalTimeoutMs = 300_000`（网络）、单页 `readTimeoutMs = 60_000`。**容量算术**：(300−12 渲染)/60 = 4.8 → **4 页整**，与实测真书目录跨度（4 页）一致；措辞统一：**网络守卫 ≤300s，含渲染总耗时 ≤312s**（探针一次性成本；导入 630 页本就 5-6 分钟，+5 分钟可接受，缓存命中后重导零调用）。**首次调用与重试统一前置检查** `elapsed + readTimeout ≤ tocTotalTimeoutMs`，不满足则放弃剩余页整体返 null。**elapsed 起算点**：首次页面渲染前（渲染纳入预算）。60s 单页依据：整页转写实测 60-70s/页但输出 ~4000 token，目录页输出仅 ~2500 token，应显著更快；E2E 记录实际每页耗时分布验证此假设。**可调性**：探针阶段二者为构造常量；P3b-2 正式消费时迁入 Settings 可调参数，与总体计划案「阈值可调」全局决策对齐。
  - **不经 VisionScheduler**：探针 ≤4 次轻量调用，VisionScheduler 为逐页转写的大批量队列（重试/去重/并发控制）设计，接入它的复杂度对 4 次调用不划算；**类注释注明迁移触发条件：单书调用量 >10 次、或总目录页数 >4 页且处理耗时 >3 页预算时重新评估接入**（P3b-2 扩入口时先查此线）。
- PROMPT（钉死格式，沿用转写 PROMPT 的实测风格）：
  ```
  这是书的目录页照片。把目录条目提取为 JSON：
  {"entries":[{"title":"条目标题原文","page":123,"level":1}]}
  要求：只输出 JSON，不要解释或代码围栏；title 忠实原文不改写不翻译；
  page=条目点线后标注的页码整数，看不到页码用 null；
  level：章/篇/部/编/卷/回等大标题=1，节/小节=2，三级及以下条目（如（一）、1.）也记 2；
  双栏目录按先左栏后右栏、栏内从上到下顺序输出；忽略页眉、页脚、本页页码。
  ```
- 参数：temperature 0.1、maxTokens 8000、readTimeoutMs 60s、网络总守卫 300s（见上）。**重试策略独立性**：TocVisionParser 的重试（仅网络错/超时、1 次）独立于 VisionTranscriber 的重试实现——类注释注明「若 VisionTranscriber 重试策略变更（如加指数退避），此处需手动评估同步」（4 次调用场景不值得抽共享接口）。

### 3.3 解析与校验（纯函数，可单测）

`TocJson.parse(raw: String): List<TocEntry>?` 容错规则（**文件顶部注释记录缓存格式版本历史**：`// v2: 2026-10-02 initial prompt/rules`，规则变更时追加行并同步缓存文件名 vN）：

1. 剥代码围栏（```json … ``` / ``` … ```）后再取首 `{` 至末 `}`。模型输出被 maxTokens 截断时 JSON 不完整，走规则 2「非法 JSON→null」——归为解析失败不重试，天然兜底，不另加截断机制。
2. `entries` 非数组 / 缺字段 / **空数组** → null。
3. 单条目容错：title 非空白字符串、page 为正整数或 null、level ∈ {1,2}（其他值丢弃该条目，不整体失败）。
4. title trim 后 ≤40 字（与 BookParser 标题长度约束同口径），超长截断丢弃该条目。
5. **整体守卫**（全部通过才返回非 null）：
   - 条目数 ≥3（目录至少几条；<3 视为误判页面）
   - 有 page 值的条目中，按出现顺序非降序占比 ≥90%（v7.0 由 80% 收紧：20% 逆序属系统性错误不应放过；OCR 个别误读仍可容忍。**E2E 记录真书实际乱序占比**，若 OCR 误读致真书误拦（占比 >10%），P3b-2 用实测数据回调）
   - level=1 条目 ≥1（没有章级条目的不是目录）
6. **虚构条目的边界**：纯函数只能拦结构性异常（乱序/缺 level=1/条目过少），无法语义判「内容是编造的」——语义正确性留给 P3b-2 的页码偏移校准（offset 一致率 <60% 即弃用），P3b-1 探针阶段以人工核对样例（§4）补位。

### 3.4 触发与回退（P3b-1 只挂探针，不改行为）

- `ImportViewModel` 导入流程中，PDF 分支提取完成后：**`settings.buildVisionTranscriber() != null`（与逐页转写同一开关判定，实测代码 159 行）** → 挑 `tocLike` 页（**tocLike 判定位于 `PdfCleaner.kt:219`：`RE_TOC_LINE` 命中 ≥ `TOC_MIN_HITS`，P3b-1 只读不改**；≤前 200 页内，**按页号升序取前 4 个 tocLike 页**（v12.0 定死语义：无论连续与否；真书 28-31 连续不受影响））渲染并调 `TocVisionParser`；结果（或 null）存 `tocResult` 属性 + logcat，不参与分章。**探针阶段不上报导入进度**（用户不可见；耗时上限由总超时守卫保证），P3b-2 正式消费时再接入 phase 文案。
- 断网/无 key/解析失败/**页面渲染失败**/无 tocLike 页 → 静默 null（`Log.w("P3b", ...)` 记原因，渲染异常与模型异常分开记，便于 P3b-2 排查入口质量），导入行为与 P3a 现状逐字节一致。**时序**：探针与 applyVision（同步视觉转写）**串行执行——applyVision 完成后触发，不并发**；AiClient.chat 为无共享可变态的纯请求调用，串行下无并发安全问题。**诊断日志（结构化）**：成功时记 `P3b toc entries=NN (level1=X, level2=Y, pageRange=A-B)`——一个 logcat 行携带全部质量信号；条目 <10 额外 `Log.w("P3b toc quality warning: N entries, below minimum 10")`；若选中了 tocLike 页但解析结果为 null，`Log.w("P3b", "TOC pages may be misidentified: N pages selected, parse failed")`——为 P3b-2 提供入口质量诊断信号。
- **tocLike 入口缺陷耦合声明**：tocLike 页来自文本管线（P1/P2 产物），实测 11 本中 7 本选不出目录页（§1.1）——探针在这些书上零调用零产出（回退路径，无副作用）；但**已选中页也可能误判**（P3a 实录：页 31 目录尾页曾漏判）。两层风险都由「失败返 null 全路径回退」兜住，P3b-2 再修入口。
- **缓存**：识别成功结果存 **`vision_cache/toc/`** 独立子目录（评审建议：与逐页转写缓存物理隔离，规避其潜在清理机制误删）、文件名 `toc_v2_{uriHash}.json`（复用 VisionCache 的 uriHash 算法；`v2`=格式版本号，Prompt/解析规则/模型变更时递增，旧版本文件视为 miss 重建）。**归属与实现**：直接 File I/O 读写该文件，不经 VisionCache 的逐页转写 API（那是页级转写缓存接口，格式与生命周期都不同），`toc/` 子目录由 P3b-1/P3b-2 独立管理。**原子写**（评审 P0）：写入用 `writeTo(tempFile) + renameTo(finalFile)`，杜绝并发/中断读到半截 JSON；读时 catch IOException 一律视为 miss 重建。**并发边界**：探针期 ImportViewModel 单线程调用无并发；P3b-2 引入并发消费时须重新评估文件锁或迁 SQLite KV（P3b-2 计划案检查项）。**清理策略**：探针阶段不做清理——每书一个 ≤64KB 的 JSON，增长极慢，立即上 LRU 属过度设计；P3b-2 正式消费时按书库规模评估 LRU（与 VisionCache 清理机制独立）。**损坏恢复**：读时发现文件损坏/空 → 视为 miss 重新识别；写失败至多重试 1 次，仍失败则 `Log.w` 放弃写缓存——**不把已成功的解析结果作废**（缓存只是优化，作废有效数据反而浪费已烧的图），导入照常推进。**失败熔断**（v10.0）：解析失败时写 `toc_fail_v2_{uriHash}.marker`（内容=ISO 时间戳，文件名含缓存版本号），**30 天 TTL 内同书重导直接跳过探针**（防坏目录页每导必烧 4 次调用×60s）；探针成功后删除 marker；marker 版本与当前缓存版本不符 → 视为过期正常重试。缓存命中时跳过全部网络调用，总超时守卫不计时（命中分支提前返回）。**全有全无**：整体成功才写缓存，单页成功不单独缓存（探针阶段重导重烧的成本 ≤4 张图，换实现简单不维护分片状态）。

## 5. 风险与红线

1. **不丢字红线**：P3b-1 不触碰文本流（只读 tocLike 页图像），零风险。
2. 视觉输出不稳定 → 钉死格式 + 重试 1 次 + 整体守卫 + 失败返 null 全路径回退。
3. **耗时风险（评审建议 2）**：单页 readTimeout 60s、网络总守卫 300s 硬上限（首次调用与重试统一前置检查，容量算术 (300−12)/60≈4.8 → 4 页）；探针在导入协程 IO 路径执行不阻塞主线程；探针一次性附加 ≤312s（含渲染），缓存命中后重导零调用。
4. 视觉调用成本：目录页 ≤4 张图；断网/关开关零调用；缓存防重烧（全有全无）+ 失败熔断 marker 防坏书反复烧。
5. 凭据纪律：key 只经现有 Settings 管道传入构造器，不落日志。
6. 半份目录不采纳（单页失败整体放弃）：避免「只有半数章的目录」造成 P3b-2 半对半切。
7. **入口覆盖率局限（实测 4/11）**：探针入口依赖 tocLike，7 本书零产出——P3b-1 不修（不改行为红线），如实记录；P3b-2 扩入口后重测覆盖率。**入口耦合监控**：P1/P2 文本管线改版可能导致 tocLike 判定变化、探针静默失效——P3b-2 计划案检查项：改版后验证 tocLike 入口仍可用。
8. **解析成功但质量低**（评审建议补充）：守卫只拦结构性异常，「条目少而正确」「条目对但大量缺失」拦不住——P3b-1 靠 §4 人工抽检补位；P3b-2 的 offset 校准须增加**条目数下限检查（<10 条视为质量不足弃用）**，写案时落实。
9. **模型幻觉**（评审补充，显式条目）：视觉模型可能返回**结构合法但语义伪造**的条目（虚构标题/随机页码），守卫无法拦截——P3b-1 靠 §4 三门人工抽检补位，P3b-2 offset 校准（一致率 <60% 即弃用）为最终防线。
10. **缓存孤儿文件**（评审补充）：`toc/` 子目录独立管理，探针阶段不清理（每书 ≤64KB，增长极慢）；**P3b-2 计划案评分检查项：清理机制是否纳入范围**（100 本 ≈ 6.4MB 时必须处理）。
11. **重试策略技术债显性化**（v8.0）：TocVisionParser 重试独立于 VisionTranscriber 实现（6 次调用不值抽共享接口，理由见 §3.2）——**VisionTranscriber 重试策略变更（加指数退避/改重试条件）时，TocVisionParser 需手动评估同步**（类注释 + 本条双处索引；CI 一致性断言属过度工程，探针期以注释+评审把关）。
12. **构造路径分叉**（v10.0）：TocVisionParser 探针期由调用方直接构造（区别于 VisionTranscriber 的 Settings 工厂路径）——**P3b-2 正式消费时迁移至 Settings 工厂方法（与 VisionTranscriber 同路径）**，避免 API key 传递路径分叉（P3b-2 计划案检查项）。

## 6. 回滚
