### v1.0（初稿）

## 1. 本案在体系中的位置

P6 决策案三段路线：P6a（Go，2026-02-10）→ **P6b（本案）** → P6c（PP-DocLayout，与 P4 扫描件场景合并立项）。本案回答一个问题：**扫描件 PDF 能否经本地 OCR 进入既有清洗/切章管线并出书**。全部判据过 → 扫描书导入闭环；任一不过 → 诚实记档，回退扫描书现状（导入拒绝），数字路径零损失。

**范围边界（决策案约束逐条固化）**：
1. 服务范围=**横排单栏扫描书**（P6a 判据② N/A 口径限定；竖排书排除——导入时检测到竖排页占比超阈值整书走现状路径，见 §4-S4）；
2. 双栏扫描书**不进 OCR 路径**（P6c DocLayout 就绪前；复用 PdfLoader 既有 detectDoubleColumn 提示文案，维持现状拒绝/视觉路径）；
3. **数字 PDF/TXT 路径行为零变化**——TextSource 抽象只改入口类型不改变任何行为，589 单测全绿为硬门禁（判据①）；
4. PP-DocLayout/双栏排序/图表区域检测不在本案（P6c）；
5. **模型不打进 APK**（决策案风险 3 原文）：assets/ocr 从 APK 移除，首次导入扫描书时按需下载（§4-S5）；OcrPocActivity 与 assets 下架（git 历史保留）；
6. **引注隐去仅 OCR 路径**（老板需求来源为扫描书转写稿；数字路径不动保证零回归——数字书引注隐去记档为潜在后续需求）。

### S1：TextSourceRow 抽象与数字路径接入（判据① 主战场）

- 新增 `TextSourceRow`（决策案 §2 决策 3 草图八字段：text/x/y/w/h/fontSize/fontFamily/confidence/sourceVersion；字段语义/坐标系注释照抄决策案并按 F2 修正：fontFamily=「现管线无此信号，数字与 OCR 路径恒 null，保留字段为 P6c 预留」）。
- **adapter 职责边界（决策案原文）**：只做单位换算/字段映射/置信度透传，不做任何清洗决策。数字路径 adapter：PLine→TextSourceRow→还原 PLine（恒等映射，sourceVersion=0 表示数字确定性路径）；OCR 路径 adapter：OCR 行→TextSourceRow→SpanInfo（每行单 span，size=行高×(72/140)）→P1 原样进入（单 span 行 normalize 为近恒等，管线统一不绕行）。坐标口径：PLine 显示坐标 y 自顶向下，OCR 像素坐标同向——**无需 y 翻转**（决策案「pdfbox 左下原点 y 翻转」已由 LineCollector 承担，OCR 侧直接 ×(72/140)），计划案显式记档防过度设计。
- sourceVersion 定值（决策案「P6b adapter 上线时重新定值」）：数字路径=0、OCR 路径=1（PROD_OCR_V1：det/rec 模型哈希+宽度映射规则+引注规则+72/140 系数的组合标识）；行级属性，混合书各行可异；管线变更递增并全量重导。**重导触发机制（v1.5 P2-4）**：SettingsRepository 存 `lastOcrVersion`（该书最近一次成功 OCR 导入时的 sourceVersion），导入完成后更新；再次导入同一扫描书时比对当前 sourceVersion 与 lastOcrVersion，不匹配 → parseNote/对话框提示「扫描书识别规则已更新，建议重新导入」→ 用户确认后 OcrImportRunner 按当前版本重跑该书（重跑粒度=整书，实现简单且避免混合版本章节；增量重跑留 P6c 评估）。
- **OCR 路径标题字号阈值参数化（v1.1 P0-1，决策案 P6a 判据⑤触发条款落地）**：P6a 实测 std=3.06pt>0.5pt，决策案要求「P6b 把 P3a 阈值放宽至 ≥1.5/2pt 并记档」——落地为：标题字号判据对 OCR 路径改为「字号 ≥ bodySize+1.5pt 与 ≥1.15×bodySize 取**更宽者**」（放宽方向），数字路径阈值零改动；参数随 TextSourceRow.sourceVersion 分支选择（不是全局开关，杜绝误伤数字路径）。两档放宽与「仍不行退回」处置见 §6③b。
- fontFamily 字段纪律（v1.1 P2-5）：保留（决策案草图八字段原文），KDoc 注明「全路径恒 null——数字路径本无字体名信号（F2），P6c DocLayout 引入时评估启用」；实现不写任何非 null 值、不建死逻辑分支。
- 验收：589 单测全绿（判据①）+ 新增 adapter 恒等性单测 + **单/多 span 行为锁定单测组（v1.2 顺手修+v1.3 P2-8 扩充）**：①单 span 行过 `RowNormalizer.normalize` 输出**全字段逐一断言**（text/x0/x1/y0/size 与输入一致，含坐标 -1 分支）；②多 span 行恒等性单测（构造 3-5 span 行 → PLine → TextSourceRow → SpanInfo → normalize → PLine，全字段与原始 PLine 一致）；③该组单测 KDoc 标注「同时锁定 RowNormalizer 单/多 span 分支行为，normalize 逻辑变更时须同步更新」——「近恒等」假设以显式测试固化而非口头约定。

### S2：OcrEngine 生产化

- 从 OcrPocActivity 抽取推理核心为 `OcrEngine`（无 Android UI 依赖，可 JVM 侧接口化）：`open(modelsDir)` / `recognize(bitmap): List<OcrLine>` / `close()`；det/rec 双 session 生命周期=一次导入会话持有、结束 close（onnxruntime arena ~208MB 释放，F9）。
- 线程纪律：导入协程内**串行并发=1**（决策案 §3.1 CPU 密集不宜并发）；主进程运行（PoC 坑记档：独立进程 StudyApp 崩，模块总览）。
- 页级置信度=行置信度均值；**零行页（v1.1 P2-3）**：OCR 返回 0 行 → 页置信度记 0（空集不进均值计算）→ 直接归兜底。
- **缺行率口径（v1.1 P1-3，统一为决策案原文）**：缺行率 = max(0, 全书中位正文行数 − 该页正文行数) / 全书中位正文行数；**缺行率 >20% → 该页兜底**（决策案 §3.1 权威口径）；v1.0 的「行数 <0.4×中位」表述废弃（与 20% 口径不等价，评审实证反例）。

### S3：OcrTextPostProcessor（纯 JVM object，四条规则全部来自 P6a 已验证口径）

| 规则 | 内容 | 来源与验收 |
| --- | --- | --- |
| a. 标点宽度归一 | 全角 `，：；（）` → 半角（中文语境）；句号/引号/书名号/顿号保持；西文语境不动 | gt_fix2.py 验证口径；**验收=6 页 literal CER ≤5%**（§6 内部判据 W） |
| b. 引注隐去 | R-CIP 豁免（行含罗马数字+.+圈码=CIP 数据行）；R-FN 行首圈码+空格；R-IN 其余圈码；R-BR `[1]`/`【1】`/1-3 位方括号数字。正文序号保护：`1.` `一、` `（一）` 等形态一律不碰（P2 RE_STRONG_NEW_SEG 依赖的序号形态全保留） | strip_citations.py 已验证（8 页 23 处 0 误伤）；**验收=Kotlin 与 Python 输出 8 页 0 diff**（§6 内部判据 Y） |

| d. 碎片行中间层 | 行高 < 页主字号×0.5 的碎片行与相邻行合并（y 间距 ≤0.5×字号）；页失败率 >10% 整页转视觉兜底不进 P2（决策案 §2 决策 3 原文） | **验收=判据③c 合并成功率 ≥90%**（E2E 日志统计） |

### S4：导入集成

- `ImportViewModel` scanned 分支改造：`scanned && ocrEnabled && 单栏` → `OcrImportRunner`，**两遍法时序（v1.1 P2-4 定死）**：Pass1 逐页（PdfPageRenderer 140dpi 渲染 → OcrEngine → S3 行内后处理 a/b——仅依赖单行文本，无需统计量）→ Pass2 全本行收齐后 `PdfCleaner.docStats` 预计算主字号 → 逐页执行 S3 规则 c（diagram）/d（碎片行合并，依赖主字号）+ 低置信/缺行分流 → PLine → `PdfCleaner.clean`（F5 复用）→ PageOut → 既有 applyVision/BookParser 汇合。进度 phase=「本地文字识别 第 N/M 页（约剩 M 分钟）」（中位耗时×剩余页数估）。
- 页级分流（决策案 §3.1 调度时序逐条）：页置信度 ≥阈值(85%，F9 数据下 shpc 几乎不触发，记档) 且缺行率 ≤20% 且非 diagram 且碎片行达标 → 进管线；否则该页入 `pendingVisionItems` 后台队列（复用 429 退避/续跑，**不占 400 护栏**——护栏豁免=OCR 直通页不计入队列计数，仅兜底页计数）；兜底页 OCR 草稿不入库（决策案原文），视觉完成后整页替换。
- **双失败兜底**（决策案 §3.1）：兜底页视觉也失败 → 该页文本留空不阻塞、parseNote 提示「第 N 页未能识别，可重导或对照原书」、记档供单页重试。
- 竖排书排除（v1.2 P2-6 对齐 P6a 方法论；v1.3 P2-6 两段式控成本）：**初筛**=系统性抽样 10 页（每 46 页 1 页）跑 direction_scan 同款投影特征扫描（ratio≥0.381 SUSPECT 带），渲染+扫描成本 <2s（手机口径 S7 复核）——命中 ≤1 页 → 判横排直接放行；**确认**=命中 ≥2 页 → 全本扫描，SUSPECT+VERTICAL 页占比 ≥20% → AI 目视抽 3 页确认 → 整书走现状拒绝路径并提示「竖排扫描书暂不支持」。体系图页偶发 SUSPECT 由 diagram 分类器消化不触发整书拒绝（P6a 实证 51 SUSPECT 页复核全为结构性误报、VERTICAL 0 页，20% 占比阈值对「真竖排书=近乎全页命中」有充分间隔）。
- 开关：SettingsRepository 新增 `ocrEnabled`（默认 true，M3 设置页入口「扫描书本地识别（OCR）」）；off → scanned 书走现状（allowScanned=false 拒绝文案不变）=**回滚方案载体**（既有路径原样保留，OCR 产出缓存不删）。
- **并发防护（v1.2 P1-2）**：OcrImportRunner 伴生对象 Mutex 互斥——OCR 导入进行中触发第二次扫描书导入直接提示「正在本地识别中，请稍后再试」，不排队（避免双引擎 ~416MB PSS 叠加 OOM）；数字书导入不受限（无引擎占用）。
- **异常 close 保证（v1.2 P2-3）**：整轮 OCR 导入 try-finally 包裹，finally 必调 `OcrEngine.close()`（异常/用户取消路径均释放 ~208MB arena）。
- 漂移监控最小实现（决策案「置信度-准确率相关性漂移检测」落地步）：导入完成统计页均置信度分布/低置信率，**两级告警（v1.4 P2-1）**：页均置信度 median <0.90 → 预警（parseNote 轻提示，早期信号）；<0.85 → 硬告警（parseNote 提示「建议在设置中关闭 OCR」）=回滚评估入口（不自动关）。**生产侧轻量准确率代理检查（v1.2 P1-1）**：导入完成后校验「页均字数偏差」（|该页字数−全书中位页字数|/中位 >60% 的页占比 >10%）+ 章节标题锚点匹配率（正文「第X章」锚数 vs 检出章节数），任一异常 → 同条 parseNote 提示——准确率侧以结构代理指标覆盖（无需人工标注），与置信度分布告警、判据③章节差共同构成生产守门。**简化理由记档（v1.1 P2-6）**：P6a §3 映射表实证本书质量下高置信≠低 CER（标点宽度归一错误置信度照样 0.9+）——纯置信度阈值不可作质检主手段（P6a 交接 #4），故置信度只承担分布侧告警，准确率侧由上述代理指标（生产）+debug 抽样对照工具（开发阶段）覆盖。
- **用户反馈通道（v1.3 P1-1，决策案「用户反馈文本错误率 >5%」回滚触发落地）**：parseNote 处提供「识别结果有误？」反馈入口（计数存 SettingsRepository，按书记录）；累计 ≥3 次 → 下次导入完成提示升级「多次反馈识别问题，建议在设置中关闭 OCR」=回滚评估触发。用户不量化错误率，计数入口即决策案「用户反馈」条款的生产形态。
- **离线校验队列（v1.3 P1-2，决策案「定期抽样校验」生产形态；v1.4 P1-2 消费者绑定）**：导入完成以固定种子抽 1-2 页 OCR 快照（页码+文本+行置信度）落盘 `filesDir/ocr_verify/`（滚动保留最近 2 本书）；**消费者=后续维护版本（P6c 或 v1.5）开发阶段**——开发者手动拉取快照与当前版本 OCR 输出做 diff，偏差 >2% → 触发漂移基线更新与规则复核；**不自动上传**（隐私+流量成本记档）——生产实时侧分工=置信度两级告警+字数偏差代理指标+用户反馈计数（见上两条），抽样校验=离线队列+debug 工具承担，决策案双手段全部有着落。**空窗期填补（v1.5 P2-2）——上线首月维护计划**：P6b 上线至 P6c/v1.5 自动化消费者就绪期间，开发者每 2 周从测试设备手动拉取 `ocr_verify/` 快照与当前版本 OCR 输出 diff 一次，偏差 >2% → 记档并触发漂移评估；该人工检查在自动化消费者上线后停止（过渡契约，避免「有队列无消费者」空窗）。

## 8. 风险与对策

1. **模型下载不可达**（手机网络 GitHub 不稳）：失败明确报错可重试，不假降级；记档 M7 同源约束（自更新同样依赖 GitHub 可达）。
2. **diagram 分类器过拟合 8 页样本**：双特征阈值只求 shpc 型体系图页召回，误伤正文页的代价更高——验收含 6 正文页 0 误伤+独立验证 5 页（D 判据）。**全本 E2E 偏离处置步骤（v1.3）**：命中数显著偏离 6 页预期（<3 或 >15）→ 人工复核命中清单；复核发现误伤正文页 → 收紧阈值并重跑 D 判据（标定+独立验证）；发现漏检 diagram 页（对照 P6a 方向扫描 SUSPECT 清单）→ 放宽阈值重跑 D；两轮修正后仍不稳 → 回退单特征版（仅树线字符频次）并记档，最坏处置=关闭规则 c（diagram 页走低置信兜底路径，功能不缺失仅兜底成本+2-6 页视觉调用）。
3. **视觉兜底 E2E 撞配额/限流**：复用 VisionScheduler 429 退避；兜底页预估 6-20 页，若超 50 页判据④即 No-Go——如实记档不重试凑数。
4. **OCR 内存与导入并发**：+208MB PSS、largeHeap 已设（F9）；引擎 close 释放；导入期间禁用并发 OCR（串行）；低配设备（<4GB 或 <4 核，F9 实测口径）跳过 OCR 走现状提示（决策案风险 3 门槛条款，门槛=P6a 实测修订值记档：4GB/4 核实测可行）。
5. **判据③ 探针在扫描书失效**（目录页渲染质量/版式）：探针失败记档走兜底口径（§6③），不跳过判据。
6. **引注规则长尾误伤**（8 页外的新形态）：E2E 全本抽查含圈码行 20 行人工（AI 目视）复核，误伤 >2 处 → 规则收紧记档；「正文序号保护」形态清单在 S3 单测固化。
7. **时间盒超时**：按已完成项判据定夺，No-Go 记档，不延长不放宽（各步失败阈值见 §4 预算表）。
