# M6 计划案：全书总览与复习中心

> 版本 v1（对应总计划 M6：跨章总览、总导图、间隔复习推进、错题本；验证=复习间隔推进单测、总览生成冒烟、M4/M5 回归）

## 1. 目标与非目标

**目标**
1. 复习中心（底部 Tab 空壳重建）：今日待复习列表 → 逐章复习评估 → 间隔推进落库；错题本 Tab。
2. 全书总览：书详情页（ChapterListScreen）有 ≥2 个总结资产后出现入口 → AI 单调用生成三段（跨章总览/书级导图/总记忆主线）→ `BookEntity.overviewJson` 落库 → BookOverviewScreen 渲染 + 重新生成。
3. 书架徽标：书卡片显示今日待复习章数（N>0 才显示）。

**非目标**
- 复习评估不新出 AI 题：复用 M5 总结包自测题（quizJson）；AI 动态出复习题进 backlog。
- 复习评估不写 quiz_attempts（M5 语义=章末自测作答历史，不混淆）；只推进 review_items。
- 总导图不合并章级导图（书级树由 AI 独立生成）；导图仍只读。
- 无通知/推送提醒。

## 2. 数据与算法设计

### 2.1 间隔推进（纯函数，计划核心可测点）

```kotlin
// ReviewModels.kt
val INTERVAL_DAYS = listOf(1, 3, 7, 14, 30)      // intervalIdx 0..4
const val DAY_MS = 24 * 60 * 60 * 1000L

enum class ReviewVerdict { REMEMBER, FUZZY, FORGOT }   // 记得/模糊/忘了

data class ReviewAdvance(val intervalIdx: Int, val dueAt: Long, val done: Boolean)

fun advanceReview(intervalIdx: Int, verdict: ReviewVerdict, nowMs: Long): ReviewAdvance {
    val idx = intervalIdx.coerceIn(0, INTERVAL_DAYS.lastIndex)
    return when (verdict) {
        REMEMBER -> if (idx >= INTERVAL_DAYS.lastIndex) ReviewAdvance(idx, nowMs + INTERVAL_DAYS.last() * DAY_MS, true)
                    else ReviewAdvance(idx + 1, nowMs + INTERVAL_DAYS[idx + 1] * DAY_MS, false)
        FUZZY    -> ReviewAdvance(idx, nowMs + INTERVAL_DAYS[idx] * DAY_MS, false)
        FORGOT   -> ReviewAdvance(0, nowMs + INTERVAL_DAYS[0] * DAY_MS, false)
    }
}
```
（入口先 coerce：越界档位（如历史脏数据 idx=5）返回值不持久化越界，边界用例同时断言返回 idx。）
落库走现有 `ReviewItemDao.markResult(id, intervalIdx, dueAt, done)`（M1 预留，无 schema 变更）。

### 2.2 复习评估流（章级聚合一次推进）

- 进入一章复习：读该章 `ChapterAssetEntity.quizJson`（M5 资产）。
  - 有题：逐题渲染题干 → 用户点"看答案"（参考答案+解析）→ 自评 记得/模糊/忘了 三按钮（题级记录）。
  - 无题/无资产：退化为单问"这一章的内容还记得多少？"三按钮。
- 章级聚合：全 REMEMBER→REMEMBER；任一 FORGOT→FORGOT；其余→FUZZY。单按钮场景即该值。
- 完成后 `markResult` 推进一次，回到列表（行从到期列表消失）。
- 复习页按进页快照渲染（复习中资产被重生成/清空不中途换题）；自评结果不落 attempts（见非目标）。

### 2.3 错题本（M5 契约落地）

- **去重契约两步走（修正评审 P0）**：SQL 层**不做** verdict 过滤（否则"先错后对"的 CORRECT 行被提前滤掉，永远出不了列）；调用方先按 `(chapterId, qIndex)` 分组取 `createdAt` 最新一条，**再**过滤 `verdict == 'WRONG'`——同一题"先错后对"自动出列，"两次都错"取最新。
- M1 预留的 `QuizAttemptDao.wrongByBook`（SQL 带 verdict='WRONG' 且无书名 JOIN）与 `BookRepository.wrongAttempts` 包装**删除**，`DaoTest` 对应用例同步改为测 `wrongAll`（评审 P1-3：wrongByBook 并非零调用方，WrongAttempt 加非空 bookTitle 会让旧 SQL Room 编译失败，必须同步清理）。
- `WrongAttempt` 投影加 `bookTitle: String` 字段（加书名 JOIN，UI 分组展示用）。
- UI 按书分组折叠；行=章名+题干，点开展开 你的答案/参考答案/解析（题干从该章 `ChapterAssetEntity.quizJson` 按 qIndex 现查，资产缺失显示"总结包已更新，题目内容不可用"占位）。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 章多预算超限 | 每章摘要截断 600/300 字、>20 章取前 20 标注 truncated、总预算 20_000 硬顶（M5 预算模式复用） |
| 复习评估中资产被重生成 | 评估页进页快照渲染；评估不写 attempts；落库仅 markResult（id 维度，与资产无关） |
| dueList 同章多条 | distinctBy (bookId, chapterId)（M5 契约防御） |
| wrongByBook 删除影响现存调用方 | 评审 P1-3 实测 BookRepository.wrongAttempts 与 DaoTest 用例引用——计划内一并删除/改写（wrongAttempts 无 UI 调用方），全量回归锁定 |
| 到期列表/徽标跨天不自动刷新 | Flow 的 now 订阅时固化：复习页与书架每次进入重新收集拿新 now（Room 失效通知保证同订阅内 markResult 后即时刷新）；跨天停留不翻转可接受，M7 打磨时评估改成每分钟 tick 重算 now |
| Robolectric 视口挤出（M4a/M5 两次踩坑） | 新 UI 冒烟断言前先等首项渲染再滚动；断言目标尽量放列表头部 |
| AiGate 占用与多 Runner 并发 | OverviewRunner 复用同把锁与 join 纪律（M4b/M5 已验证模式） |

## 10. 与总计划的偏差登记（QA 核对口径）

1. **复习评估实现为自评三态而非 AI 出题**（评审 P1-4）：总计划 §4.3-5 写"复习评估（JSON）：对今日到期要点出快速回想检查"。M6 实现改为**复用 M5 章末自测题逐题回想 + 记得/模糊/忘了自评**，无题章退化单问三按钮；AI 动态出复习题进 §9 backlog。偏差理由：判定三态→1/3/7/14/30 推进的总目标完全达成；复用已有自测题零额外 AI 成本且与 M5 数据语义一致；"JSON"字样本就与自测题的 quizJson 存储吻合。总计划 §4.3-5 已同步加括注（见本计划同批修订）。
2. **总览入口门控收紧为"≥2 个已总结章"**（评审 P2-5）：总计划 §4.1 写"读 ≥2 章"；本实现要求 ≥2 个 promptVersion 匹配的总结资产——总览输入只有总结包，无资产的章进不了输入，按"读过"门控会生成空洞总览。
