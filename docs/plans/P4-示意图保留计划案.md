## 1. 现状（S）

- **S1 管线只认文本**：`PdfLineExtractor` 按 pdfbox 坐标把文本 span 成行，图片对象（`PDImageXObject`）完全不读——`PdfTypes.kt` 的 PLine/Para/PageOut 全是文本结构，图片在提取阶段即丢失。
- **S2 视觉转写只管文字**：OPT-E/F 的视觉兜底是「扫描页文字重建」（140dpi 渲染→视觉 LLM→整页替换段落），不产出图片资产。
- **S3 阅读页纯文本流**：`ReadScreen` LazyColumn 渲染 `ParagraphEntity`（role=BODY/FRONT/TOC/FOOTNOTE/BACK），无任何图片行；项目未引 Coil/Glide。
- **S4 DB 现状 v4**：books/chapters/paragraphs/para_notes/quiz_attempts/chapter_assets/vision_queue/review_items 八表；paragraphs 已有 `pageNo`（P3b-2 加，段落页码——图定位的现成锚点）。
- **S5 书生命周期**：删书走 `BookRepository.removeBook`→Room CASCADE 删行；无文件系统清理点。**OPT-F 整书重建链路**：vision_queue 消化完 → `VisionRebuilder` → `BookRepository.replaceBookContent`（事务内 `chapterDao.deleteByBook` 删旧章重插）——这是 figures 生存必须覆盖的路径（见 §3-D）。
- **S6 既有表分工**：`chapter_assets` 是 **AI 生成的章级资产**（summaryMd/promptVersion，M5/M6 产物）；`figures` 是**导入时提取的原生 PDF 图片资产**——两者语义正交，独立成表，不共享列。

**内联图实测（P1-3）**：三本书全 xref 流对象扫描（`(?:^|[\s\[])BI[\s\[]` 词边界正则，覆盖 Form XObject 内部）——mfzz 3229 流=0 处、bddl=0 处、shpc=0 处。**「覆盖率 <5%」从推测升级为三书实测 0**。

**含图页文字层质量实测（P1-3）**：mfzz 4 张幸存图所在页 p86/p482/p488/p492 的文字层 = 692/974/727/703 字符、PUA 坏字 0、行数 49/103/41/52——全部健康，「含图页文字层完好」从 UNMEASURED 升级为 MEASURED（样本 4 页）。

**页面旋转分布（P1-1 实证）**：mfzz /Rotate 90 占 82%（516/630）——主场景而非边角案例。文本管线（`PdfLineExtractor`）靠 PDFTextStripper 的 DirAdj 坐标天然落在显示空间（`PdfLineExtractor.kt` 头注释即此口径）；图片提取器走 `PDFStreamEngine`，引擎按 PDF 规范在**用户空间**（pre-rotation）驱动——**必须自建折算函数**，否则 516 页上的过滤与锚定全错（§3-B）。4 张幸存图恰都在 rotation=0 页，属基线巧合，不构成豁免。

基线确定方法（J2 统计依据）：**全量扫描**（非抽样）+ §3-B 三层规则逐条模拟（PyMuPDF 复算），mfzz 4 张已逐页人工目视确认为真示意图（体系图/图示）；容差 ±1 的来源：pdfbox 与 pymupdf 的 bbox 计算引擎可能有 1 张边界差异（SMask/Form 变体）。**阈值实证从 1 本扩至 3 本真实教材**（P1-1）：bddl/shpc 零幸存+零误杀临界图，mfzz 4/4 命中——三书分布（底图 518/1027/461、装饰 186/134/0、真图 4/0/0）横跨两种排版形态，规则零调参全适配。

两条硬结论：
1. **不做过滤 = 灾难**：630 页的 mfzz 会把 518 张背景图（~155MB）灌进图库，阅读页被整页扫描图淹没。
2. **真示意图特征清晰**：占比 2%~85%、边 ≥40pt、非同位重复——三层过滤可精准圈出（mfzz 实测圈中 4 张）。

## 3. 方案

### A 数据层（DB v4→v5）

新表 `figures`：

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | Long PK auto | |
| bookId | Long FK→books CASCADE | Index("bookId")（r5-P2-9 降级：复合索引 (bookId,pageNo) 无消费查询，不建死索引；P6 页级聚合需要时再迁移） |
| chapterId | Long FK→chapters CASCADE | Index("chapterId")，归属在落库时按页码区间算定（§3-C）；**r7-P2-3 决策记录**：单书 figures 行数 <100 时 `byChapterFlow` 全表扫描 <5ms，不建 (chapterId,pageNo,...) 复合索引，J8 实测 >5ms 再建 |
| pageNo | Int | 1-based PDF 页号（与 paragraphs.pageNo 同口径）；**冗余可用**：整书重建时据此重挂（§3-D），P6 页级聚合需要时再加复合索引（r5-P2-9） |

| seqNo | Int | 全书图序号（v1.8，r8-P2-3；**v1.9 算定时点提前**，r9-P0-1 连锁：阶段 1 结束幸存者清单即确定 → 阶段 2 落盘前按 `pageNo ASC, ordAfterPara ASC, bboxY0 ASC` 排序 1 起赋号——file 命名依赖 seqNo，必须先于 staging；assignChapter 落库时沿用同值，本期只写不改）；阅读页角标「图 N（p{pageNo}）」供用户/AI 指代（「第 3 张图」唯一定位），P6 caption 直接引用 |

**表结构冻结点（r6-P2-7）**：v5 schema 定稿后新增列必须走 v6 migration，禁止在 v5 内追加空列；P6 caption 归独立 `figure_captions` 表（AI 产物不污染 figures 原生资产语义）。**去重责任（r6-P2-6）**：`file`/`md5` 均无 DB 级 unique——`insertAll` 前内存层按 `(md5, pageNo, ordAfterPara)` 全同键去重（防复制残留重复行；同书同 md5 不同位置是合法内容，不合并），`byMd5` 调用方自担聚合语义，P6 跨书去重接入前先跑全表 md5 聚合对账。

`FigureDao`：`insertAll`、`byChapterFlow(chapterId): Flow<List<FigureEntity>>`（阅读页，**ORDER BY pageNo ASC, ordAfterPara ASC, bboxY0 ASC**，P1-5 同页多图顺序确定性）、`byBookOnce(bookId)`（重建/清理对账）、`updateChapterIds`（§3-D 重挂）、`deleteByBook`。`byMd5` 本期不建（v1.9，r9-P2-4：无调用方死 DAO 与「不建死列」纪律冲突，md5 的本期消费=落盘对账与内存去重，均不走 DAO；P6 跨书去重接入时补一行查询）。

**存储编码规则（P2-4，确定性双分支，无色彩数检测）**：解码后按**源格式族**编码——源 JPEG→JPEG q90（保持有损基因一致，避免 PNG 膨胀）；其余（PNG/GIF/JBIG2/含 alpha 的解码产物）→PNG 无损（线稿/细字体系图不受 JPEG 振铃损伤；mfzz 4 张幸存图源即 PNG）。宽 >1200px 先等比降采样再编码；**降采样上限结合显示尺寸（v1.8，r8-P2-2）**：`targetWidth = min(srcW, max(1200, dispWpt × 2))`（2px/pt 视网膜余量，评审原公式 `mediaBox.width/72×2` 量纲有误——408pt 页会算出 11px，已修正）——300dpi 扫描大图（源 3000px、显示 400pt）降到 1200px 不再保留冗余像素；mfzz 幸存图（显示 283pt → 上限 max(1200,566)=1200 ≥ 源 1180px）不受影响，J2 基线数字不变。**不走 JPEG 字节直通**：DCTDecode 流可能是 CMYK，Android BitmapFactory 直解会失败/反色——一律过 Bitmap 统一处理。**SMask 语义澄清（v1.7，r7-P0-2）**：SMask 是主图资源字典内的 alpha 通道**引用**，不是经 `Do` 运算符绘制的独立对象（评审「Do 分别处理主图和 SMask」与 PDF 规范不符——SMask 永不触发 Do，故「重复提取/独立入表」场景不存在）；pdfbox `PDImageXObject.getImage()` 遇 SMask 自动合成返回带 alpha 的 ARGB_8888 Bitmap，含 alpha 产物走 PNG 正是本规则第二分支——主图+透明度一体保留。

### B 提取器 `PdfFigureExtractor`（新文件，data/importer/pdfpipeline/）

**两阶段架构（P0-2 修正：过滤先于一切解码）**：

- **阶段 1（元数据，零解码）**：自定义 `PDFStreamEngine`（单一实例跨页复用，`processPage` 逐页驱动；P1-10。**单线程约束（v1.8，r8-P1-4）**：`PdfFigureExtractor.extract()` 为同步单线程调用——只在导入协程内串行执行一次，不暴露给并发调用方，graphics state 栈无线程安全诉求，KDoc 声明），注册运算符：CTM 栈（concatenate/save/restore/setMatrix）+ `Do`——`Do` 内区分：`PDFormXObject` → 递归进入（CTM × form.matrix，P1-3，Form 内嵌图不漏；**递归深度上限 50**，r7-P2-1：超限 `Log.w` + `ExtractorStats.droppedFormDepth` 计数、parseNote ⚠ 提示，防异常 PDF 深嵌套栈溢出）；`PDImageXObject` → 由当前 CTM 解 user-space bbox（顶点变换取 min/max）→ **立即旋转折算**（见下）→ 只记 `ImageMeta(xref, pageNo, dispBbox, srcW, srcH, ctmA/B/C/D/E/F)`（CTM 六参数一并记录，r5-P1-1），绝不调 `getImage()`。R1/R2/R3 全部在元数据集合上判定。**OC 可选内容层（v1.8，r8-P2-1）**：PoC 加 (g) 项探查 fork 是否暴露隐藏层判定（图所属 `PDOptionalContentGroup` 的可见性 API）——支持则隐藏层图直接跳过并记 `ExtractorStats.droppedOC`；不支持则 `Log.w` 一次后忽略（隐藏层图照提，残余风险登记，J2 容差 ±1 承接）。**内联图页号分布（v1.8，r8-P2-6）**：BI 计数同时记 `biPages: Map<Int,Int>`（页→次数），parseNote 技术明细输出「p12 含 3 处内联图」（≤5 页全列，>5 页列前 5 加「等 N 页」），供 P6 按页定位。
- **旋转折算（P1-1，主场景：mfzz 516/630 页 /Rotate 90）**：新建纯函数 `FigureCoordMath.rotateRect(rotation, rect, mediaBox)`——用户空间 bbox（y 向上、原点左下）→ 显示空间 bbox（y 自顶向下，与 PLine 同口径）。四分支：0° 平移翻转 y；90°/270° 轴交换（显示页宽高互换）；180° 双翻转；mediaBox 原点非 (0,0) 先平移到原点。四角变换取 min/max。`PDFTextStripper` 无现成折算函数可共享（其显示坐标来自 DirAdj 内部机制），故独立建函数并用**四方向已知四角单测**锁定（J1）。R1 的「页宽/页高」、R2 的页面积、R3 归一化、ordAfterPara、bboxY0 全部用折算后显示空间值。
- **过滤规则**（常量集中 `PdfFigureThresholds.kt`，每常量 KDoc 标注单位/来源/边界用例；**r6-P1-1c：KDoc 显式记录「阈值仅在『扫描底图+文字层』形态的 3 本台版法学教材上验证过，异源 PDF 通用性未验证——敏感性验证（≥2 本异源真书对账）为 P6 前置任务」，防后续维护者误当通用判据**；未来若需 per-book 覆盖，最小改动=常量升格为可注入 `FigureThresholds` data class（默认值即当前常量），r6-P2-4b）：
  - **R1 扫描底图**：`面积占比 ≥85%` **或** `(宽 ≥90% 页宽 且 高 ≥90% 页高)`（页宽/页高=**折算后显示空间**尺寸）。真值表：85.1%→滤；84.9%→过 R1（可能死在 R2）；宽 91% 且高 91%→滤；宽 91% 高 84%→留（单边超限不成底图）；**84.9% 面积且宽 95% 高 95%→滤（「或」第二分支命中，r6-P2-3c）**。
  - **R2 装饰**：bbox 宽或高 <40pt（显示空间，≈14mm；p86 图高 107pt 安全保留）或面积 <2% → 滤。
  - **R3 页眉/水印**：同 xref 出现 ≥3 页 **或** 同 rawMd5 出现 ≥3 页（v1.9 内容兜底，r9-P2-6：生成器常把同页眉图重复定义为不同 xref，xref 判定漏滤——**rawMd5 只对通过 R1/R2/xref 型 R3 的候选集计算**（v1.10，r10-P2-2：读压缩流原始字节不解码，候选集 ≤10 张；对 708 张全量算会对 518 张 R1 底图白读 ~155MB 字节），同字节+同位=同图）**且** 各页归一化 bbox（x0/y0/w 相对显示空间页宽高）两两偏差 ≤2% 页宽 → 滤（droppedR3 分 xref 型/内容型计数，parseNote 对账）；位置不同的合法重复（如书末插图目录）保留（P1-2）。
  - 边界反例入单测：±0.1% 双向断言（P2-7）。

### C 管线接线与章归属

- `PdfExtractResult` 增 `figures` + `figureStats` 字段（result 级，不动页级结构）；`PdfLoader.extract` 在文本提取后调 `PdfFigureExtractor`（engine 实例复用）。
- **figures 落库事务边界（v1.9，r9-P2-1）**：`importBook` 扩展 figures 入参，`figureDao.insertAll` 在 `importBook` 的**同一 `withTransaction` 内**执行（与 chapters/paragraphs 同事务）——confirmImport 里另插会留下「有章无图」半成品书，事务内失败即整书失败无中间态。
- **视觉转写与 figures 锚定的交互（P1-2，采用评审方案 B：含图页不转写）**：`ordAfterPara` 锚定的是提取时的文字层段落序；`applyVision`/`VisionRebuilder` 的整页替换会改变该页段落数量与顺序，锚定即失效。对策：**幸存图所在页排除出视觉转写，两道闸防护（v1.6 纵深，r6-P1-3）**——
  - **第一道闸（源头过滤）**：PageSelector 选页后、`applyVision` 与 `confirmImport` 入队 `pendingVisionItems` 前，统一经 `excludeFigurePages(selected, figurePageNos)` 过滤（`failedVisionItems` 是过滤后集合的子集，天然无 figure 页）；
  - **第二道闸（消费兜底）**：`VisionWorker` 逐页处理队列项时，该页 ∈ figures.pageNo → **跳过转写、标 DONE、`Log.w`**（上游过滤失守——如历史遗留队列行、缓存变体——时下游仍拒绝，锚定语义保命）；`VisionRebuilder` 只消费 Worker 转写产物，Worker 拒即全链路拒；
  - 代价：含幸存图的页不做视觉增强（mfzz 4/630 页；**实测这 4 页文字层 692–974 字符、PUA=0，MEASURED 健康**，§2）；收益：锚定指向的段落序列永不被替换，确定性 100%。P6 版面模型接入时锚定改版面级再重估。
  - **低质量防御分支（P1-3）**：被排除页若 `rawChars < 100` 或 `puaCount > rawChars×10%`（文字层烂）→ **第一道闸不排除**，照常进视觉转写，并在 parseNote 追加「p{n} 的 {m} 张示意图因文字层质量低可能错位」（m=该页幸存图数）；此时第二道闸同样放行（以低质量分支标记为准）；**残余风险声明（v1.7，r7-P1-3）**：放行页的图锚定可能偏一段且无修复交互——「长按调整位置」UI 与 `anchorQuality` 列明确不做（§6：本期无消费 UI 不建死列死交互，归 P6）；常量入 `PdfFigureThresholds`，单测锁定（J6④）。
- **章归属单一时点**：提取产物不带 chapterId；`confirmImport` 落库时按页码区间归属——校准路径用 `outcome.chapters` 排序后 `startPage` 区间（与段落重排「起点 ≤ 页号取最大者」同一规则），现状路径用 `ParsedChapter.startPage`。TXT/粘贴路径恒无图。**适用范围声明（v1.7，r7-P0-1）**：「单一时点」覆盖的后续变更=replaceBookContent 重挂（§3-D）——P5 章节树 UI 是**纯导航**（浏览/跳转/展开收起），删假章在 confirmImport 导入流程内完成，**项目不存在「导入后修改章节结构」的功能**，故无第三归属时点；未来若新增章节编辑（重排/合并/拆分），须在编辑事务内调用 `reassignFiguresToChapters(bookId)`（复用 `assignChapter` 按最新 startPage 重算，登记 P6），否则图挂错章。

### D 整书重建的 figures 保命（P0-1）

`BookRepository.replaceBookContent`（VisionRebuilder 链路）事务内增「figures 重挂」子步骤，顺序严格：

1. 删旧章**前**：`figureDao.byBookOnce(bookId)` 读全量 figures（含 pageNo/file/ord）；
2. `chapterDao.deleteByBook`（figures 行随 CASCADE 蒸发，无妨——数据已在内存）；
3. 插入新章；
4. 按新章 `startPage` 区间重插 figures（页码 → 「起点 ≤ pageNo 取最大者」同段落规则；文件在 `filesDir/figures/{bookId}/` 原地不动，file 列不变）。

**删书文件清理（r5-P0-2，代码修改点）**：`BookRepository.removeBook` 现状只删 book 行（Room CASCADE 清 figures 行），磁盘 `filesDir/figures/{bookId}/` 无清理点会永久泄漏——在 `removeBook` 事务成功后追加 `File(filesDir, "figures/$bookId").deleteRecursively()`（构造注入 filesDir 路径，不直持 Context）；J4 断言删书后行 0 + 目录不存在。

importBook 的首次落库（§3-C 归属）与 replaceBookContent 的重挂共用同一区间映射纯函数 `assignChapter(pageNo, chapterStartPages): Int`（单测锁定）。**边界定义（P2-1）**：页号早于首章 startPage → 归首章；晚于末章 startPage → 归末章（clamp 到两端，图不丢弃）；章列表空 → 返回 -1 调用方跳过该图（防御，正常导入不可能空）。**显式前提约束（r4-P1-2）**：`replaceBookContent` 只替换段落内容，**不得重排 chapters 列表顺序、不得修改 startPage**（P3b-2 校准/删除链路亦然）——figures 重挂的正确性以此为前提；J6② 单测断言该不变量（前后 startPage 序列逐一对齐 + figures.chapterId 与重建前一致）。**校准页内段序不变量（r5-P1-2）**：P3b-2 目录校准只改 `chapterId`/`startPage`/`idx` 跨章重编号，**同一 PDF 页内段落相对顺序不变**（pageNo 相同段的 idx 相对序不变）——`ordAfterPara` 在校准后依然有效；J6⑤ 单测：mfzz 四张幸存图所在页校准前后页内段序逐一对齐。**ordAfterPara 重挂不重算（v1.10，r10-P1-1 方案 B）**：重挂语义=纯值保留（J6② 逐列等值断言锁死）——图页段落不被 vision 替换（两道闸），页内段序不变与校准不变量（J6⑤）同源；**残余场景**：图页跨页并段的邻页被视觉转写后 merge 判定可能变化，图页渲染段列表可差 1 段，与提取期 merge 残差（risk 5）叠加总偏移 ≤2 段，渲染端 clamp 防越界（§3-E），J3② 走查项记录人工目视确认。`replaceBookContent` KDoc 显式声明：**「chapters 逐章 startPage 与替换前相等（按章 id 对齐）是 figures 归属正确性的充要条件，违反即须调用 reassignFiguresToChapters」**（v1.10，r10-③：把 r4-P1-2 约束升格为代码级不变量注释）。

## 5. 风险

1. **pdfbox PDFStreamEngine 兼容性**（Form/SMask/JBIG2）：Form 递归已入设计（P1-3）；单图 try-catch 跳过不阻断；J2 容差 ±1 承接 bbox 引擎差异。**内联图 BI/ID/EI 明确不做**（§6），仅计数暴露。
2. **图内容级 CTM 旋转/镜像**：与 P1-1 页面级 /Rotate 折算是**两回事**——页面级已折算（v1.2 新增）；图内容级 v1.8 起对 90° 倍数旋转/翻转**自动 Matrix 转正**（§3-B 阶段 2，r8-P2-8），真斜切/非 90° 维持原图展示+parseNote 提示（教材图实测正向为主；三书幸存图 CTM 正交性由 PoC (e) 复核）。
3. **内存峰值**：两阶段架构下底图零解码；幸存图全尺寸→缩放→recycle 顺序单驻留（P1-4）；实测幸存图 ≤1.2MP 单图 ≈4.5MB；J8 meminfo 判据兜底。
4. **staging 与落库间失败**：复制失败不落库（v1.7，r7-P2-8：md5 对 filesDir 最终文件算，复制失败即无 figures 行）；**清理点定死（r4-P2-5 + v1.7 finally 补强，r7-P2-5）**：`PdfLoader.extract` 入口 `cacheDir/figures_staging.deleteRecursively()` 且 **extract 的 finally 块再清一次**（中途异常/用户取消不残留）；并发导入场景不存在（导入为单任务顺序流），不做 UUID 隔离。
5. **段级锚定错位（跨页并段）**：并段的续行不在图所在页的段落列表中（段实体挂在首页），锚定误差最多偏一段；页面内可感知修正（v1 接受，J3② 走查记录，P6 版面模型解决）。**rebuild 叠加声明（v1.10，r10-P1-1）**：vision 重建改变邻页 merge 判定可再引入 ±1 段，总偏移上限 **±2 段**；阅读页 clamp 已防越界崩溃；不重算（§3-D 方案 B 理由：y0 数据流改动不成比例）。
5b. **vision 侧兜底 guard（r6-P1-3c）**：上游 `excludeFigurePages` 过滤失守（历史遗留队列行/缓存变体/新入口）时，`VisionWorker` 消费闸仍拒绝 figure 页转写——上游过滤是优化，下游拒绝是保命，两道闸各自可独立成立。
6. **引擎跨页复用状态污染**：engine 的 graphics state 栈必须每页 reset（processPage 前清栈），单测+实测防串页 bbox；**reset API 归 PoC 探查（r5-P2-7）**：fork 是否有 `reset()`/`endPage()` 钩子，无则在 `processPage` 前手动初始化 CTM 栈为单位矩阵并清空累积状态——PoC (f) 项，结论进文件头注释。
7. **chapterId 归属与校准假章交互**：假章删除（P5-C）重导时图按新区间重归属——单一时点原则天然规避（提取产物无 chapterId）。
