# 识别模块升级总体计划案（OPT-G）v2

> 目标：吸取论文神器五层管线经验，升级本项目 PDF 识别模块，让「目录、非正文信息、章节划分」的识别达到实地可用水平。
> 工作流：总体计划 + 6 个小计划逐案 AI 评分（≥90 分才实施），每个小计划完成后验证 + 回归，全部完成后大功能整体验证，最后整体质检推送 GitHub。
> v2 修订：按 AI 评审意见拆分 P3 为 P3a/P3b；TOC 归属方案改为挂前置区（不动数据模型）；阈值改可调参数并加敏感性测试；补回滚策略与失败判据；明确句末判据与 P5 可自动化验收。

## 1. 老板核心诉求（验收锚点）

1. 句子不能拆得太散（段落完整性）。
2. 非正文信息（目录、版权页、脚注等）用特殊字号/字体区分展示。
3. 目录识别出的章节要准确（目录页不能混进正文，章节划分要准）。

## 2. 实测证据（2026-10-02 模拟器实地导入 sample_book 仿真书，22 页，ground truth 已知）

数据库取证（study_friend.db，bookId=4）：

| # | 发现 | 证据 | 严重度 |
|---|------|------|--------|
| F1 | 目录 8 条目挂在第一章名下（chapterId=19），第一章显示「18 段」= 10 正文 + 8 目录条目 | paragraphs 表 TOC role 8 条 chapterId=19 | 高 |
| F2 | 「目 录」标题与第一条目黏连成一段（「目 录第一章 担保法概述 …… 4」） | TOC[0] 段文本 | 中 |
| F3 | 同步视觉转写失败页不入队：2/4 页成功，2 个失败页 vision_queue 无记录（表里只有旧书任务） | vision_queue 无 bookId=4 行 | 高 |
| F4 | 视觉转写进度文案误显示为「提取 PDF 1/4 页」（复用 progress 状态，phase 文案被绕过） | ImportScreen.kt:159 | 低 |
| F5 | 封面书名与作者黏连（「担保法制度讲义林明远 著」）、版权页整页一段 | 开篇 FRONT 段 | 低 |
| F6 | 章节判定纯文本正则（A/B/C 档），无字号几何证据；仿真书章标题 16pt 黑体 vs 正文 10.5pt 宋体的显著差异完全没用上 | BookParser.kt | 高 |
| F7 | tocEntries 已解析但未反哺章节校验/修正 | BookParser.kt | 高 |

根因追溯（评审意见补充）：
- F1 代码路径：`BookParser` 的 TOC 区域识别产出 `tocEntries` 后，条目文本仍留在 tocLike 页的段落流里，`PdfLoader.assembleText()` 把目录页以 `\n` 连成整块，整块位于第一个章标题「第一章 担保法概述」之前——但开篇（封面/版权）与目录块之间无空行分隔导致被并入第一块？实测显示 TOC 段落在 chapterId=19（第一章），即目录块与第一章正文落在同一个解析块/章节区间内，`BookParser` 的章节切分把「目录块之后到下一个章标题」的内容划给了第一章。
- F6 失效模式：A 档正则（`第[一二三...]+章`）在真书上的误判来自目录条目（「第一章 担保法概述……4」同样命中正则）与正文引用（「根据第三章的规定」），无几何证据时无法区分；这正是目录页必须先被隔离 + 章标题需要字号证据的原因。

做对了的（回归保护对象）：章数与章标题 10/10 全对；正文段无段裂（96 段 BODY 中非句末收尾的 16 条全是节标题行）；FRONT/TOC/BODY/BACK role 划分生效；每章内部结构完整（导语1+节标题2+正文6+小结1）。

## 3. 小计划划分（依赖顺序 P1 → P2 → P3a → P3b → P4 → P5）

P3a 与 P3b **串行执行**（评审意见采纳）：两者都动 `BookParser.kt`，P3a 只新增字号证据辅助函数与 TOC 对齐校验函数（不改章节切分主流程），P3b 在其产物之上改前置区归属与目录块组装——函数级隔离 + 串行提交，消除 merge 冲突面。P4 与 P3 无文件交集，可与 P3b 并行实施，但提交仍按序。

### P1 行聚类 + 碎片缝合（提取层地基）
- 现状：`PdfLineExtractor` 按 DirAdj 坐标直接成行，无行聚类；跨字号/上标/公式会产生碎片行。
- 移植：论文神器传递式行聚类（y 容差 0.5×字号+1.0pt，论文神器经验帖 §3 常量表）+ 碎片缝合五分支（contained/overlapped/adjacent/near_neighbor/wide_gap）。
- 边界声明：本项目语料（仿真书+真书）均为单栏排印；多栏/混排 PDF 本轮不覆盖，作为已知边界写入模块总览。聚类失败（抛任何异常）时整体回退现行为。
- 文件：`PdfLineExtractor.kt`（新增 `LineClusterer` / `FragmentStitcher`，纯函数）。
- 验收：新增单测覆盖 5 种碎片场景（fixture 内嵌测试常量，不依赖外部文件）；仿真书 E2E 段落数与基线一致；不丢字红线：全书总字数不允许减少 >0.5%。

### P2 段落组装升级（解决「拆得太散」）
- 现状：`ParagraphAssembler` 9 规则缺「满行必接/近满行接/标点行吸附/深缩进标签块」。
- 移植：满行（行宽 ≥0.9×版心宽）必接；近满行+句末接；以逗号/顿号结尾的行吸附到下一段；深缩进标签块（缩进 ≥2×正文缩进且短行）成独立段。
- 句末判据（明确定义，评审意见采纳）：复用 `ParagraphAssembler.endsSentence` 现行集合——。？！…」』"）等收尾符号 + 圈码①-⑩ + 引注[n]；补充：节标题行（第一节/一、/（一）等形态）不算句末段，单独成段。列表项（1. / ① 开头短行）按标签块规则独立成段。
- 文件：`ParagraphAssembler.kt`。
- 验收：仿真书 BODY 段句末收尾率保持 100%（节标题行除外，其 role/形态可区分）；真书（民法总则/物权）段落总数较「升级前同书重导入基线」下降 ≥5%（合并假断段；基线度量方式：升级前代码对同一本真书跑一次导入取段落数作 before，不做人工标注）且无超长段（>800 字）新增。

### P3a 章节判定升级——字号证据 + TOC 反哺校验（修 F6/F7）
- 字号证据：`docStats` 已有字号直方图，把主字号传入 `BookParser`；标题候选要求字号 ≥ 主字号+1pt 或黑体形态（字体名含 Bold/Hei/SimHei）；纯文本 A 档正则降级为参考信号（无字号信息时保持现行为，兼容 TXT）。
- TOC 反哺校验：`tocEntries` 与识别出的章标题做对齐校验。阈值设为可调常量并做敏感性测试：标题相似度用「去空白后包含或编辑距离」，编辑距离阈值 T_dist ∈ {1,2,3}、目录命中率阈值 T_hit ∈ {40%,60%,80%} 三档组合在仿真书+真书上实测选优。
  选优标准（评审意见补充）：第一优先「仿真书 8/8 全对 且 真书错误数 ≤167」的组合；并列时选 T_dist 更大者（更宽容，减少漏修正）；仍并列选 T_hit 更低者（更早触发反哺）。选定值写入常量表并注明实测数据出处。
  **勘误（2026-10-02，P3a 落地后）**：「错误数 ≤167」的口径已被 P3a 实测替代——真书 mfzz 的可验证硬指标修正为「**假章 1→0 且 12 真章逐段逐字不劣化、总字数守恒**」（E2E 断网对照 DB 实测达成）；「≤167」的逐条错误归因从未实测（UNMEASURED），后续版本不再以此数为验收口径。
- 命中率达标时：以目录条目文本修正章标题；不达标时保持现行为（宁可漏修正不可错修正）。
- 文件：`BookParser.kt`、`PdfCleaner.kt`。
- 验收：仿真书 8 章标题 8/8 对；真书章节错误数 ≤ 基线 167（勘误 2026-10-02：改为「假章 1→0 且真章不劣化」，见上）；TXT 路径单测全绿（无字号信息不降级）。

### P3b 目录归属独立化 + 标题黏连修复（修 F1/F2/F5）
- TOC 归属方案（评审意见采纳的低风险版）：**不动数据模型**——目录条目段迁移到前置区（开篇章内、版权页之后），role 保持 TOC。不新建「目录章」，chapterId 下游消费方（ReadScreen 章节分页、复习模块、进度追踪）零影响。
- chapterId 消费方清单（已核实）：ReadScreen 按章分页读 paragraphs；复习模块按 chapterId 取段；ImportViewModel 落库时按 chapters 表写入。均为「按章取段」模式，条目挂哪个章只影响展示归属，无结构连锁。
- 「目 录」标题行独立成段（目录块组装时首行单独成段）。
- 封面/版权页黏连（F5）：行距跳变 + 短行信号拆段，尽力而为不设硬指标，失败回退整页一段现状。
- 文件：`PdfLoader.kt`（assembleText 目录块边界）、`BookParser.kt`（前置区归属）。
- 验收：仿真书目录 8 条目 chapterId=开篇章且 role=TOC；第一章段数=10；「目 录」独立成段；真书目录条目不混第一章。
- 回滚：P3a 与 P3b 各自独立 commit，出问题单独 revert。

### P4 视觉增强升级（修 F3 + 提升替换率）
- 方案：
  1. 同步视觉转写失败页写入 vision_queue（status=PENDING），复用 WorkManager 兜底（修 F3）。失败判据（明确定义）：API 非 200、返回空文本、长度守卫触发（转写文本 < 原文本 0.5×）三种，任一命中即视为失败并入队。0.5× 阈值沿用 `VisionTranscriber` 现行长度守卫常量（真书四轮 E2E 已验证的存量值），本轮不改值，列入可调参数观察。
  2. PROMPT 升级为论文神器版：保留原文分段、不翻译、不总结、输出纯文本。
  3. 视觉文本后处理：全半角标点归一、行首尾空白清理（纯函数单测）。
- 文件：`ImportViewModel.kt`、`VisionTranscriber.kt`、`PageSelector.kt`。
- 验收：模拟器实测失败页 100% 出现在 vision_queue；仿真书替换率 ≥3/4（较基线 2/4 有进步）；后处理单测全绿。

### P5 阅读页非正文样式 + UI 文案（老板诉求 2 落地 + 修 F4）
- 方案：
  1. ReadScreen role→样式映射扩展：FRONT/BACK 段与 TOC 段同款 bodySmall（12sp）+ onSurfaceVariant 色值；BODY 段维持 BodyStyle 16sp。做成 `roleStyle(p.role)` 纯函数并可单测断言映射关系（评审意见采纳：代码级断言替代纯截图）。
  2. ImportScreen 视觉转写阶段显示「视觉转写 N/M 页」：视觉阶段 progress 与 phase 分离（修 F4）。
- 文件：`ReadScreen.kt`、`ImportScreen.kt`、`ImportViewModel.kt`。
- 验收：roleStyle 映射单测全绿；模拟器截图人工复核（辅助）；进度文案以 ui_describe 断言「视觉转写」字样出现。

## 4. 回归与整体验证

- 每个小计划完成后：全量单测（现有 299 个必须全绿）+ 仿真书 E2E 重导入对比。
- E2E 对比脚本（`.e2e/compare_e2e.py`，复用真书四轮 E2E 的既有对比思路）对比项：① 章数；② 每章段数；③ role 分布（FRONT/TOC/BODY/BACK 计数）；④ 全书总字数与变化率；⑤ 章标题清单 diff；⑥ 目录条目 chapterId 归属。任一项超阈值即告警。
- 存量数据安全（评审意见补充）：新算法只在导入时生效，**不做存量 books 的在线重解析**；每次 E2E 重导入前 `adb exec-out run-as ... cat` 拉取 DB 快照存 `.e2e/backup/`，升级前后各一份，可随时回溯比对。
- 大功能整体验证（全部完成后）：仿真书 ground truth 全量对比（8 章标题 8/8、TOC 归属正确、正文无段裂、视觉队列兜底生效）+ 真书民法总则/物权重导入（章节错误数 ≤ 基线 167、脚注不混正文）+ 模拟器实地走查阅读页。
- 更新 `docs/模块总览/M2-导入与解析.md` 与本计划案的实施记录。

## 5. 风险与红线

1. 不丢字红线：任何清洗/缝合不得减少全书总字数（视觉替换页除外），E2E 对比脚本自动校验。
2. 失败即回退（判据明确）：新算法环节全部 try-catch 包裹，任何异常/空结果/校验不过 → 回退现行为并 `Log.w("OPTG", ...)` 记录回退原因（上线后可观测的替代埋点，项目无埋点设施，不引入新依赖）。
3. 纯函数：新算法全部写成可单测的纯函数，不依赖 Android 类。
4. 兼容：TXT 导入路径与现有 299 单测行为不变（TXT 无几何信息，新证据信号全部可选）。
5. 回滚：每个小计划独立 commit；算法层回退判据失败即自动走旧行为，无需发版回滚。

## 6. 明确不做（本轮范围外）

- 彝文借码还原扩展、跨页续接算法重写（现有实现已有真书数据支撑）。
- 扫描版全页视觉识别（保持 scanned 拦截提示现状）。
- 多栏/混排 PDF 支持（单栏为主，边界写入总览）。
- AI 讲解/复习等功能链路改动。
