## 问题清单

- [10 可执行性] T2.1+T2.2 节代码清单内 test_replica_units.py 的 inline 代码仅含 9 个 test_* 函数（ctc 4 + det 4 + 新增 3 = 实际列出的 9 个），但验证期望写「11 passed」。零上下文工程师照文本逐字执行会得到 9 passed，触发「红则修 replica_ocr.py」的死循环——代码质量门与验证闭环同时失效。 → 建议：二选一：(a) 补齐缺失的 2 个 test_* 函数完整代码并核对数量到 11；(b) 将期望输出改为「9 passed」并同步 §0 T2.1+T2.2 行、「Kotlin 8 条 + 新增 3 条 = 11」的算术说明。以对齐实测为准。
- [2 证据出处] §1 M1 证据清单第 2 条 rapidocr_vs_phone_same_pages 的 source 字段写「本会话配对实验（C_p*.json vs d*.txt）」——无文件路径、无行号、无命令、无产物留档路径。这是 7 条事实中唯一缺 file:line 或脚本锚点的一条，且该结论直接影响后续「差距主因是管线配置而非模型档位」的方向性论断。 → 建议：为该配对实验补产物文件（如 .e2e/p6c/pair_cmp_report.json）与可复跑命令，source 改为具体路径+行号或脚本名；或降权为「观察」并从关键结论依赖链上解耦。
- [9 纪律合规] §5 score_review.py 的 except 仅捕获 (RuntimeError, json.JSONDecodeError)。主档案 HTTP 429 通常经 ai_client 层抛 HTTPError/RequestsException（非 RuntimeError），会直接穿透重试 for 循环并崩溃；「重试 1 次」名存实亡。当前靠 §6 手写备用档案 id 人工绕过，纪律上属于「已知故障路径未被代码覆盖」。 → 建议：在 except 子句中加入 requests.exceptions.HTTPError / Timeout / ConnectionError（或统一封装为 AiClientError），且 429 单独走指数退避；把备用档案 id 参数化为环境变量而非脚本外说明。
- [4 验证闭环] T2.4 判据修正案的裁定时点与执行链路不一致：文本先写「待老板 M6 追认（未私自放宽）」，又写「追认前 M3 判据以修正案为草案基准」。若 M6 拒追认，M3 已按修正案判据跑出的结论须重跑或撤销，形成返工黑洞。 → 建议：明确三档决策门：(a) 追认即冻结修正案为正式判据；(b) 不追认则 M3 全链 BLOCKED 并回退至 Δ≤0.02 原口径（附回退后预估影响面）；(c) 追认时给出「修正前/后」两套判据并排跑的对账 B 双跑结果以自证一致性。
- [3 方法可行] §6 R2 触发条件是「T2.3 两轮不过→像素差检查」，但正文 §4 T2.4 描述「本次 T2.4 归因提前使用（3/5 页超 5% 红线）」——同一触发条件在两个里程碑被复用，触发条件定义未同步升级。后执行的工程师可能误判 T2.3 归因是否仍须执行。 → 建议：在 §6 R1 行显式补一行：「T2.4 归因已前置复用该检查，T2.3 归因若触发则复用同一像素差脚本，避免重复实现」；并在 T2.3 节的 fallback 段落中指向 T2.4 已产出的像素差实测表。
- [6 成本预算] §7 成本表 LLM 调用有次数与耗时（85–240s/次），但缺单次 token 用量与预估费用；PC 机时也未标注 CPU 型号/核心数，跨机器复现会漂移到 2x。可预算但不可跨机复现。 → 建议：LLM 行补：模型名、单次 prompt 字符数→估算 tokens、单次费用区间；PC 机时行补：机器规格（CPU/内存/是否 onnxruntime intra_op threads）与同规格下 24 页/401 页的实测秒数基准。
- [10 可执行性] 命令环境混用：replica_ocr / pytest 用 Windows 路径 .e2e/p6a/venv/Scripts/python，而 T2.4 PAGES= 行用 GNU sed+paste（Git Bash），score_review 用 python 裸命令，check_session_close 用 python + 反引号外双引号 Windows 路径。零上下文工程师在同一 shell 内切换会踩坑。 → 建议：文档顶部加一节「执行环境」：明确 shell（Git Bash/WSL/cmd）、PYTHON 二进制别名、venv 激活方式；所有命令按同一 shell 语法统一，或为每条命令标注 shell。
- [10 可执行性] §4 T2.3 期望输出给了两页样例（p001 / p321）但缺 match_report 表的完整表头样例与一行 ❌ 失败行样例。零上下文工程师首次读到 failed 行时无法判断是判据未达还是代码异常。 → 建议：追加 1 行 matchA_report.md 表体样例（含 ❌ 与 Δ 数值），并显式给出「失败行归因第 1 步该看哪个字段」的指针（如 Δ、n_lines 差、sim 三项中先判定哪一项）。
