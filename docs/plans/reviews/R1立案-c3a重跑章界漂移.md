## 一、结论（先行）

P0 修复的**核心目标全部达成**：底稿取自 DB（14772 字与基线分毫不差）、洗书未再发生、覆盖守卫通过、书内容零丢失。**败的是 J3c 章结构断言**：重建后 5 章（基线 11 章）。根因是**设计层缺口**，不是实现 bug：

> 重建把现有章结构扔掉、用 `BookParser.parse(styleAware=false)` 从纯文本重推章界。但本书（视觉队列的主场景=扫描书）的章标题在导入时是靠**字号证据**检出的，而**DB 不存字号**——重解析从信息论上就不可能稳定复原导入结构。实测基线里连独立「第X章」段落都不存在（`LIKE '第_章%'` 0 行，标题行早在导入管线并入正文段），纯文本重推必然失败。

## 四、四组实测证据

1. **缓存 miss 实锤**：本次导入 SAF uri hash=`-34899318`，原跑=`-6b997af4`——uri 变了缓存必 miss。10:16 新落 `vision_-34899318_3.json`(682B)/_4(26B)/_5(26B)，旧 08:15 的 _3 仅 259B。新转写 3 次商汤调用（页4/5 转写为**空**=纯图页，两次跑都空，非回归）。
2. **形态反转**：落码注释假设「视觉目录条目无点线」（原跑 259B 确实无点线），新转写**带点线且带尾页码**（682B）——`inferTocLike` 判 true、BookParser isTocBlock 认出、条目重组 ROLE_TOC，目录链路实测通过。
3. **J3b-计时 43698ms**：miss 变体 3×商汤（~13s/页）+重建，与包 §4 预声明「未命中 ≈+1min」吻合；<10000 阈值是按命中口径标定的，数值上不过、机理上属预声明合法路径。
4. **基线标题行非独立段**：`SELECT … WHERE text LIKE '第_章%'` 与 `LIKE '参考文献%'` 在基线均 0 行——标题行在导入清洗/合并阶段已并入正文段，且 DB 无字号列。
