# M2 计划案：导入与解析（txt/pdf → 章节/段落 + 目录确认）v3

> 目标：用户能把一本书装进 App：选 txt/pdf 文件或粘贴文本 → 读取 → 自动识别章节与段落 → 目录确认页（改名/重切）→ 落库。含解析器完整单测。
> v3 修订：`第X` 家族按后缀拆档（章级/节级），档位偏序 A≥B≥C 替代"首次出现"跨档定级；标题判定先于软合并的管线顺序写死；FFFD sanity 仅配合 REPLACE 路径并如实写明 UTF-16 无 BOM 局限；importBook 改收 DB 类型；盲切改必做；编码下拉补 UTF-16BE；PDF 测试载体注明 Robolectric。

## 0. 执行顺序（慢构建机器上控制往返次数，每步末尾标注触发什么构建）

1. **BookParser + TextLoader 纯 JVM 函数**（无 Android 依赖）+ 全量单测 —— 仅增量 `testDebugUnitTest`，最快。
2. **importBook 落库**（Repository 事务方法）+ Robolectric 落库测试 —— 同上，无 assemble。
3. **ImportScreen / TocConfirmScreen / ImportViewModel** + ShelfScreen 导航接入 —— 一次 `assembleDebug`。
4. **pdfbox 引入 + PDF 分支 + PDF fixture 测试** —— 新依赖下载 + 全量 `testDebugUnitTest` + `assembleDebug`/`assembleRelease` 回归，一次跑完收尾。

风险表：

| 风险 | 缓解 |
| --- | --- |
| TXT 编码误判（GBK/GB18030 走 REPLACE，U+FFFD 占比是替换路径判据；UTF-16 无 BOM 被 GBK 误解码无自动判据） | 严格 UTF-8 优先 + FFFD sanity + 全失败时报错并给手动编码下拉兜底 |
| 标题误切/漏切（正文数字行、`第X节`被当章） | 仅 1 级样式切章 + 标题护栏（见 2.2）+ 确认页自定义正则重切兜底 |
| 加密/损坏 PDF | 加载 try/catch（含 InvalidPasswordException）→ 友好提示 |
| 扫描版 PDF（无文字层） | 字/页均值检测 → 明确提示改用 txt/粘贴 |
| 大文件内存（7.3GB 机器） | openInputStream 流式读取 + 逐行解析；全文只保留 ViewModel 一份 |

## 1. 导入流程

```
ShelfScreen [+导入] → ImportScreen
  ① 选择方式：系统文件选择器(txt/pdf) / 粘贴文本框
  ② 填书名（默认取文件名）、作者(可选)、编码下拉（自动/UTF-8/GBK/GB18030/UTF-16LE/UTF-16BE，默认自动）
  ③ 读取内容：TextLoader.load(uri, 编码选择) → 全文字符串
  ④ ImportViewModel 持有全文与解析结果（ImportScreen→TocConfirmScreen 共享，旋转/跳转不重读文件）
  ⑤ BookParser.parse(text, 自定义标题正则?) → List<ParsedChapter>(标题+段落列表)
  ⑥ TocConfirmScreen：章节列表预览（每章段落数/字数）、
     改名（对话框）、换标题正则重新识别、无标题书提示"整本作为一章"
  ⑦ 确认 → BookRepository.importBook() 事务落库 → 回书架
```

- 文件选择：`ActivityResultContracts.OpenDocument`，mime `text/*` + `application/pdf`；拿到 uri 立即 `takePersistableUriPermission`（读授权跨重启有效），内容经 `contentResolver.openInputStream` 流式读取（不复制文件）。
- TXT 编码：选"自动"时先查 BOM（UTF-8 / UTF-16LE / UTF-16BE）；无 BOM 按 UTF-8 **严格解码**（CodingErrorAction.REPORT，抛错即换下一候选）→ GBK → GB18030。GBK/GB18030 走 REPLACE 模式，解码后做 **U+FFFD 占比 sanity**（> 0.5% 视为乱码，换下一候选）——严格 REPORT 路径无需该判据。已知局限如实写明：**UTF-16 无 BOM 的文本可能被 GBK"成功"误解码**（无自动判据），只能靠 ② 的手动编码下拉兜底。全部候选失败 → 报错"无法识别编码，请手动选择"。**编码结论仅在导入过程内使用，不持久化**——文本已拆段入库，后续不再读原文件，filePath 只存原始 uri。
- PDF：pdfbox-android 2.0.27.0，`PDFBoxResourceLoader.init(context)` 后 `PDFTextStripper` 提取。三类失败都给友好提示，不崩溃：`InvalidPasswordException`/口令加密与一般 IOException → "PDF 已加密或损坏，请解密后重试，或改用 txt/粘贴"；`OutOfMemoryError` → "PDF 过大，建议拆分后导入"；提取字符数 < 100 字/页均值 → "该 PDF 是扫描版/无文字层，请改用 txt 或粘贴文本"。

## 2. 解析算法（纯 Kotlin 对象 BookParser，无 Android 依赖，全量可单测）

### 2.1 段落切分（学论文神器，只认空行，不按长度发明段落）
- 按一个或多个空行（含全角空格行）切块；块内残留单换行做软合并（中文直接拼接，英文/数字间补空格）；剔除纯空白块。
- 每段超长（>1200 字）不硬切——阅读页按段落渲染，超长段允许（v1 不做段内再分）。

### 2.2 章节标题识别（管线顺序 → 护栏 → 正则档位 → 定级）
- **管线顺序（写死，先判标题后软合并）**：按空行分块 → 对块内每个**物理行**过标题候选门（此时不做软合并，紧跟正文的单行标题才不会漏）→ 命中 1 级的标题行抽走作为章边界 → 其余行软合并成段。
- **标题候选护栏**（先于正则匹配）：独立物理行 + 去首尾空白后行长 ≤ 40 字符 + 不以句号/逗号/顿号/问号/感叹号结尾 + 非目录条目形态（行内点线/省略号后接页码结尾，如"第一章 导论……1"）。不满足者直接不参与标题判定（正文里的"去年 GDP 增长 1.5 亿。"、"3. 5 个测试点"等天然排除）。
- **正则族按档位组织**（`第X` 家族按匹配到的后缀字拆分档位）：
  - **A 档（章级）**：`第[一二三四五六七八九十百千0-9零〇两]+[章单元篇部卷回]`、`Chapter\s+\d+`、`Unit\s+\d+`、固定词（前言/序言/引言/目录/附录/后记/参考文献）
  - **B 档（节级）**：`第[一二三四五六七八九十百千0-9零〇两]+[节讲]`
  - **C 档（小样式）**：`[一二三四五六七八九十]+[、.，]`、`（[一二三四五六七八九十]+）`、`\d+(\.\d+)*[、.．\s]`。序号类正则**一律行首锚定（^）**，标题取整行——"共 3. 5 个测试点"这类独占一行的文本因非行首锚定命中而被排除。
- **定级规则（档位偏序，P0 核心）**：A ≥ B ≥ C 恒成立，跨档不靠"首次出现"压制；**只有 1 级档位参与切章**，低档命中**只保留在正文段落文本中，不建章、不改变段落内容**（总计划 §4.4：单元下的小节不拆成独立学习单元）。1 级 = 文中出现的最高档位：有 A 用 A；无 A 有 B 用 B（**仅分节的讲义 → 节升 1 级正常切章**）；仅 C → C 档首个命中的样式为 1 级。
- 段落角色：`目录`节之后的段落 role=FRONT，`参考文献/附录/后记`之后的 role=BACK，其余正文 role=BODY。**M2 需在 DbValues 增加 `ROLE_BACK = "BACK"`**（纯字符串常量，DB 存 TEXT，无 schema 迁移）。
- **单元=章**：`第X单元`在 A 档，与章同级（总计划 §4.4 声明）。
- 兜底：全文无任何标题 → 整本 1 章"全文"；**必做**——字数 > 5 万时按每 ~3000 字在段落边界盲切为"第 N 部分"，并在确认页提示用户。

### 2.3 目录重切
- 用户输入自定义正则 → 重跑 2.2（替换内置标题正则族）；解析失败/零命中给出友好报错不崩溃。

## 3. 落库
- `BookRepository.importBook(book: BookEntity, chapters: List<Pair<ChapterEntity, List<ParagraphEntity>>>)`：**入参一律 DB 类型**（解析层 ParsedChapter → Entity 的映射在解析器/ViewModel 侧完成，Repository 保持"纯 DB 封装"边界）。Room 事务内：insert book 得 **bookId（insert 返回值）并 copy 回填进各 ChapterEntity** → insertAll 得 **chapterId（insertAll 返回列表按序对应）** → 回填 chapterId 后批量插入段落；**章节/段落 idx 由 importBook 按列表序统一回填**（确认页传入顺序即最终顺序）；**status 一律写 READY**（目录已在确认页过目）。`BOOK_IMPORTED` 值本里程碑不使用，保留给未来"粘贴即导"快速路径，避免实现者误用。总计划 §4.4 字段对齐 M1。
- 重复导入同一文件不去重（v1 简单化，书架允许同名书）。

## 4. UI
- ImportScreen：两个大按钮（选文件/粘贴文本）+ 书名/作者输入 + 编码下拉 + 读取中进度态 + 错误提示条。
- TocConfirmScreen：LazyColumn 章节列表（序号、标题、段落数·字数徽标）、长按/菜单改名、顶部"换识别规则"入口、底部"完成导入"。平板横竖屏自适应：单列居中最大宽度 720dp。
- 状态归属：文本/解析结果/选中章节全部活在 ImportViewModel（普通 ViewModel，无 DI 框架），确认落库成功后清空并返回书架。

## 5. 单测（纯 JVM + Robolectric）
1. 段落切分：空行/多空行/全角空格/软合并（中文拼接、英文空格）/首尾空白。
2. 标题识别样本集：`第一章 …`、`第12章 …`、`第3单元`、`Chapter 5`、固定词；**档位偏序边例**：文中"一、"先于"第一章"出现 → 仍按 A 档切章、"一、"留正文（A≥B≥C 偏序生效）。
3. **小节不拆章（P0 钉死）**：`第1单元 …`+`第一节 …` 样本 → 只切出单元级章节，`第一节`标题行保留在段落文本内。
4. **仅节级升 1 级**：只有 `第一节/第二节` 的讲义样本 → 节作为 1 级正常切章（不退化成整本 1 章）。
5. **护栏反例**：正文行"去年GDP增长1.5 亿。"（句读标点结尾被护栏排除）、"共 3. 5 个测试点"（非行首锚定命中被排除）→ 均不产生标题；超 40 字的数字开头行 → 不产生标题。
6. 整书兜底：无标题文本 → 1 章；超长盲切触发（> 5 万字必做路径）。
7. FRONT/BACK 角色标记（`目录`后 FRONT、`参考文献`后 BACK、正文 BODY）。
8. 编码：UTF-8 无 BOM / GBK 中文样本字节 → TextLoader 解码正确；**sanity 拒绝分支**（构造字节：UTF-8 严格解码失败 → GBK REPLACE 后 FFFD > 0.5% 被拒 → GB18030 干净命中）；编码参数显式指定时直通。编码逻辑抽成可测纯函数。
9. 目录重切：自定义正则生效；非法正则 → 友好错误。
10. 落库往返：importBook 后 BookDao/ChapterDao/ParagraphDao 查询计数与内容断言（Robolectric 内存库，status=READY）。
11. PDF 冒烟：**跑 Robolectric**（`PDFBoxResourceLoader.init(context)` 需要 context），test resources 放一个最小 ASCII 文本 PDF fixture，pdfbox 提取断言（中文 PDF 提取属已知能力，pipeline 用 ASCII fixture 钉住；真机中文 PDF 验证列入 M7 手工项）。

## 6. 不做
EPUB；扫描版 OCR；段内再分；同文件去重；目录拖拽排序/合并拆分章节（v1 只改名+重切）；书内笔记。

## 7. 验证
1. 单测全绿（上面 11 组）。
2. `assembleDebug` + `assembleRelease` 回归。
3. Robolectric Compose 冒烟（简化版）：ImportScreen 输入粘贴文本 → 触发确认回调 → 断言解析+落库路径执行（用 compose ui-test-junit4 + createComposeRule；若该基础设施在本机不稳定，降级为 ImportViewModel 层冒烟并在验证报告中注明）。落库往返已有 §5.10 兜底。
4. 界面导航联调（书架→导入→确认→书架出现新书）属 M4 阅读页联调时一并人工核对；最终 M7 模拟器整体冒烟。
