# P1 小计划案：行内 span 聚类 + 字号抗坏值重估（OPT-G P1）v2

> 总体计划案 v3 已通过（93 分）。本小计划案按老板工作流单独送 AI 评分 ≥90 后实施。
> v2 修订：按评审意见修正上标 span 的行为描述与单测期望（M1）；新增聚类/重估生效度量验收（M2）；补充 LineCollector 归属说明（S3）。
> 非阻塞建议落实：P1 实施时不动段落组装逻辑（P2 范围），before 基线在 P2 实施当天取。

## 1. 问题与收益

- 现状 `PdfLineExtractor.flushLine()`（PdfLineExtractor.kt:52-72）把一次 `writeLineSeparator` 内的全部 TextPosition 压平成一个 PLine：`size = 行内最大字号`。
- 两个后果：
  1. **字号证据被污染**：知网系 PDF 标点 span 字号是 1.5~3pt 乱值（论文神器经验帖 §5 实证）；反之正文行混入大字号 span（章首装饰字）会把整行 size 拉高。P3a 的「标题字号 ≥ 主字号+1pt」判据直接吃这个污染值。
  2. **上标/引注混行**：`[39]。` 这类上标 span 的 y0 与正文主行差 2~6pt（经验帖 §6.4 实测 dy=0~0.45×字号），被压进同一 PLine 后 x 几何（min x0/max x1）失真，且 text 里上标与正文黏连位置不可控。
- pdfbox 已做行分隔（writeLineSeparator），**页级行聚类不适用**（没有可聚的行碎片）；碎片问题在「行内 span」粒度。这是本计划与论文神器原算法的架构差异：聚类从页级行列表下沉到行内 span 组。

## 2. 方案

新增纯函数 `RowNormalizer`（文件 `android/.../data/importer/pdfpipeline/RowNormalizer.kt`）：

```
输入：List<SpanInfo>（text, x0, x1, y0, size）——一次 flushLine 收集的 span 序列
输出：List<PLine>（1..n 条；多数行 1 条）
```

步骤（全部纯函数，无 Android 依赖）：

1. **robust size 重估**（论文神器经验帖 §5 `robust_line_size` 移植）：
   - 剔除线 = 行内最大字号 × 0.55；剔除 < 剔除线的 span；其余按 span 字符数加权平均。
   - 全部被剔（空行守卫）→ 退回 bbox 高度（heightDir）；仍无 → −1（字号未知，现行为）。
2. **行内传递式聚类**（经验帖 §6.4 移植，粒度改为 span）：
   - span 按 (y0, x0) 排序；新 span 与**已收组内任一** span 的 y0 距离 ≤ 容差（0.5×重估字号+1.0pt）即收入该组，不只与组首比（锚点贪心会把同一排版行劈开）。
   - **上标/引注 span 的行为**（评审 M1 修正）：上标 dy≈0.3×字号 **小于**容差 0.5×字号+1.0pt，会被聚入主行组而非独立成组；随后由缝合 near_neighbor 分支（dy ≤ 0.45×字号）**缝入主行文本**，x 排序保证拼接位置正确。只有 y0 差超过容差的真碎片（异常跨行 span）才会拆成独立 PLine。
3. **组内拼接**（缝合四分支，经验帖 §6.4 表；前提：同组判定已由第 2 步完成）：
   - contained：span bbox 完全落在已拼文本 bbox 内（±2pt）→ 直接拼。
   - overlapped：gap ∈ [−1.5×字号, 0) → 直接拼。
   - adjacent：0 ≤ gap ≤ 0.8×字号 且字号比 ≥0.9 → 直接拼。
   - near_neighbor：dy ≤ 0.45×字号 且 gap ≤ 0.8×字号 → 拼。
   - 四分支都不中但同组 → 仍拼（组内不丢字红线），gap 信息记入 Log.w。
   - **wide_gap 分支本轮不做**（需栏沟检测，单栏语料场景少；边界声明写入模块总览）。
4. **无坐标 span 兜底**：坐标全 −1 的行（无位置信息）整行原样单 PLine 输出（现行为不变）。

`LineCollector.flushLine()` 改为：收集 `SpanInfo` 列表 → `RowNormalizer.normalize(spans)` → 追加产出的 PLine。PLine 数据结构不变。

## 3. 测试与验收

- 单测（`RowNormalizerTest`，构造 span fixture，不依赖 PDF；RowNormalizer 放 `pdfpipeline` 包与 PLine 同层，`LineCollector` 是 `PdfLineExtractor` 的私有内部类，flushLine 是唯一调用点——S3 已确认归属）：
  1. 纯正文单组行 → 单 PLine，size=字符加权均值（非最大值）。
  2. 标点乱值行（1.5pt 标点 span + 10.5pt 正文）→ size ≈10.5 不被拖垮。
  3. 上标引注行（dy=0.3×字号，评审 M1 修正期望）→ 上标 span 不丢失，被缝入主行 PLine 的 text（x 排序位置正确），PLine 数量=1。
  4. y 抖动同行 span（y0 差 4.6pt@9pt）→ 仍聚为一组（容差内）。
  5. 跨组碎片（y0 差 > 容差）→ 拆成 2 条 PLine，文本不丢。
  6. 无坐标行 → 原样单 PLine。
  7. 空白行守卫 → 不产出 PLine。
- 验收：
  - 全量单测全绿（现有 299 + 新增）。
  - **生效度量**（评审 M2 新增）：flushLine 每页输出统计日志（S1）——组数分布、size 重估前后差值；E2E 后断言：(a) 正文行 size 与全书主字号众数差的均值较基线下降（size 证据更集中）；(b) 跨组拆分与重估生效计数 >0 或明确记录本语料为 0（首跑统计确定基线值，写入验收记录）。
  - 仿真书 E2E 重导入：总字数变化 ≤0.5%（不丢字）、章数 10 不变、正文段无段裂不回退。
  - 真书《民法总则》重导入：章节数与段落数与基线对比，允许 ±1% 波动（评审 S4 收紧），不丢字。

## 4. 风险与回退

- 全部逻辑 try-catch 包裹，任何异常 → 回退现行为（单 PLine 最大字号），`Log.w("OPTG")` 记录。
- 独立 commit，可单独 revert。
- 已知边界：wide_gap（宽缝专名）与多栏不覆盖；上标独立成 PLine 后段落组装层把它当短行处理——比黏连失真好，P2 段落升级时一并观察。
