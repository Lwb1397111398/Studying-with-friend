# P6 决策案：本地 OCR 与版面检测体系（扫描件快路径）

> 版本：v1.6（2026-10-02）· 状态：**评分通过**——七轮轨迹 83→85→85→85→90→89→90，第 7 轮确认 90 分；第 6 轮建议 P0×3/P1×4/P2×3 已全部落实于 v1.6 正文，第 7 轮附表建议转 P6a/P6b 计划案落实
> 老板原话（2026-10-01，两次点名）：「视觉大模型存在慢、限流等问题，能不能搭配上本地 OCR 进行辅助，比如本地也能手机跑的 PaddleOCR / PP-OCRv5 mobile。要不要采纳你说了算，采纳之后如何配合你自己规划，到底用不用这个模型、可不可以换成你认为其他更适合的 OCR 模型都由你自己决定。」「光靠 OCR 还不足以处理复杂情形，可以加入一个版面区域检测模型，即 PP-DocLayout，辅助以视觉模型 API，就可以形成很完备的体系。可以先继续做任务，之后好好思考下。」

## 1. 现状：什么书在逼视觉大模型扛主力

导入管线按 PDF 类型实际走两条路：

| 类型 | 识别方式 | 现状 |
| --- | --- | --- |
| 数字 PDF（有文本层，如 mfzz/bddl/mzzz） | pdfbox 提取「文本+坐标+字号」→ P1 行内聚类 → P2 段落组装 → P3a 字号证据链 → BookParser 切章 | 已闭环：351 单测、真书 E2E 假章 24→12、代码质检 93 分。**OCR 无用武之地**——文本层精确率远高于任何 OCR |
| 纯扫描 PDF（无文本层，如 shpc 461 页） | 唯一路径=视觉大模型逐页转写（SenseNova，实测 20-81 秒/页，429 限流频发） | **被卡死**：461 页超过 VisionScheduler 的 MAX_QUEUE_PAGES=400 护栏，导入时直接拦截；即使放行，461 页全靠视觉 API 约需 2.6-10.4 小时（估算值 UNMEASURED）且限流下随时中断 |

结论：**本地 OCR 的目标场景只有扫描件**，数字 PDF 一行代码都不该为它改。

## 2. 核心决策（五条）

1. **采纳本地 OCR，条件性选型 PP-OCRv5 mobile**。理由：据社区评测及 PaddleOCR GitHub release notes（待 P6a 实测确认），PP-OCRv5（2025 年发布）在 mobile 级模型里中文识别精度领先，检测+识别全管线模型 ≈15-25MB（含双模型，PoC 实测为准），支持简繁日文，官方提供 Paddle Lite Android 部署路径（与 ML Kit/Tesseract 等替代品的对比为**纯定性描述**，量级差异待 PoC 实测）。**选型条件化**：P6a 首日验证四项——公开发布状态/实际体积/语言包/Android 部署路径；四项确认即采纳；任一不成立则 fallback 至 PP-OCRv4 / PP-OCRv3 最新 mobile 版（TextSource 管线不变，仅换模型文件）并相应修正主选型记录。
2. **OCR 定位=扫描件的「快路径主力」，不是视觉大模型的辅助**。扫描件页先走本地 OCR（估算 0.5-1 秒/页，零成本零限流），OCR 干不了的才交给视觉大模型——方向与老板「OCR 辅助视觉」相反，理由见第 3 节分工表。**记档声明**：本案方向（OCR 主力）与老板 2026-10-01 原话表述（OCR 辅助视觉）相反，依据为 §3 量化预期与 §4 判据；老板已授权完全自主决策（「到底用不用这个模型…都由你自己决定」），此声明为透明记档而非待确认项。
3. **OCR 输出伪装成 pdfbox 文本行，复用全部既有清洗管线**。PP-OCRv5 每行输出「文本+四点坐标+置信度」，坐标换算后与 pdfbox 行同构；RowNormalizer（P1）/段落组装（P2）/字号证据链（P3a）改为消费抽象的行数据源（TextSource），数字 PDF 与扫描件在 P1 起汇合。**不另写扫描件专用切章逻辑**——BookParser 及其 351 单测直接受益。接口草图（P6b 计划案的评分前置）：

```kotlin
/** 统一行模型：数字路径=pdfbox 行（确定性文本，confidence=null）；
 *  扫描路径=OCR 行（概率性文本，confidence 0-1，行级粒度，页级置信度由上层聚合） */
data class TextSourceRow(
    val text: String,       // 行文本
    val x: Float, val y: Float, val w: Float, val h: Float,  // 统一 PDF 点单位、
    // 左上原点（pdfbox 用户空间原点在左下，实现侧做 y 翻转）；OCR 像素坐标
    // × (72/140) 换算——OCR 输入是本项目 PdfPageRenderer 固定 140dpi 渲染图
    // （已核对 data/importer/PdfPageRenderer.kt const val DPI=140），DPI 为自家
    // 常量，渲染 DPI 变更须同步换算系数；P6a 首日验证追加复核此项防漂移
    val fontSize: Float?,   // 数字路径=pdfbox 实测字号；OCR 路径=行高换算估计值（噪声 ±0.5pt）
    val fontFamily: String?,// OCR 路径恒 null（P3a 的 A 档字体名信号在 OCR 路径缺失，
    //                          章标题召回影响由 P6b 判据⑤量化把关）
    val confidence: Float?, // 数字路径 null（确定性）；OCR 路径 0-1 行级，页级兜底阈值待 P6a 标定
    val sourceVersion: Int, // 产出该行的管线版本（模型/换算规则变更时递增，与 TocJson FORMAT_VERSION 同纪律）；
    //                        行级属性——混合书（部分页 OCR/部分 pdfbox）各行可携带不同版本号，
    //                        下游不依赖统一版本号；管线版本变更时全管线重新导入
)
```

版心宽两条路径算法不同（pdfbox 从 CropBox、OCR 从图像宽×(72/140)），P2 满行判断以版心宽为分母，在 TextSource 实现内各自提供。OCR 路径行聚类失败时无「回退现行为」可退（现行为=pdfbox 行）：先走碎片行中间层——行高 <主字号×0.5 的碎片行尝试与相邻行合并，合并失败则该页置信度记低整页转视觉兜底，不进 P2。

4. **PP-DocLayout 采纳，但排在 OCR 之后（P6c 评估），且它同时是 P4 的技术底座**。版面区域检测只对扫描件有价值（数字 PDF 坐标信息已够）；它输出 15-23 类区域（正文/标题/图/表/页眉/页脚等，依版本/配置，P6c 实测确认），三个用途：① 扫描件双栏/多栏阅读顺序排序（OCR 纯按坐标排会串栏）；② 图/表区域排除防正文混入；③ **P4「示意图/思维导图保留」的区域检测底座**——检出 figure 区域截图保留，正好是老板要的 P4 功能的技术实现路径。
5. **视觉大模型角色降级为三件事**：① 目录页结构化（P3b-1 已闭环）；② OCR 低置信页兜底（页级置信度低于阈值或缺行异常——**阈值为标定参数**，P6a 用 shpc 抽样页产出置信度分布后定初值，不拍脑袋）；③ PP-DocLayout 检出复杂版面页（图表密集）时转写。扫描件全本依赖从 461 次视觉调用降到估计 <50 次。

双栏过渡期策略：P6b 交付时 PP-DocLayout（P6c）尚未就绪，双栏扫描书的 OCR 行按 y 坐标排序会左右串栏——**P6b 只验证单栏扫描书，双栏书暂不导入 OCR 路径（维持视觉全页转写），P6c 交付 DocLayout 排序后放开**。缺口量化：过渡期双栏扫描书维持现状（受影响页数待 P6a 抽样统计，预估 UNMEASURED）；若 P6c 否决，双栏扫描书 OCR 路径长期不可用，此影响记档。

### 3.1 OCR 与视觉兜底的调度时序（P6b 实施约束）

```
导入提取（扫描书）→ 逐页 OCR（同步串行，并发=1，CPU 密集不宜并发）
    ├─ 页置信度 ≥ 阈值 且 缺行率 ≤20% → 该页文本进入 TextSource 管线
    ├─ 低置信页（<阈值 或 缺行率 >20% 或聚类失败）→ 入 VisionScheduler
    │   队列（复用既有 429 退避重试/持久化，该页 OCR 草稿保留不入库）
    └─ 低配设备（低于最低规格）→ 整书跳过 OCR，全部页走既有视觉队列路径
```

**双失败兜底（决策层策略）**：OCR 低置信页的视觉转写也失败（429 重试耗尽/超时/队列满）时，该页文本留空、不阻塞全书导入——导入完成 UI 提示「第 N 页未能识别，可重导或对照原书」，缺口页记档供后续单页重试。

## 3. 体系分工（目标架构）

```
PDF 导入
  ├─ 有文本层 → pdfbox 行（现状）──┐
  └─ 无文本层（扫描件）            │
       ├─ PP-OCRv5 mobile 本地识别（快路径，~0.5-1s/页）
       │    ├─ 页级置信度正常 → OCR 行 ──┤
       │    ├─ 置信度低/缺行异常 → 视觉大模型逐页转写（兜底）
       │    └─ 目录页 → P3b-1 目录探针（视觉大模型，已闭环）
       └─ PP-DocLayout（P6c 评估）：双栏排序 / 图表区域排除 / P4 示意图截图保留
                        ↓
        TextSource 统一行接口 → P1 行内聚类 → P2 段落组装 → P3a 字号证据链
        → BookParser 切章 →（P3b-2）目录驱动校准章节树
```

量化预期（以 shpc 461 页为例，均为估算 UNMEASURED，PoC 实测后修正）：现状视觉全本 2.6-10.4 小时且被 400 页护栏拦死；OCR 快路径约 4-8 分钟全本本地完成 + 视觉兜底约 25 分钟以内。

| **P6c PP-DocLayout 评估**（与 P4 合并立项） | PicoDet-S 版面模型（~22MB，**需确认可纯 CPU 推理**；若依赖 GPU/NPU 则低端设备降级 ONNX Runtime CPU session 或否决；PicoDet-S 具体版本号/模型下载 URL 于 P6c 计划案实测时补录，本决策案只锁定模型家族与体积量级）跑 shpc 双栏页与图表页，评估双栏排序与 figure 区域检出质量；作为 P4 示意图/思维导图保留的检测底座 | 双栏页阅读顺序正确率 ≥90%（人工标注 **40 页**对照：20 双栏+20 含图表；某类不足 20 页则取该类全量并记档不足量——20 页样本置信区间过宽）；figure 检出召回 ≥80%。不过则 PP-DocLayout 降级为仅 P4 使用或否决；若整体否决，P4 退回 pdfbox 坐标启发式（空白区域检测+面积占比阈值）或暂缓 P4 待替代方案评估后重新立项——P6c 否决不造成 P4 断崖。**退路可行性声明**：坐标启发式在数字 PDF 上有验证基础（P3a 字号证据链同一坐标系统），但扫描件无可用坐标——该退路仅覆盖数字 PDF 的 P4 场景，扫描件场景 P4 暂缓 |

## 5. 风险与对策

1. **竖排/繁体古籍**：PP-OCRv5 对竖排支持有限，shpc 实际形态未取样确认（当前仅知 461 页纯扫描）。对策已内置 P6a 判据——先取样再定，竖排书不硬上 OCR。
2. **Paddle Lite 社区活跃度**：官方维护重心转向服务端，Android 端可能踩坑。对策：PoC 限时 1.5 天，被卡即切换 ONNX Runtime Mobile 备选路径，不恋战。
3. **模型分发与设备门槛**：模型本体 ≈15-25MB + 字典与运行时资源，判据上限 30MB。对策：模型不打进 APK，首次使用扫描件功能时按需下载到应用缓存（复用既有 update/download 设施），数字 PDF 用户零负担。**最低设备规格（初值 6GB RAM / 8 核 CPU / Android 8.0+，待 P6a 实测修订）**：P6a 测试设备已含一台 4GB/4 核——若 4GB 实测通过（内存峰值与单页耗时达标），门槛下修至实测可行值并记档，不拍脑袋定 6GB；低于最终规格的设备不走 OCR 快路径、直接用视觉大模型路径；P6a 记录实测设备内存峰值作为规格依据。
4. **OCR 行与 pdfbox 行的口径差**：OCR 无真字号（行高换算有噪声）、无字体名、坐标是像素非 PDF 点（×(72/140) 换算）。对策：P3a 字号证据链依赖「相对字号差」而非绝对值，行高换算满足——但换算噪声可能吞掉 1pt 的标题/正文差，**已在 P6a 判据⑤显式验证**；版心宽由 TextSource 实现各自提供（见 §2 决策 3）。OCR 特有失效模式（公式页/彩色水印页/传真级低质量扫描/手写批注页）在 P6a 抽样中带类型标签，P6b 按类型分层监控。
5. **不得为通过判据放宽判据本身**：任何阶段 No-Go 都诚实记档并回退到视觉大模型现状，不降低阈值硬上。
6. **模型维护**：OCR/版面模型文件版本锁定（下载时校验哈希），升级视为管线变更须重跑对应阶段判据（对齐 TocJson FORMAT_VERSION 递增纪律）。**升级触发条件**：PaddleOCR 大版本发布/安全漏洞公告/升级后判据重跑失败任一项；检视周期=每季度过一次 release notes，无重大变更不触发。
7. **视觉兜底页限流**：低置信页/复杂页走视觉大模型仍可能撞 429——复用 VisionScheduler 既有指数退避重试与持久化队列（P3a 已验证），不另造机制。
