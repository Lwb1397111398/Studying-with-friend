# P2 小计划案：段落组装升级——满行必接/近满行接/深缩进标签块（OPT-G P2）v3

> 总体计划案 v3 已通过（93 分）；P1 已实施验收通过（317 单测绿、设备验收零丢字）。
> v3 修订：弱守卫改**显式短路**（同时拦满行必接与近满行接，修复规则交互缺口）；阈值迭代量化；新增误接检测指标。
> v3 评审 91 分通过，6 条建议已吸收：短路实现模式明确（组合条件）；深缩进多行策略明确；**深缩进标签块调整到满行必接之前**（自查发现跨规则交互缺口：满行必接抢先会吞掉深缩进标签块）；新增 2 条交互单测；回退粒度明确为单规则开关；安全上限 20%→15%；阈值依据补充。

## 1. 问题与收益

- 现状 `ParagraphAssembler`（9 规则）的断段臂（规则 5-8）都以「上一行句末」或「行距/缩进」为信号，**没有利用「上一行是否写满」这个最强排版信号**：中文段落末行几乎必然不满（x1 < right−1.5×字号），满行行以句号结尾时大概率是段中句号（下文未完）。
- 论文神器经验帖 §7 实证：满行必接是其段落规则的第一优先臂，段裂的主要修复来源。真书 167 错误的逐条归因分类**未实测**（诚实标注：UNMEASURED），但段裂类错误直接表现为段落总数虚高，可用「段落数下降幅度」做交叉验证——before 基线 682 段（含假断段），若满行必接有效段落数应显著下降。
- 真书 before 基线（P2 实施当天实测）：bookId=1《民法总则》682 段 / 535,567 字符（BODY 628 + TOC 54）。P1 已证明 BODY 段落不受提取层改动影响，基线有效。

## 2. 方案（在现 9 规则中插入 3 条，优先级安排如下）

几何线（沿用 `DocStats` 已有的 left/right/bodySize，新增满行线常量）：
- 满行线 `full_x = right − 0.5×bodySize`（论文神器经验帖 §7）
- 近满线 `near_full_x = right − 1.0×bodySize`
- 深缩进线 `deep_indent_x = left + 1.6×bodySize`（≈2 字符缩进；规则 6 的缩进线是 0.8×）

新规则（插入现 when 链，规则编号顺延）：
1. **深缩进标签块**（插在规则 4 y 回跳之后——评审建议 4 触发自查，发现若放在满行必接之后，上一行满行+本行深缩进短行的列表场景会被满行必接抢先续接，标签块规则永远走不到，故提前）：`line.x0 ≥ deep_indent_x` 且本行短行（x1 < right−1.5×line.size）→ flush 前段，本行开启新段（标签/列表块独立成段）。连续多行深缩进短行各自独立成段（flush 语义自然覆盖，不合并——列表项本就逐项成段）；后续深缩进行以禁则标点开头时走规则 1 并回，优先级不变。正文标准 2 字符首行缩进虽落入深缩进区间，但首行写满不满足短行条件，不触发；单行短段落误触发时行为（独立成段）与正确结果一致，无害。
2. **满行必接**（紧随其后）：`prev.x1 ≥ full_x` → 续接，无论上一行是否句末。**强新段短路守卫**（评审 1【阻塞】采纳，方案 a 显式短路）：`prev` 句末 且 本行首字符是段首禁则标点或数字序号（`一、/1./（一）/①`形态）→ **同时跳过满行必接与近满行接两条规则**，直接落规则 5 行距断段链。实现模式（评审建议 2）：when 链前计算 `val strongNewSeg = endsSentence(p.text) && isStrongNewSegStart(first)`，满行/近满两臂条件各写 `&& !strongNewSeg`（组合条件，不改 when 结构）。注意守卫语义是「不强制接」，后续是否断段仍由规则 5-8 的几何信号决定——顶格长行序号+行距正常时会续接，属已知边界（无新段几何信号的顶格排版本就近满行接语义范围），由真书 E2E 误接指标兜底。
3. **近满行接**（紧跟满行必接，受上述短路守卫约束）：`prev.x1 ≥ near_full_x` 且 `endsSentence(prev.text)` 且本行**无缩进**（`line.x0 < left + 0.8×bodySize`）→ 续接。守卫：本行缩进 = 作者起新段意图，优先断段。

不改动：规则 1 段首禁则并回、规则 2/3 标题隔离、规则 4 y 回跳、规则 9 默认续接；`endsSentence` 判定集合不变（P2 计划案 v2 评审已确认现行集合覆盖中英句末/引号/圈码/引注）。

阈值依据（评审建议 1，标注：估算，UNMEASURED）：真书 BODY 628 段，中文正文段落平均 3-6 行、每段约 1-2 个段中句号落在满行上，估算段裂（假断段）占比 5-10%，满行必接修复其中大部分 → 段落数预期下降 5-8%，取 5% 为达标下限；上限 15%（评审建议 6，自 20% 收紧）为防过度合并保险——超过 15% 意味着误接严重；2pp 深缩进指标：短行独立段占比是标签/列表块健康度代理，段落重构不应显著改变它，±2pp 容差。

## 4. 风险与回退

- 三条新规则全部为纯函数内联判断，try-catch 不适用（无 IO/算法异常面）；回归风险由单测 7 + E2E 一致性断言拦截。
- 独立 commit 可 revert。
- 已知边界：满行必接在「段落末行恰好顶满」的罕见排版下会误接下一段首行——近满行接的缩进守卫可挡住有缩进的新段；顶格新段（无缩进排版）仍可能误接，属可接受残余风险（真书 E2E 段落数 ≤20% 上限兜底）。

### 5.2 深缩进标签块决策变更：默认关闭（保留代码 + 开关）

真书（王泽鉴《民法总则》重排版，630 页）文字层取证（pdfplumber 实测）：

- 该书排版恶劣：部分页双栏（x0 出现 66/454、x1 出现 395/787 两组）、页边有行号栏被 pdfbox 当文本行、正文满行仅 32%；
- 约 **10% 行落入「深缩进+短行」区间**（列表/标签形态误判），深缩进臂在全书净增 ~1500 个碎片段：P1 6661 段 → P2(开深缩进) 8137 段（+22.2%），正常段段长中位 37→29 字；
- 结论：无字号证据支撑时深缩进臂弊大于利。**决策：`deepIndentBlockEnabled = false` 默认关闭**，规则代码+开关+单测保留（3 条深缩进单测改显式开启，新增默认关闭不触发单测），待 P3b 有字号证据后再评估启用。

**量化重启门槛**（AI 质检建议 3 吸收）：同时满足以下三条才重新启用——
1. 目标书页内存在连续 ≥3 行的深缩进（x0 ≥ left+1.6×bodySize）短行块；
2. 该块行字号与正文字号差异 ≥1.0pt（或与正文行距明显不同），即排版本身给出了「非正文流」证据；
3. 在 ≥3 本不同排版的书上验证，列表块拆分准确率 ≥95%（人工标注 50 块样本）。
   备选判据（字号 API 不可靠时，v3.2 复核建议 1 吸收）：条件 2 的字号证据可由
   「行距差异 ≥1.2×正文行距」或「连续深缩进行 ≥5 行」替代，任一满足即可触发重启评估。
   P3a 验收标准：正常排版书上深缩进形态行占比 <1% 则关闭该臂评估；>5% 则重议默认值。

外推边界（AI 质检建议 4 吸收）：默认关闭的决策来自单本恶劣排版书；通用 PDF 上深缩进列表块可能真实存在。P3a 起：对排版正常书（单栏、满行率 >60%）先跑 P1/P2 对比观察，若正常书出现「列表项被并入正文」样本则优先级提升。仿真书（单栏满行率≈100%）已验证 P2 关深缩进臂无此症状（逐段全等）。

P2 最终保留：满行必接 + 近满行接（纯续接臂，只会减段不会增碎段）。

### 5.4 方法论沉淀

1. 对照实验必须**控制视觉转写变量**：飞行模式导入（或导入后立即断网拉 DB），否则视觉 LLM 的整页转写会覆盖文字层组装结果，使组装器 A/B 对比失效——本轮仿真书 106 vs 96 段的假差异即由此而来。P3 之后所有组装器验收沿用本方法。
2. **规则命中计数器**（AI 质检建议 6 吸收）：`ParagraphAssembler.hitStats`（生产 null 零开销，`PdfCleaner.clean` 接线后 println 进 logcat）。真书全书命中：满行必接 4056、近满行接 29、strongNewSeg 守卫拦截 1474、行距臂 2929、默认续接 6510、缩进+句末 1813。后续调阈值以命中分布为据，不再盲调。P3 起升级为 JSONL 结构化落盘
   （files/hitstats.jsonl，调试开关控制，生产不写）支撑多书批量调优。
3. **基线校验前置**（v3.2 复核建议 3 吸收）：每本新测试书导入后，先跑「断网 P1 基线 +
   段长中位 + 满行率」三指标写入计划案，确认口径一致后再进组装器开发——P2 的
   682 基线教训即缺此步。
4. 性能：真书 630 页两版导入总耗时一致（~5 分钟），组装层为纯函数内联判断，无感知
   差异；细粒度单页耗时 UNMEASURED，P3 若做性能调优再测。
