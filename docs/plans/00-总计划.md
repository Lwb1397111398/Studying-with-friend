# 「Studying with friend」总计划案 v1

> 一句话：做一个安卓平板上的读书陪伴 App——像朋友一样陪你读书：该讲的地方用大白话讲给你听，读完一章帮你总结、画导图、教你怎么把知识串起来记。

## 1. 目标与非目标

### 目标（v1 必须交付）
1. 导入教材：txt 文件、PDF 文件、粘贴文本；自动识别章节与段落，导入前可确认/改名/重切。
2. 阅读页：按章节阅读正文；进入章节可跑「粗读」，AI 标注哪些段落值得讲（★）、哪些段落应该合并讲、哪些简单到不用讲——不段段都讲。
3. 段落讲解：点段落或点「讲解本节」，AI 用朋友口吻讲通俗版：讲什么 / 大白话讲解 / 生活例子类比 / 关键点 / 一句话记忆钩子 / 1-2 个自检小问题。结果缓存，可重复看。
4. 章末总结包：读完一章生成 ① 章节总结（流式输出）② 思维导图（可缩放、可导出 PNG）③ 记忆思路（讲故事式串联叙述，配 TTS 朗读）④ 知识串联（把并列知识点编成一条线的故事，如「无/限制/完全民事行为能力」→ 一个人从胎儿到成年的成长线）⑤ 自测题 3-5 道（可作答、对答案）。
5. 全书总览：读过 ≥2 章后，生成跨章关系总览 + 全书总导图 + 总记忆主线。
6. 复习中心：自测错题本；章末要点按 1/3/7/14/30 天排期，首页显示今日待复习。
7. 设置：AI 接口配置（Base URL / 模型 / API Key，测试连接，Key 加密存储）、讲解详略（简略/标准/深入）。
8. 导出：章节总结包导出为 Markdown 文件。
9. 交付可安装的 APK（release 签名）+ 使用说明。

### 非目标（本期不做，留作后续迭代）
- EPUB / 扫描版 PDF 的 OCR
- 导图节点手动拖拽编辑（v1 只读+缩放）
- AI 对话闲聊 / 自由追问（v1 只做段落讲解与章末包）
- 语音输入、云同步、多用户

## 3. 技术选型（全部选本机已验证的方案）

- **语言/UI**：Kotlin 2.0.21 + Jetpack Compose（Material3）+ Navigation Compose，单 Activity。
- **存储**：Room 2.6.1（KSP 编译器），复杂结构以 JSON 字符串存 TEXT 列。
- **AI**：OpenAI 兼容 `/chat/completions`；`HttpURLConnection` 直连（Studying-helper 安卓端验证过，零额外依赖）；结构化任务用 JSON 输出+修复重试，长文任务用 SSE 流式；AndroidKeyStore AES/GCM 加密 API Key。
- **导图**：WebView + mind-elixir（复用 tingsiwei 已打包的本地资产，完全离线），JavascriptInterface 桥接。
- **PDF**：com.tom-roush:pdfbox-android:2.0.27.0（Studying-helper 验证过）。
- **测试**：JUnit4 + Robolectric（解析器、AI 输出解析、DAO 均可离线测）。
- **构建**：Gradle 8.9 wrapper + JDK 21（Android Studio JBR）+ 默认 GRADLE_USER_HOME（本机 1.4GB 缓存可用；tingsiwei/小说工具均在中文用户名下构建成功）。**SDK 定位**：M0 时写入 `local.properties` → `sdk.dir=E\:\\engine\\androidstudioSDK`（不依赖 ANDROID_HOME 环境变量）。项目路径无中文仅含空格，AGP 支持空格路径；若构建异常则回退 junction `E:\engine\studying-friend`。

## 4. 产品设计

### 4.1 用户主流程
```
书架(空态引导) → 导入(txt/pdf/粘贴) → 目录确认(章节列表可改名/重切) → 书架(有书)
  → 点书 → 章节列表(进度/已总结标记) → 进阅读页
  → 阅读页: 正文分段显示; 可跑「粗读」→ 段落出现★(值得讲)/合并标记
  → 点段落或「讲解本节」→ 朋友口吻讲解卡片(缓存)
  → 读完点「章末总结」→ 生成总结包: 总结/导图/记忆思路/串联/自测
  → 书架显示进度; 读≥2章后书详情页出现「全书总览」
  → 复习中心: 今日待复习 + 错题本
```

### 4.2 页面结构（Compose Navigation）
- `ShelfScreen` 书架：书卡片（进度条、今日待复习数）、导入入口
- `ImportScreen` 导入：选文件(txt/pdf)/粘贴文本、编码处理、书名
- `TocConfirmScreen` 目录确认：章节列表、改名、用自定义标题正则重切
- `BookDetailScreen` 书详情：章节列表+状态（未读/读过/已总结）、全书总览入口
- `ReaderScreen` 阅读页：上下章切换、正文段落流、段级标记、底部讲解卡片（BottomSheet）、「讲解本节」带进度、顶部「章末总结」
- `ChapterAssetsScreen` 章末总结包：Tab(总结/导图/记忆/串联/自测)、导出
- `BookOverviewScreen` 全书总览：跨章联系、总导图、总记忆主线
- `ReviewScreen` 复习中心：今日待复习列表、错题本
- `SettingsScreen` 设置：AI 配置+测试连接、详略档位

### 4.3 AI 能力与 Prompt 策略（核心）

统一 system 人设（朋友，不居高临下）：
> 你是用户一起读书的朋友，不是老师。讲人话、短句、接地气；主动联系前面读过的内容；讲完偶尔反问一句确认用户真懂了；用户卡住时换个角度再讲，不重复原话。禁止说教腔（「同学们」「我们要学会」）。

5 个任务（prompt 文本存 assets/prompts/，占位符替换，版本号管理）：

1. **粗读规划**（JSON，temperature 0.2）：输入章节段落清单（带编号、每段 ≤200 字截断）；输出 `{"gist","key_terms":[{"term","plain"}],"paragraphs":[{"id","action":"skip|explain|group","group":[ids],"why"}]}`。规则：直白叙述/过渡段→skip；难段相邻可合讲→group；每章讲解组 3~10 个，宁少勿多；长章先分块（≤8000 字/块）再归并。
2. **段落讲解**（JSON，temperature 0.5）：输入段落原文+前后各一段+章节要点+已知术语表（避免重复解释）；输出 `{"title","friendly","analogy","key_points":[...],"memory_hook","check_questions":[...]}`。friendly 300-600 字朋友口吻。
3. **章末总结包**（标签文本，一次调用，temperature 0.4，SSE 流式）：输入全章段落+已生成的段落讲解要点；输出五个标签段：`<总结>`(markdown ≤600字)、`<导图>`(TAB缩进树，节点≤15字)、`<记忆思路>`(200-500字连贯叙述，讲故事式承接)、`<串联>`(把并列/递进知识点编成一条线的故事，优先时间线/成长线/因果线，如「无/限制/完全民事行为能力→从胎儿到成年的一条成长线」)、`<自测>`(3-5 题 JSON：RECALL/TRUE_FALSE/CASE，考推演与辨析不考背诵，含答案与解析)。解析失败自动纠正重试一次；失败绝不覆盖已有内容。
4. **全书总览**（标签文本）：跨章关系 + 全书总导图 + 一条总记忆主线。
5. **复习评估**（JSON，M6）：对今日到期要点出快速回想检查，判定 记得/模糊/忘了，据此推进 1/3/7/14/30 间隔。（M6 实现口径：复用 M5 章末自测题逐题回想 + 三态自评，AI 动态出题进 backlog——见 M6 计划案 §10 偏差登记。）

### 4.4 数据模型（Room）
- `Book(id, title, author, sourceType, filePath, status, totalChapters, createdAt)`
- `Chapter(id, bookId, idx, title, readState)` — **「单元」粒度声明**：v1 中"单元"等同"章"处理，章节识别正则同时覆盖「第X章/第X节/第X单元/Unit X/一、」等形态；单元下的小节（如"第一节"）作为章内标题样式保留在正文里，不拆成独立学习单元，章末总结包即"单元总结包"。
- `Paragraph(id, chapterId, idx, text, role(body/frontmatter/…), aiAction, groupId, why)`
- `ParaNote(id, chapterId, paraIds, title, friendly, analogy, keyPointsJson, memoryHook, questionsJson, createdAt)`
- `ChapterAsset(id, chapterId, summaryMd, mindmapTree, mindmapJson, memoryMd, chainMd, quizJson, model, promptVersion, createdAt)`
- `QuizAttempt(id, chapterId, qIndex, answer, verdict, feedback, createdAt)`
- `ReviewItem(id, bookId, chapterId, title, intervalIdx, dueAt, done)`
- `Setting(key, value)`
策略：所有 schema 变更必须写 Room 迁移；AI 产物表带 `promptVersion` 便于追溯。

## 6. 质量与评分机制（响应用户要求）

- **评分制**：计划案与代码质检均由独立 AI 评审代理按固定 rubric 打分（0-100）：完整性/正确性/可行性/风险对策/与需求一致性。<90 → 按评审建议修改后重判，循环直至 ≥90；评审记录存 docs/plans/reviews/。
- **代码 rubric**：编译与测试证据、架构一致性、边界处理（网络失败/格式损坏/空数据）、资源泄漏、命名与可读性、与既有模块冲突。
- **回归纪律**：每个里程碑结束跑全量单测+全量构建；跨模块字段变更必须同步所有调用方。
- **最终 QA**：全量测试 + lint + APK 安装性检查（manifest/签名/权限最小化）+ 对照本总计划的功能核对表 + 整体代码质检评分 ≥90。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| AI 输出格式不稳 | TAB 树+标签包裹（tingsiwei 验证）；JSON 剥围栏/截取/纠正重试；三级解析兜底；失败不覆盖旧内容 |
| PDF 扫描版提取不出文本 | 提取字符数阈值检查，过少时引导改用 txt/粘贴；v1 不做 OCR |
| 长章超上下文 | 分块粗读+归并（论文神器模式）；总结包只喂段落讲解要点而非全文 |
| 中文/空格路径构建坑 | 项目路径无中文；异常时 junction 到 E:\engine\studying-friend |
| 无真机连接 | Robolectric+全量构建+lint 兜底；交付 APK+安装说明，用户装后反馈再修 |
| 依赖下载失败 | 国内镜像（华为云 gradle 发行包、阿里云 maven）已在本机项目验证 |
| 里程碑膨胀 | 非目标清单锁死范围；stretch 想法记入 docs/backlog.md 不进当前里程碑 |
