## 3. 技术方案

### 3.1 页码语义与 offset 校准

- TocEntry.page 是**目录上印的书内页码**，与 PDF 物理页号存在固定偏移 offset（书前有封面/序/目录等无码页）。
- 求法（每区段独立）：取该区段 level1 条目**首/中/尾分散 3 条**（分散取样避免锚点全集中书前段导致后段 offset 估计不稳），各自在候选窗口内找锚点页——窗口 = [目录尾页 + 书内页码 − 3, 目录尾页 + 书内页码 + 20]，页内文本（pdfbox 层）归一化后包含条目标题前缀（归一化复用 TocJson.normalizeTitle，前缀取前 8 字）即锚定。窗口非对称理由：+20 为前插页多的大型教材留余量（典型 offset 2-5 页），−3 覆盖极少数目录页码大于 PDF 页号的罕见排版。≥2 个锚点成功 → offset 取中位数（**恰 2 锚时取均值四舍五入至最近整数**——offset 为整数页差，均值可能出 .5），且锚点间 offset 互差 ≤1 视为自洽（互差 >1 → 该区段放弃）；仅 1 个锚点 → offset 采用但区段标记 low_confidence。
- **区段条目数退化**：区段 level1 条目 ≥3 条取首/中/尾 3 锚；恰 2 条降级**双锚策略**（两页码各求锚、offset 取均值四舍五入至最近整数、互差 ≤1 自洽校验照旧——与恰 2 锚场景同规则）；仅 1 条或双锚全失败 → 弃用该区段（条目计入全局分母、分子记 0）。
- **offset 合理域（系统性偏差前置防线）**：任一区段解出的 offset ∉ [0, 50] 页 → 视为系统性 OCR 异常，弃用该区段（条目计入全局分母、分子记 0）——书前无码页（封面/序/目录）实证极少超过 50 页，负值与大正值均为页码误读信号；单测补 offset=51 与 offset=-1 两个边界。此为三锚同向偏移盲区（风险 #5）的前置自动拦截，判据 #4 等距抽核仍保留作事后兜底。
- **短标题位置校验（假阳性生产防线）**：标题 ≤8 字时前缀=全文匹配，窗口内交叉引用/尾注文本可能假命中——此类条目的锚定页附加位置校验：匹配行须位于页面上半部（章标题排版位置先验），不满足不计为锚点；残余风险由 E2E 判据 #4 等距抽核兜住。
- **锚定率守卫（全局与区段两层，显式串联）**：区段层——互差不自洽/无锚点的弃用区段，其全部 level1 条目计入全局分母、分子记 0；全局层——成功锚定的 level1 条目占比 ≥60%（如 11 章须 ≥7 章）才进入校准，<60% 整体返回 null 走零回归（不是仅弃失败区段后继续）。**阈值复核计划**：60% 为 v1.1 定死的守卫下限，E2E 后回填两真书实际锚定率数据，复核是否需调整（55%/65%）。
- **页内文本来源声明**：锚点匹配依赖 PDF 嵌入文字层（pdfbox 提取）。无文字层的纯扫描版不归本案——锚点天然失败 → calibrate 返 null 零影响，扫描件文字层由 P6 本地 OCR 职责补齐后自然接入。
- **pageNo 完整性前置校验**：段落重排的唯一数据基础是 3.3 的 pageNo 链路（PageOut.pageNum → 页边界标记 → ParsedPara.pageNo → ParagraphEntity.pageNo），calibrate 开始时检查本次导入待重排段落的 pageNo 非空率——缺失比例 >5% → return null + Log.w（「pageNo 缺失率异常，跳过校准」走零回归），防止链路断裂时产出全错章节归属；单测补 pageNo 大面积缺失场景。
- 目录尾页 = 探针处理的 tocLike 页最大值（P3b-1 已知）。

### 3.2 章节锚定与切章（方向性原则：只增不删）

对每个 level1 条目映射到 PDF 页后：

- **偏差三档（闭合无空档）**：① 偏差 ≤1 页（目录映射页与本地章起点差 ≤1）→ 对齐，**保留 BookParser 章**（章名来自页面真实文本，比视觉 title 可靠），目录仅校验；② 偏差 ≥2 页 → 以目录页码移动起点，**移动后必须在新起点 ±1 页重新匹配标题行文本作为章名**，匹配不到才用目录 title 兜底——保证章名永远来自真实页面文本；②补充（多章竞争）：映射页 ±5 页范围内有多个 BookParser 章 → 移动到与映射页**偏差最小**者，偏差相同取起点页较小者（与 TOC 序号靠前原则一致），单测覆盖；③ 映射页 ±5 页搜索范围内无任何 BookParser 章 → **插入新章起点**（本地漏判场景——bddl 二三四章/六章、mzzz 第九章的修复路径），章名取该页匹配到的标题行文本，匹配不到用目录 title 兜底；插入的新章在 E2E 判据 #4 中**全量核对起点**（不受等距 5 章名额限制）——插入分支的起点错误是其最大风险，抽核前置。**±5 选取依据**：offset 校准后残留偏差预期 ≤2 页（三档②的触发域），±5 为其 2.5 倍余量；两真书 E2E 实测偏差分布将在 E2E 后回填记档，若实测分布 >3 页 → 扩大搜索范围至 ±7 或按分布动态确定，扩大书目时复核。偏差恰好 2 页由 ② 接住（单测覆盖），三档无空档。
- **段落归属（calibrate 显式重排，已代码实证）**：段落→章分配现由 BookParser 在纯文本块上完成（`BookParser.parse(raw: String)`，`ParsedPara(text, role)` 无页号），P2 组装函数不做章归属——故锚定/切章后由 calibrate 按**校准后章起点页区间**显式重排段落（章 i 起点页 ≤ 段 pageNo < 章 i+1 起点页 → 归章 i；pageNo 来自 3.3 数据前置）：三档②移动起点后，旧起点与新起点之间的段落自然归前一章；三档③新章持有起点页至下一章起点页之间的全部段落。**最后一章（章 N）无下一章截断——持有其起点页至全书末页（边界=bookPageCount）之间的全部段落**。同页出现多个章起点（页粒度归属模糊，罕见）→ 该页段落归靠前的章并 Log.w，E2E 判据 #2（每章 ≥1 段）兜底。
- BookParser 多出的章（目录无此条目）→ **保留不删**（目录可能不全/漏收，删章风险大于冗余），标记 `fromLocalOnly=true` 供 UI 弱化展示。
- **fromLocalOnly 冗余检测**：fromLocalOnly 章与相邻 TOC 章的段落页区间重叠率 >50%（重叠段数/该章总段数）→ 追加标记 `redundantSuspect=true`（疑似与目录章覆盖同一内容区间的数据冗余，UI 可选择隐藏，数据层不删——去重红线仍归「只增不删」）；单测补「fromLocalOnly 与 TOC 章完全重叠」场景，E2E 判据 #2 增重叠率检查项。
- **low_confidence 区段行为**：仍参与切章，其产出的新章/移动过的章标记 `lowConfidence=true`（数据层保留信息，UI 可选弱化展示）；不因单锚而弃用区段。
- **re-import 边界**：校准仅作用于本次导入产生的新章节行，不触碰库中既有其他书的任何数据（calibrate 输入输出都限定本次 bookId）。
- 守卫（**倒挂分级，混合阈值**）：插入+校准后若章序出现页码倒挂（后章起点 < 前章起点）——倒挂条目数 ≤ `min(全部锚定条目数 ×20%, 5)`（混合阈值：大章数书最多容忍 5 个，防止 50 章书容忍 10 个掩盖系统性问题）且跳过这些条目后其余条目序列无倒挂 → 跳过倒挂条目（计入全局锚定分母、分子记 0，可能拉低锚定率触发 <60% 守卫）继续校准并 Log.w；否则整体放弃校准返回 null 走现状（最坏情况仍是整书放弃，零回归红线不变）。超限不部分保留的依据：倒挂条目超限通常意味区段 offset 本身系统性错误而非个别条目问题——「未倒挂」章的起点同样可疑（同向偏移未必触发倒挂），部分保留会引入看似正确实则错位的章，整书放弃仍是最安全解。**倒挂守卫对所有章（含 low_confidence 章）统一适用，不因置信度标记豁免**——单锚章起点不确定性更高，更需守卫兜底。
- **同页码防重**：锚定循环发现两个 level1 条目映射到同一 PDF 起点页 → 仅保留 TOC 序号靠前的条目，后续条目跳过并 Log.w（目录页码重读/重排时零长度章不得写入 DB；单测覆盖「同页映射防重」场景，E2E 判据 #2 兜底）。
- **可观测性**：calibrate 各 guard 分支（锚定率 <60%、互差不自洽弃段、倒挂放弃、窗口全失败、方案 Z 时机错过不校准）一律 Log.w 记录触发原因+锚定率+失败条目数（对齐 P3b-1 探针失败路径的可观测性）；**锚点匹配失败时 Log.w 分类失败原因（窗口内无文本层/标题前缀不匹配/短标题位置校验失败），区分「无锚点」与「锚点误判」便于排错**；calibrate 成功时 Log.i 记录各区段 offset 值与锚点数分布（后续多书阈值调优与 unparseable 重试有效性验证的实证数据源）；**并记录全部移动章的位移量（实际 PDF 起点 − 目录映射页）——若位移量方差 <1 且中位数绝对值 ≥2 → Log.w「疑似系统性 offset 偏移」（三锚同向盲区的自动预警）且判据 #4 强制全量逐章核对（不走等距抽样）**；low_confidence 区段产出的章数单独计数记档，**产出章占比 >30% 时在 E2E 后触发「单锚弃用」收紧评审**（当前不弃用以省已花成本，实测数据说话）。

### 3.3 章节树数据结构

- **数据前置（实施时先做，属 P2 模块接口变更）**：ParagraphEntity 现无 PDF 页号（只有 chapterId/idx/text/role，段首页码在 P2 组装时被丢弃），而 3.2 锚定依赖「章的第一段落在哪页」。加一列 `pageNo INTEGER`（段首页码，1-based；跨页并段取首页）：PdfLoader/PdfCleaner 行级数据本就带 pageNum，P2 组装段落时把段首来源页带出即可，E2E 已知跨页并段场景取首页语义正确。**影响面清单（实施前对照确认）**：PdfLoader 行输出 → PdfCleaner 页级清洗 → P2 段落组装函数签名（段首来源页透出）→ ImportRepository/ChapterRepository 章节插入与查询。**职责与顺序**：P3b-2 实施者负责上述签名变更并跑 P2 全部单测回归；**独立 commit 先落地 P2 接口变更，再实施 calibrate 消费**（两个 commit 各自可回退）。DB 迁移：三列变更（paragraphs.pageNo / chapters.level / chapters.parentOrder）+ 前向兼容标志位 chapters.calibrated（INTEGER NOT NULL DEFAULT 0，本期加列不消费，供 P5 区分「未校准/目录不可用」）**合并单次 Migration（版本 +1）**，一个中间态、一个迁移测试。**Migration 与 commit 的原子性**：Migration 与 P2 接口变更落在**同一个 commit**——P2 代码需 pageNo 列存在才能编译运行，拆开必有「代码先于迁移运行」的崩溃态；该 commit 是「加了列但无人消费」的安全态（默认值保证旧查询零改动），calibrate 消费在后续独立 commit（「开始消费新列」状态），两个 commit 各自可回退。
- Chapter 表加三列：`level INTEGER NOT NULL DEFAULT 1`（1=章 2=节）、`parentOrder INTEGER`（节的章序号；章为 NULL）、`calibrated INTEGER NOT NULL DEFAULT 0`（本期加列不消费，前向兼容用——**此列最终语义定义权归 P5**：P5 立项评审必须确认该列当前语义与 P5 设计预期一致，若 P5 改用独立表方案，此列可废弃并在 P5 自身 Migration 中删除）。Migration 测试照既有模式。
- 节挂接：level2 条目按其书内页码映射后落在哪章区间（章 i 起点 ≤ 节页 < 章 i+1 起点）即挂哪章；落不进任何章区间（页码越界）→ 丢弃该节并记日志（不阻塞）。
- 目录未命中书的 Chapter 数据与现状完全同构（level 全 1、parentOrder 全 NULL），旧查询零改动。

### 3.4 探针入口扩大（修 mzzz 下册目录未覆盖）

> **跨阶段归属声明**：本节是 P3b-1 探针配置变更（缓存版本升至 v4），因 P3b-2 校准依赖多区段目录数据而必须先行。实施顺序：① 独立 commit 落地探针入口变更+缓存 v4（旧缓存自然失效）→ ② 再实施 P3b-2 calibrate 消费。**代码所有权**：由 P3b-2 实施者一并负责（单人项目，无独立 owner 审批流程），但探针质量判据 #7 独立验收（不达标回退前 4 页入口）；P3b-1 E2E 报告的探针结论**在区段化入口生效后不再直接适用，须按判据 #7 重新验证**，实施时在报告中标注。

- P3b-1 现状：tocLike 页升序取前 4。改为**区段取样**：tocLike 页按「相邻间隔 >5 页」聚类分组，每组取前 2 页，全组上限 8 页（mzzz 实况：上册 p28-30 一组、下册 p557+ 一组，各取 2 页即覆盖）。**阈值依据**：两本真书实测分布——同册目录页相邻间隔 ≤3 页、册间间隔 >500 页，阈值取 5 对两类间隔均有数量级余量（不敏感区）；后续扩大书目时按分布复核。
- 超时预算随页数扩到 **≤480s 总预算**（8 页 × 60s readTimeout；页面渲染开销约 12s 计入同一预算口径，elapsed 前置检查机制沿用 P3b-1 不变——单一总预算口径，避免双数字并存）；预算耗尽时已成功区段照常使用（**区段级全有全无**：区段内任一页失败弃整段，段间独立——比 P3b-1 的整体全有全无放宽，因多区段场景一损俱损会浪费已花的成本；单区段书行为与 P3b-1 完全一致）。
- 缓存仍整体一份 `toc_v4_{uriHash}.json`（版本升 4：入口与语义变更，旧缓存自然失效重探）。**过渡期声明**：v4 代码不读取 v3 缓存文件（文件名不同天然隔离），v3 文件在磁盘留存但被忽略（无「半新半旧」混合态），v4 探针成功后写入新缓存。**过渡期用户影响（一次性）**：已有 v3 缓存的书首次重导多付一次 4-8 分钟探针；不设专门通知——导入本有进度条与阶段文案，用户感知仅为目录识别耗时变长；是否加提示留 P5 立项评估。

### 3.5 配套小项（P3b-1 遗留议题裁决）

1. **unparseable 重试**：采纳重试 1 次（E2E 实证 2 次偶发均为同页重导即好；成本仅偶发多一次调用），仍受 elapsed 预算前置检查约束。**修订声明**：此为对 P3b-1 v3.0「JSON 解析失败不重试」决策的有意修订——当时依据是「同输入大概率同错」，P3b-1 E2E 实证该假设不成立（bddl p19/mzzz p28 同页重导均好），故修订。**版本敏感性**：重试有效性随 prompt 模板/模型版本变更需重新验证；后续 unparseable 率若降至 <5% 可回退为不重试以省调用。
2. **TocJson 80 vs BookParser 40 口径**：不统一、注释记档——80 是目录条目真实长度上限（41+ 字真条目实证），40 是正文行误判护栏；本方案章名一律取页面实际文本（受 40 约束天然安全），视觉 title 仅作匹配与兜底，两口径服务不同目的无冲突。
3. **tocResult 形态**：裸 var → **sealed class TocProbeState + var**（Idle/Running/Done(entries)/Failed；calibrate 只同步读一次当前值，响应式能力用不上，StateFlow 属多余架构噪音——对 P3b-1 计划案「升级 StateFlow 或 sealed class」二选一承诺取后者）；P3b-3 若需响应式再升级 StateFlow。**commit 归属**：TocProbeState 变更与 P2 接口变更**同一 commit**（同属安全态——新类型就绪、confirmImport 消费方在同 commit 内适配类型映射：Done(entries) 等价原非 null、其余等价原 null，行为不变、无 calibrate 逻辑），calibrate 接入在后续独立 commit；回退该 commit 时类型与消费方一起回退，无中间态。

## 5. 风险与红线

1. **视觉 title 误识**传染章名 → 章名一律页面文本优先（3.2 已定），title 仅匹配。
2. **目录页码 OCR 误读** → 多锚点中位数 + 互差自洽校验 + 倒挂整体放弃，三层防线。
3. **mzzz 下册目录页非 tocLike**（排版不同探针找不到）→ 3.4 后仍未命中则第九章保持缺失，E2E 判据 #3 用降级通过条件（其余 10 章正确），不硬造页码。
4. **DB 迁移破坏既有库** → Migration 测试 + 旧数据 level 默认值同构（3.3）。
5. **已知盲区（记录不修）**：三锚点页码被 OCR 同向偏读（如全 +2）时，中位数仍是错值且互差自洽通过——多锚点法的固有局限，靠判据 #4 等距抽核兜住发现；单测记录此场景的当前行为。
6. **红线**：不丢字、章名不虚构（无文本匹配时才用目录 title 并标记）、目录数据永不删除本地识别兜底、API key 只经环境变量。
